Brew should feel like a one-liner. Prefer **`./grind install`** (or **`kona grind install`**), or the brew starter kit. Manual Gradle edits are optional and listed at the end.

## Already have a Kona app?

From the app root (where `build.gradle.kts` / `build.gradle` lives):

```bash
./grind install brew
# from anywhere under the app:
kona grind install brew
```

That command:

1. Adds `org.konaframework:kona-brew` to your Gradle dependencies.
2. Registers `BrewServiceProvider` in `src/main/resources/META-INF/kona/providers` so grind/`PackageDiscovery` loads it on boot.

Then refresh Gradle and rebuild:

```bash
./gradlew build
# or just restart ./grind serve
```

Pin a version when you need to:

```bash
./grind install brew --version=0.1.0
# or: kona grind install brew --version=0.1.0
```

See the full package installer docs on Kona: [Installing packages](https://docs.konaframework.org/docs/packages/install/).

## Starting from zero

Scaffold an app that already includes Brew, Crema, session, and CSRF:

```bash
kona new my-app --kit=brew
# Java sample path:
kona new my-app --kit=brew --lang=java
cd my-app
./grind serve
```

## After install — quick check

1. Create a component: `./grind make:brew counter`
2. Embed `<brew:counter />` in a Crema page.
3. Open the page and click — the count should update without a full reload.
4. In DevTools, confirm `window.Brew` and `window.Alpine` exist.

Brew injects its script/styles into HTML responses by default (`brew.inject_assets`). For layouts you control yourself, add `@brewStyles` / `@brewScripts` — see [Assets](#assets-in-layouts).

Existing apps need **session + CSRF** on the web middleware stack (the brew kit wires this for you). Update requests carry `_token`.

## grind commands

Once Brew’s provider is registered, app-local grind picks up Brew commands:

```bash
./grind make:brew counter
./grind make:brew todos --class
./grind make:brew counter --lang=java --test
./grind brew:publish
./grind brew:stubs
./grind brew:layout
```

Details: [grind commands](/dx/grind/).

## Assets in layouts

When you manage the layout yourself:

```crema
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="utf-8">
    <title>@yield('title', 'App')</title>
    @brewStyles
</head>
<body>
    @yield('content')
    @brewScripts
</body>
</html>
```

`@brewScripts` emits the CSRF-aware tag that loads Alpine + Brew and calls `Brew.start()` on `DOMContentLoaded`.

## Config keys

| Key | Default | Role |
|-----|---------|------|
| `app.key` | — | HMAC key for snapshot checksums |
| `brew.class_namespace` | `app.brew` | Package roots for `<brew:name />` resolution |
| `brew.path` | `/brew` | Base path for update + script routes |
| `brew.view_prefix` | `brew` | Convention view prefix (`views/brew/<name>.crema.html`) |
| `brew.inject_assets` | `true` | Auto-inject styles/scripts into HTML responses |
| `brew.inject_morph_markers` | `true` | Wrap loops/conditionals for keyed morph |
| `brew.csrf` | `true` | Require CSRF token on updates when a session exists |

## Going deeper — manual Gradle (optional)

Only if you are not using `./grind install` / the kit:

```kotlin
dependencies {
    implementation("org.konaframework:kona-http:0.1.0")
    implementation("org.konaframework:kona-session:0.1.0")
    implementation("org.konaframework:kona-crema:0.1.0")
    implementation("org.konaframework:kona-brew:0.1.0")
}
```

Then register providers yourself (or write `BrewServiceProvider` into `META-INF/kona/providers`):

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
Kona.create(args)
    .configure {
        it.set("app.key", Env.getOrDefault("APP_KEY", "change-me"))
        it.set("session.driver", "cookie")
    }
    .providers(
        HttpServiceProvider(),
        SessionServiceProvider(),
        CremaServiceProvider(),
        BrewServiceProvider(),
    )
    .afterBoot { app ->
        HttpMiddleware()
            .alias("start.session") { StartSession(app.resolve(SessionManager::class.java)) }
            .alias("csrf") { VerifyCsrfToken() }
            .web(listOf("start.session", "csrf"))
            .apply(app)
    }
    .boot()
```

</TabItem>
<TabItem label="Java">

```java
Kona.create(args)
    .configure(c -> {
        c.set("app.key", Env.getOrDefault("APP_KEY", "change-me"));
        c.set("session.driver", "cookie");
    })
    .providers(
        new HttpServiceProvider(),
        new SessionServiceProvider(),
        new CremaServiceProvider(),
        new BrewServiceProvider()
    )
    .afterBoot(app -> {
        new HttpMiddleware()
            .alias("start.session", () -> new StartSession(app.resolve(SessionManager.class)))
            .alias("csrf", VerifyCsrfToken::new)
            .web(List.of("start.session", "csrf"))
            .apply(app);
    })
    .boot();
```

</TabItem>
</Tabs>

`BrewServiceProvider` binds `BrewManager`, discovers components under `app.brew` by default, and registers `POST /brew/update` plus the `/brew/brew.js` script routes.

Until Maven Central publishes are live for your version line, publish to Maven local from the Kona and kona-brew checkouts (`./gradlew publishToMavenLocal`), or use SNAPSHOT coordinates that resolve from `mavenLocal()`.
