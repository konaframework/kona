---
title: 语言服务器（kona-lsp）
description: 用于 Crema 指令补全和未知指令诊断的最小 LSP。
---

**kona-lsp** 是 Crema 的一个小型语言服务器协议实现。它用 `Content-Length` 分帧在 **stdio** 上说 JSON-RPC — 这是编辑器在你配置“把这条命令当作语言服务器运行”时期望的常见形状。

它接受 **`crema`**、**`java`** 和 **`kotlin`** 文档。对 Crema 文件，它扫描整个缓冲区。对 Java 和 Kotlin，它找到内联 Crema 范围 — `template()` 的返回/赋值字符串、`inline(` 参数，以及前面有 `// language=Crema` / `/* language=Crema */` 的字符串 — 然后对字符串内容运行同一个分析器，并把位置映射回宿主文件。

Maven 坐标：`org.konaframework:kona-lsp`（模块 `modules/lsp`，包 `org.konaframework.lsp`）。

## 能力

| 方法 | 行为 |
|------|------|
| `initialize` / `initialized` | 宣告完整文档同步、补全（触发符 `@`）、诊断提供者 |
| `shutdown` / `exit` | 干净拆除（shutdown 之后退出码 `0`） |
| `textDocument/didOpen` / `didChange` / `didClose` | 跟踪缓冲区文本；打开/变更时 `publishDiagnostics` |
| `textDocument/completion` | 建议内置 Crema 指令、Wire 的 `wire:*` 属性、`{{ }}` 内的回显辅助方法和变量（`url`、`route`、`asset`、`csrf_token`、`old`、`env`、`config`、`trans`、`lang`、`loop.index` 等），以及（宿主类的 `{{ }}` 内）公开字段/方法 |
| `textDocument/diagnostic` | 拉取模型报告未知的 `@directive` 名称和未知的 `wire:*` 属性（映射进 Java/Kotlin 的内联字符串） |

扫描指令和 `wire:*` 属性时会忽略注释 `{{-- … --}}`，这样注释里的示例不会报警。

### Wire 的 `wire:*`（Crema HTML）

在打开的 HTML 标签内，输入 `wire:`（或 `wi` 这样的词干）会提供与 IntelliJ 插件相同的 Wire 属性列表：`wire:model`、`wire:click`、`wire:submit`、`wire:loading`、`wire:target`、`wire:ignore`、`wire:key`、`wire:dirty`、`wire:offline`、`wire:confirm`、`wire:poll`、`wire:init`、`wire:show`、`wire:transition`，外加常见修饰符（`.live`、`.prevent` 等）。未知的 `wire:*` 名称会产生警告。触发字符包括 `@`、`:`、`.` 和 `{`。

当光标在 Crema 视图的 `{{ … }}` 内时，kona-lsp 建议每一个 Crema 回显辅助方法和约定变量（`CremaEchoCatalog`，与 `CremaHelpers` 和 IntelliJ 插件保持同步）。在内联 `template()` 字符串上，它还会建议从外层类源码扫描到的公开属性和方法（没有完整的 Java 类型解析器 — 来自 `Component` 的继承成员只有写在该文件里才会出现）。目录里的辅助方法名仍然出现在这些成员旁边。

`CremaEchoCatalog.completions(prefix)` / `CremaHelpers.completions(prefix)` 为测试和工具暴露同样的名称。

### Firefly 目录

`firefly-catalog.json` 由已发布的 `Panel`、`Resource`、`Page` 和 `Widget` 类型生成。它不是手写列表。公开类型或方法缺失时测试会失败。

在 Kotlin 或 Java 缓冲区里，输入 `Panel` 会提供该类型。`Panel().path` 和 `new ChartWidget().engine` 会提供该类型上的方法。悬停在名称上会返回包和成员。同一文件也随 Cursor 和 VS Code 的 Crema 扩展以及 IntelliJ 插件一起发布。

```kotlin
val types = FireflyCatalog.types()
val items = FireflyCatalog.completions("Panel().pa", "kotlin", 0, 10)
val hover = FireflyCatalog.hover("Page", "java", 0, 0)
```

```java
List<FireflyCatalog.TypeRecord> types = FireflyCatalog.types();
FireflyCatalog.hover("Page", "java", 0, 0);
```

## 运行它

```bash
./gradlew :kona-lsp:jar
java -jar modules/lsp/build/libs/kona-lsp-*.jar
```

或者：

```bash
./gradlew :kona-lsp:installDist
modules/lsp/build/install/kona-lsp/bin/kona-lsp
```

进程从标准输入读取 LSP 消息，并把响应/通知写到标准输出。不要交互式地往里打字 — 让编辑器拥有这些管道。

从应用检出：

```bash
./grind ide:lsp
```

打印同样的说明，而不启动服务器。

## 从 Kotlin 或 Java 使用（测试 / 工具）

公开表面可以不经过编辑器使用。Kotlin：

```kotlin
val diags = CremaAnalyzer.diagnostics("@csrf @notReal")
val items = CremaAnalyzer.completions("@for", 0, 4)
val code = LspServer().serve(inputStream, outputStream)
```

Java：

```java
List<CremaAnalyzer.Diagnostic> diags = CremaAnalyzer.diagnostics("@csrf @notReal");
List<CremaAnalyzer.CompletionItem> items = CremaAnalyzer.completions("@for", 0, 4);
int code = new LspServer().serve(inputStream, outputStream);
```

`CremaDirectives.KNOWN` / `isKnown(name)` 暴露与补全和诊断共享的内置指令集。

## 它还不做的事

- 完整的 Crema 解析或 HTML 校验
- 来自应用路由器的路由名补全
- 格式化或重命名重构
- 第二个 Java/Kotlin 语言服务器（Java 扩展仍然拥有 `.java` 文件；在编辑器里合并补全列表）

这些以后可以增长；这一里程碑让协议表面保持小而真实，这样编辑器今天就能接上。
