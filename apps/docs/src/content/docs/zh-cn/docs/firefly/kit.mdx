这些部分放在你已经挂载的面板上。插件调用的面板方法与应用调用的相同。没有单独的插件注册表。

## 租户

`tenant(Tenant("acme").label("Acme"))` 在顶栏加一条链接。链接设置 `?tenant=acme`。该请求渲染期间，`FireflyTenant.id()` 是 `acme`。调用了 `tenant("tenant_id")` 的资源会在 id 已设置时把该列加进 `query()`。Cadence 模型仍然返回 `ModelBuilder`。未知的租户 id 会在页面上失败，并指出这个 id。

```kotlin
Panel().path("admin").tenant(Tenant("acme").label("Acme"))
Resource("orders").model(Order::class.java).tenant("tenant_id")
```

```java
new Panel().path("admin").tenant(new Tenant("acme").label("Acme"));
new Resource("orders").model(Order.class).tenant("tenant_id");
```

## 插件

子类化 `FireflyPlugin`，覆盖 `register` 和 `boot`，把实例传给 `plugin(...)`。`register` 立即运行。`boot` 在面板挂载时、页面路由之前运行。`configureUsing` 是其他 Firefly 类型使用的同一个静态钩子。`view("plugins/banner.crema.html")` 把视图路径存在插件上。

```kotlin
class BannerPlugin : FireflyPlugin() {
    override fun id(): String = "banner"

    override fun register(panel: Panel) {
        panel.hook(Hook.BODY_END, "<p>Banner</p>")
    }
}
```

## 导入与导出

`FireflyTransfer.exportAction()` 和 `importAction()` 是对话框动作。`export(rows, file, bus)` 和 `import(file, bus)` 运行 `ExportRows` 和 `ImportRows`。这些任务实现 `ShouldQueue`。传入队列 `Bus` 且驱动为 sync 时，它们就地运行。传入 `null` 时，同样的 `handle()` 在调用方上运行。

## 测试

`Firefly.test(page)` 读取已渲染的页面。

```kotlin
Firefly.test(page)
    .assertSee("Ada")
    .assertFormField("name")
    .assertTable("Ada")
    .assertDialog("Export")
```

```java
Firefly.test(page).assertSee("Ada").assertFormField("name");
```

自定义字段是表单字段的子类。`assertFormField` 查找它的 `data-ff-path`。

## 新应用

`kona new desk --kit=firefly` 写出一个 Crema 应用，加上 `app/firefly/Panel`、`pages/`、`widgets/` 和 `resources/` 文件夹，以及在 `/admin` 挂载面板的启动类。`--lang=java` 写出 Java 面板。欢迎路由保持原位。
