Show a record when the screen should display a value, not collect one. Put the infolist on a view page, or anywhere you want a label and a value.

The types live in `org.konaframework.firefly.infolists` (`kona-firefly-infolists`). They sit on the schema tree from [Schemas](/docs/firefly/schemas/), so a section, a grid, and tabs are the same layouts you already use. On the Desk page the infolist is a single name entry. On orders, the view page at `/admin/orders/view` mounts the order infolist. Both classes live under `app/firefly/`.

Each entry is a `div.ff-entry` with `x-data="ffEntry"`. That Alpine factory is registered by the schema script. Copyable state and live binding use it.

## Entry types

| Entry | Use it for |
|-------|------------|
| [Text entry](/docs/firefly/infolists/text-entry/) | Labels, money, dates, badges, markdown, HTML |
| [Icon entry](/docs/firefly/infolists/icon-entry/) | Glyphs and boolean Yes/No pills |
| [Image entry](/docs/firefly/infolists/image-entry/) | Photos, avatars, stacked galleries |
| [Color entry](/docs/firefly/infolists/color-entry/) | CSS color swatches |
| [Code entry](/docs/firefly/infolists/code-entry/) | Syntax-highlighted source (Shiki) |
| [Key-value entry](/docs/firefly/infolists/key-value-entry/) | Maps as a two-column table |
| [Repeatable entry](/docs/firefly/infolists/repeatable-entry/) | Lists of nested entries or a table |

## Render an infolist

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val page = Infolist.make()
    .statePath("user")
    .record("ada")
    .operation("view")
    .components(
        TextEntry.make("name").state("Ada"),
    )
page.hydrate()
val html = page.render()
```

</TabItem>
<TabItem label="Java">

```java
Infolist page = Infolist.make()
    .statePath("user")
    .record("ada")
    .operation("view")
    .components(TextEntry.make("name").state("Ada"));
page.hydrate();
String html = page.render();
```

</TabItem>
</Tabs>

`Infolist.make()` wraps a `Schema`. `components(...)` replaces the root list. `statePath` prefixes stored paths, so `name` lives at `user.name`. `fill` writes a map. `get` reads a dotted path. `schema()` returns the wrapped schema when you need `set` or partial render. `record` and `operation` are stored on that schema for the page that hosts the infolist. You see the name **Ada**.

On a resource view page, the panel wraps the rendered markup in `.ff-infolist`. That host fills the content column (`width: 100%`, no `xl` cap) — the same width model as list tables, reduced only by panel / page / resource `maxWidth`. Create and edit forms stay at the default `xl` column. To tighten or widen a section inside the infolist, call `maxWidth("xl")` (or another token) on that component; see [Schemas](/docs/firefly/schemas/#max-width-xl-and-friends).

## Pass a value or a closure

Entry setters return the entry, so you can chain them. A setter accepts a fixed value or a `java.util.function.Function` (or a `Predicate` for flags). The function receives `Get`, the same reader a schema component uses.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val name = TextEntry.make("name")
name.state("Ada")
name.state(java.util.function.Function { get -> get.get("../name") })
name.placeholder { "Empty" }
```

</TabItem>
<TabItem label="Java">

```java
TextEntry name = TextEntry.make("name");
name.state("Ada");
name.placeholder(get -> "Empty");
```

</TabItem>
</Tabs>

The last call wins. `state("Ada")` after a closure stores the literal and drops the closure.

`label`, `heading`, and `description` are overridden on `Entry` and return the entry. When you omit `label`, Firefly humanizes the entry name (`first_name` → “First Name”) so labels stay visible. Schema methods such as `hidden`, `visible`, and `live` still return the schema `Component`. Call those as statements, then continue with entry methods:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val name = TextEntry.make("name").state("Ada")
name.hidden { get -> get.get("/draft") == true }
name.live()
```

</TabItem>
<TabItem label="Java">

```java
TextEntry name = TextEntry.make("name").state("Ada");
name.hidden(get -> Boolean.TRUE.equals(get.get("/draft")));
name.live();
```

</TabItem>
</Tabs>

## Helpers on every entry

| Method | What you get |
|--------|----------------|
| `placeholder` | Text when the state is empty |
| `color`, `icon`, `iconColor`, `iconPosition` | Presentation. Icon position is `before` or `after` |
| `tooltip` | Screen-reader text |
| `url`, `openUrlInNewTab` | Wrap the value in a link |
| `copyable`, `copyMessage`, `copyMessageDuration`, `copyableState` | Copy affordance on the entry |
| `helperText`, `hint`, `hintColor`, `hintIcon` | Secondary text and hint |
| `prefix`, `suffix` | Text around the value |
| `alignment`, `alignStart`, `alignCenter`, `alignEnd`, `alignJustify` | Text alignment (default **justify**; labels stay start) |
| `wrap`, `inlineLabel` | Wrapping (default **on** so long values fit view/manage modals and page containers) and an inline label |
| `extraAttributes` | HTML attributes on the component root. A map or a closure. Names that are not HTML attribute names are skipped |
| `aboveContent`, `belowContent` | Schema components rendered around the value |
| `state` | Literal value, or a closure. A literal wins over the schema path |

`configureUsing` on an entry class runs for every later `make()` of that class. Pass `null` to clear it.

State resolution: a literal or closure from `state(...)` wins. Inside a repeatable item, a dotted name such as `author.name` is read from that item. Otherwise the entry reads `schema.get` at its absolute path. Nested attributes use the same dotted path as table columns (up to four levels).

Known icon names (`home`, `bars`, `user`, `check`, `x`) render inline SVG. Any other name is stored as `data-ff-icon` and does not throw.

## Lay entries out

Place entries inside the schema layouts. Use `Section`, `Grid`, and `Tabs` from the schema module.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
Infolist.make().components(
    Section.make("Profile").schema(
        Grid.make(2).schema(TextEntry.make("name")),
        Tabs.make().tabs(
            Tab.make("Code").schema(CodeEntry.make("snippet").state("a = 1")),
        ),
    ),
)
```

</TabItem>
<TabItem label="Java">

```java
Infolist.make().components(
    Section.make("Profile").schema(
        Grid.make(2).schema(TextEntry.make("name")),
        Tabs.make().tabs(Tab.make("Code").schema(CodeEntry.make("snippet").state("a = 1")))
    )
);
```

</TabItem>
</Tabs>

## Write your own entry

Subclass `Entry` and set both `view` and `meta("ff-view", ...)` so the schema renders the Crema view.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
class NoteEntry(name: String) : Entry<NoteEntry>(name) {
    init {
        view("firefly.entries.note")
        meta("ff-view", "firefly.entries.note")
    }
}
```

</TabItem>
<TabItem label="Java">

```java
public class NoteEntry extends Entry<NoteEntry> {
    public NoteEntry(String name) {
        super(name);
        view("firefly.entries.note");
        meta("ff-view", "firefly.entries.note");
    }
}
```

</TabItem>
</Tabs>

```bash
./grind make:firefly-entry Note
```

The command writes `app/firefly/entries/Note.kt` and a Crema view that uses `x-data="ffEntry"` and `@entangle`. `--lang=java` writes a Java class. The view name is `firefly.entries.note`. Reference the class from the infolist. `discover` does not scan `entries/`.

## Prefix, suffix, and what lives elsewhere

`prefix` and `suffix` are text, or a closure that returns text. They are not action buttons. A count or an average belongs on a table column: call `summarize` on [Tables](/docs/firefly/tables/). A code editor is a form field on [Forms](/docs/firefly/forms/).
