`Panel`（`org.konaframework.firefly.Panel`）是你构造、配置并挂载的对象。它是 `app/firefly/Panel` 里的类。外框渲染使用另一个简单名相同的类，`org.konaframework.firefly.support.Panel`，写在[面板外框](/docs/firefly/chrome/)。你在应用里写的类是 `org.konaframework.firefly` 里的那个。

加入模块不会登记路由。路由在你调用 `mount` 时出现。

可链式调用的设置器接受静态值或闭包。闭包接收模式的 `Get`。空白的 id、品牌、域或守卫名会抛出 `FireflyException` 并指出该字段。

## 一次调用里的面板

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val panel = Panel()
    .id("desk")
    .path("admin")
    .brand("Desk")
    .navigation(NavigationType.APP)
    .page(ListPage("orders"))
panel.mount(router)
```

</TabItem>
<TabItem label="Java">

```java
Panel panel = new Panel();
panel.id("desk");
panel.path("admin");
panel.brand("Desk");
panel.navigation(NavigationType.APP);
panel.page(new ListPage("orders"));
panel.mount(router);
```

</TabItem>
</Tabs>

`path("admin")` 和 `path("/admin/")` 都提供 `/admin`。`path("")` 和 `path("/")` 提供站点根。根面板按名称登记每个页面、认证屏幕和资源页面。它不登记兜底路由。

如果路径已经被路由，`mount` 会抛出 `FireflyException` 并写出两个处理器的名字。两个面板可以挂在同一个路由器上，一个在 `path("")`，一个在 `path("admin")`。`domain("ops.example")` 会拒绝 `Host` 头不匹配的请求，包括头里带端口的情况。

`mount(router, state)` 对照该状态映射求值闭包。第二次 `mount` 会抛出 `Panel [id] is already mounted`。

## 方法

| 方法 | 它做什么 |
|------|----------|
| `id` / `path` / `brand` / `domain` | 字符串或 `Get` 闭包。Id 默认 `admin`。路径默认 `admin`。品牌默认 `Firefly` |
| `navigation` / `topNavigation()` | `NavigationType`。默认 `APP`。见[导航](/docs/firefly/navigation/) |
| `theme(FireflyTheme)` | 记号和局部。默认 `KonaTheme`。见[主题与 CSS](/docs/firefly/themes/) |
| `layout(PanelLayout)` | 替换外壳排列 |
| `hook(Hook, html)` | 把 HTML 追加进一个外框钩子 |
| `spa(true)` | 在有 URL 的链接上加上 `wire:navigate` |
| `authenticate(false)` | 页面不重定向到登录。hello 示例这样做 |
| `guard` / `useAuthGuard` / `reuseAppGuard` | 谁已登录。见下文 |
| `item` / `cluster` / `userMenu` | 导航树。见[导航](/docs/firefly/navigation/) |
| `page` / `resource` / `widget` | 不经过发现登记一个实例 |
| `discover(path)` | 加载 `pages/`、`widgets/` 和 `resources/`。见[登记面板](/docs/firefly/registration/) |
| `tenant` | 加上租户链接。见[租户](/docs/firefly/tenancy/) |
| `plugin` | 立即调用 `register`。`boot` 在 `mount` 内部运行。见[插件](/docs/firefly/plugins/) |
| `mount(router)` | 登记路由 |
| `render(request)` | 一次请求的外框，不含页面正文 |
| `guardName()` | `firefly-{id}`，或你传给 `reuseAppGuard` 的名字 |

## 认证与守卫

面板守卫是 `firefly-{id}`，除非你调用 `reuseAppGuard()`（应用守卫名 `web`）或 `reuseAppGuard("name")`。`useAuthGuard(guard)` 适配一个应用 `Guard`。在你这样做之前，面板保留自己的 `MemoryPanelGuard`，并且不替换应用的登录或会话。

屏幕是面板前缀下的 `/login`、`/register`、`/password-reset`、`/email-verify` 和 `/profile`。除非你调用 `authenticate(false)`，页面需要该守卫。登录和注册读取 `email` 和 `password`（注册还读取 `name`）。缺少字段返回 422 HTML。失败的尝试返回 422 HTML，消息是 `Those credentials do not match`。

守卫没有 id 时，用户芯片显示 **访客**。

## 主题与钩子

`theme(HarborTheme())` 选择随面板构件发布的示例主题：不同的主色、保留钩子标记的侧栏局部，以及 `.ff-panel` 下的一小段额外样式表。`hook(Hook.BODY_END, "...")` 仍然注入外壳。应用主题、布局和钩子的是支持包里的 `Panel`。槽和局部请读[面板外框](/docs/firefly/chrome/)。

## 生成一个

```bash
./grind make:firefly-panel
./grind make:firefly-panel --lang=java --id=desk --path=admin
./grind firefly:install
./grind make:firefly-theme Harbor
./grind firefly:publish
```

`make:firefly-panel` 和 `firefly:install` 写入 `Panel` 以及空的 `pages/`、`widgets/` 和 `resources/` 文件夹。生成的类只设置 `id` 和 `path`。`firefly:publish` 把侧栏局部复制到 `resources/views/firefly/sidebar.crema.html`，以便你编辑。局部必须保留钩子标记，否则渲染会抛出。
