`kona new` scaffolds a Gradle app with a local `./grind` CLI. With **no arguments** it asks every question. A directory name skips **only** the directory question — language, kit, CSS, database, install, migrate, and seed are still asked. Pass a flag to skip that step. Scripts use `--no-interaction` for silent defaults (`CI=true` does **not** skip prompts).

```bash
kona new                          # ask every question
kona new my-app                   # directory set; still asks lang / kit / CSS / db / …
kona new my-app --no-interaction  # silent defaults (kotlin, web, sqlite)
kona new my-app --kit=api --lang=java --no-interaction
kona new my-app --kit=inertia --frontend=react --css=tailwind
kona new my-app --kit=inertia --frontend=vue --typescript
kona new my-app --kit=brew --css=bootstrap --install-deps --migrate --seed
```

The default kit (when you skip the stack prompt) is **`web`** — Crema views. Non-interactive CSS stays **custom** (inline styles, no npm) so a first `./grind serve` works with zero JavaScript toolchain. The interactive CSS prompt defaults to **Tailwind CSS**.

## Interactive order

Without `--no-interaction`, `kona new` asks only for values you did not already pass:

1. **Where should we create the app?** — default `kona-app` (skipped if you pass a directory)
2. **App name** — `APP_NAME` in `.env`; default is Title Case of the folder (`my-app` → `My App`)
3. **Language** — Kotlin (default) or Java
4. **What are we brewing?** — API only, Crema, Brew, or Inertia
5. **Inertia adapter** — Vue, React, or Svelte (Inertia only)
6. **Frontend language** — JavaScript (default) or TypeScript (Inertia only; skipped when `--typescript` / `--ts` or `--javascript` / `--js` is set)
7. **CSS** — Tailwind, Bootstrap, or custom (skipped for API)
8. **Database** — sqlite (default), h2, mysql, mariadb, pgsql, sqlsrv, oracle
9. **Install dependencies now?** — Gradle wrapper, plus `npm` or `pnpm` when `package.json` exists
10. **Run initial migrations?**
11. **Run database seeders?**
12. **Summary card** — then confirm before any files are written

`--no-interaction` / `--no-interactive` never wait on stdin (no directory uses the default folder `kona-app`). Closed or unreadable stdin prints an error instead of scaffolding. `CI=true` is **not** treated as `--no-interaction`.

## Flags that skip a step

| Flag | Skips |
|------|--------|
| Directory argument | “Where should we create the app?” |
| `--name=` / `--app-name=` | App name (`APP_NAME`) |
| `--lang=kotlin\|java` | Language |
| `--kit=` / `--preset=` | Stack (`web`, `api`, `crema`, `inertia`, `brew`) |
| `--frontend=vue\|react\|svelte` | Inertia adapter |
| `--typescript` / `--ts` | Inertia frontend language → TypeScript |
| `--javascript` / `--js` | Inertia frontend language → JavaScript |
| `--css=tailwind\|bootstrap\|custom` | CSS (`tw`, `bs`, `none` / `vanilla` / `plain` aliases) |
| `--database=` | Database engine |
| `--install-deps` / `--no-install-deps` | Gradle + npm/pnpm offer |
| `--migrate` / `--no-migrate` | Initial migrations |
| `--seed` / `--no-seed` | Seeders |
| `--no-interaction` / `--no-interactive` | Every prompt; use defaults |

`--install-deps=false`, `--migrate=no`, and `--seed=0` are the same as the `--no-*` forms.

After a **DONE** chip, the outro lists `cd`, `./grind serve`, and (when you skipped migrate) `./grind migrate --seed`. Kits with a JS app also print `npm install && npm run dev`.

## Kits

| Kit | Dependencies | What you get |
|-----|--------------|--------------|
| `web` (default) | HTTP + grind + session/auth/queue/… + **crema** | Welcome view, login, dashboard, JSON `/api/health` |
| `crema` | same as `web` | Alias of `web` |
| `api` | without Crema | Plain-text `/` welcome + JSON health (no CSS pipeline) |
| `inertia` | + `kona-inertia` | Inertia middleware, root shell, Vite + Vue/React/Svelte, Crema login/dashboard |
| `brew` | + `kona-brew` | Crema landing with a live `<brew:counter />` plus login/dashboard |

Every kit registers Cadence, Redis, Session, Auth, Queue, Schedule, and Mail providers; generates `APP_KEY` in `.env`; and applies `StartSession` + CSRF (except `/api/*` and `/brew/*`) in `bootstrap.Middleware`.

## CSS

`--css` (and the CSS prompt) compose on the kit. They write a **real** Vite pipeline, not a stub:

| Value | What is written |
|-------|-----------------|
| `custom` (non-interactive default) | Existing branded inline styles on Crema views; Inertia welcome pages use inline styles. No extra npm unless the kit already has a JS app (Inertia). |
| `tailwind` | `package.json` + Vite + Tailwind v4 (`@tailwindcss/vite`), `css/app.css` with the coffee `@theme`, Crema views (or Inertia pages) using utilities, `@vite('src/main/resources/js/app.js')` |
| `bootstrap` | Vite + Bootstrap 5, Crema/Inertia markup using Bootstrap classes |

Crema and Brew with Tailwind or Bootstrap add `src/main/resources/js/app.js` that imports the CSS. Inertia adapters import the same file from `app.js` / `app.jsx` (or `app.ts` / `app.tsx` when you opt into TypeScript).

The web root is the project directory `public/` (`paths.public`). Logos and `robots.txt` live there. Vite’s production build writes `public/build`. Source entries stay under `src/main/resources/js/`. `kona new` does not create `src/main/resources/public`.

Serve CSS in development with Vite running (`npm run dev`) alongside `./grind serve`. Production: `npm run build` writes `public/build`.

## Inertia adapters

| `--frontend` | JavaScript entry (default) | TypeScript entry | Packages |
|--------------|----------------------------|------------------|----------|
| `vue` (default) | `src/main/resources/js/app.js` | `src/main/resources/js/app.ts` | `@inertiajs/vue3` |
| `react` | `src/main/resources/js/app.jsx` | `src/main/resources/js/app.tsx` | `@inertiajs/react` |
| `svelte` | `src/main/resources/js/app.js` | `src/main/resources/js/app.ts` | `@inertiajs/svelte` |

The same path is the Vite `rollupOptions.input` and `InertiaManager.viteEntries`, so the manifest key matches the tag `{!! vite !!}` prints.

### Frontend language

JavaScript is the default. Non-interactive `kona new my-app --kit=inertia --no-interaction` stays JavaScript.

| Flag | Effect |
|------|--------|
| `--typescript` or `--ts` | TypeScript entry, `tsconfig.json`, and `typescript` in `devDependencies` |
| `--javascript` or `--js` | Force JavaScript |
| Both | The **last** flag on the command line wins. `--typescript=false` selects JavaScript; `--javascript=false` selects TypeScript |

API, Crema, and Brew ignore these flags and do not ask. Only Inertia shows **Frontend language** (after the adapter prompt).

TypeScript scaffolds:

- **Vue** — `app.ts`, `<script setup lang="ts">` on `Pages/Welcome.vue`, `env.d.ts`, `vue-tsc`, script `typecheck`
- **React** — `app.tsx` and `Pages/Welcome.tsx`, `vite-env.d.ts`, `@types/react`, `@types/react-dom`
- **Svelte** — `app.ts`, `<script lang="ts">` on `Pages/Welcome.svelte`, `vite-env.d.ts`, `svelte.config.js` with `vitePreprocess` so `npm run build` can compile the page

`npm run build` is still Vite. `npm run typecheck` runs `vue-tsc` (Vue) or `tsc` (React and Svelte).

Landing, login, and dashboard still ship as **Crema HTML** so session auth works before you add more Inertia pages. `js/Pages/Welcome.*` is the client page to grow from.

## Install, migrate, seed

When you accept (or pass `--install-deps`), `kona new` runs `./gradlew --no-daemon help -q` in the new app and, if `package.json` exists, `npm install` (or `pnpm install` when `pnpm-lock.yaml` is present). Failures print a WARN chip and continue.

`--migrate` runs `./grind migrate`. `--seed` runs `./grind db:seed`. If there is no database, or grind fails, the installer skips that step instead of aborting. The default engine is **sqlite** (`storage/database/database.sqlite`) so migrate/seed can succeed locally without a server.

## Kotlin and Java

Every kit has Kotlin and Java skeletons (`--lang=kotlin|java`). Controllers, providers, and routes match the language you choose; shared assets (views, `package.json`) are language-neutral.

Generated apps resolve `org.konaframework` artifacts from **Maven Central**. Full guides: [Brew](/docs/brew/), [Inertia](/docs/inertia/), [Vite](/docs/assets/vite/).
