Firefly is Kona's admin panel. You describe a screen in Kotlin or Java. Kona renders it on the server, and [Wire](/docs/wire/) keeps the fields in step with the browser.

A panel is a class. After you install Firefly, the app finds every panel under `app/panels` when it boots. If you do not set `path`, the URL prefix is the panel id. `path("admin")` serves that panel at `/admin`. `path("")` serves it at the site root.

<FilamentNod>

Firefly stands on the shoulders of [Filament](https://filamentphp.com/). The way Filament fits a panel together — resources, forms, tables, and how those pieces compose — shaped a lot of what you can do here. We’re our own panel for Kona. You write it in Kotlin, and you call the same types from Java. Live fields go through [Kona Wire](/docs/wire/), views through [Crema](/docs/crema/), and records through [Cadence](/docs/cadence/).

</FilamentNod>

Use a panel for the people who run the app. A public page or a JSON API stays on an ordinary Kona route. Installing Firefly registers those panel URLs when the app boots.

You can also call `render()` on a schema, a form, or a table and place that HTML in a view or a test. The panel is what turns those pieces into URLs, a sidebar, and a sign-in screen.

## What you put in the app

`./grind install firefly` writes the config and a service provider. `./grind make:firefly-panel` writes the panel class under `app/panels/{id}/`. The provider loads that class, and the class loads three folders beside it:

| Folder | Put this here |
|--------|----------------|
| `pages/` | A screen you design, such as a Desk page |
| `widgets/` | A stat, a chart, or a block on a page |
| `resources/` | One class per record type, such as notes or orders |

`samples/hello-kotlin` and `samples/hello-java` are an older layout under `app/firefly`, and those classes call `path("admin")`, so they are served at `/admin`. These pages follow the Kotlin sample. The Java sample has the same screens.

On that app you can open:

- `/` — the welcome page, outside the panel
- `/admin/desk` — the Desk page: a form, an infolist, a table, a header action, and a widget
- `/admin/notes/manage` — a simple resource. One page. Create, edit, view, and delete open in a dialog
- `/admin/orders/list`, `/admin/orders/create`, `/admin/orders/edit`, `/admin/orders/view` — a full resource, with line items on edit and view

Drop a resource in `resources/`. Discovery picks it up. Call `page`, `widget`, or `resource` yourself only when you want to skip the folder.

## Where the types live

Depend on `org.konaframework:kona-firefly`. That coordinate brings the other Firefly modules with it. Open a module when you want the package for a type:

- `kona-firefly` — the panel, pages, resources, navigation, tenancy, plugins, import and export, and `Firefly.test`
- `kona-firefly-schemas` — the component tree and its state map. Sections, grids, tabs, and plain text live here
- `kona-firefly-forms` — fields on that tree, including the combobox select and the crafted date picker, with validation
- `kona-firefly-infolists` — read-only entries: text, icons, images, and the other ways to show a record
- `kona-firefly-tables` — columns, filters, search, sort, and pages
- `kona-firefly-actions` — a button or a link, the dialog it can open, and the server method it calls
- `kona-firefly-notifications` — a toast, a database bell, and a broadcast refresh marker
- `kona-firefly-widgets` — stats, charts, and custom blocks on a page
- `kona-firefly-support` — the dialog, icons, theme tokens, and `FireflyException`. The other modules depend on it, so your app depends on `kona-firefly` only

## When you want a plugin, a theme, or a test

Pass a plugin to `plugin(...)`. `register` runs immediately. `boot` runs when the panel mounts. Inside those methods you call the same panel methods the app calls: a brand, a hook, a page. Keep the class in the app when the behavior belongs to that app. Read [Plugins](/docs/firefly/plugins/).

The shipped look is `KonaTheme`. `Stylesheet.render` writes the colors and type as CSS custom properties on `.ff-panel`. Component rules match only inside that class. To change the look, implement `FireflyTheme` and pass it to `theme(...)`. `extraCss()` is wrapped in `.ff-panel { ... }`, so your rules stay inside the panel. The hello sample uses the shipped theme. Read [Themes and CSS](/docs/firefly/themes/).

`Firefly.test` reads HTML you already rendered. It lives in `org.konaframework.firefly.testing`.

`assertSee` fails when the text is missing. `assertFormField` looks for `data-ff-path`. `assertTable` wants both `ff-table` and the text. `assertDialog` wants both `ff-dialog` and the title. `Firefly.test(html)` checks a string. The same assertions are on [Import and export](/docs/firefly/import-export/).
