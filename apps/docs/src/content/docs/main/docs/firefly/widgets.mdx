A widget is a small block on a page: a stat, a chart, a table, or a paragraph you wrote. You place it with `widgets(...)` on a page. The panel draws those blocks inside `<div class="ff-page-widgets">`.

The hello sample’s `DeskWidget` is a paragraph that reads “Open orders”. Discovery finds it in `widgets/` and puts it on the Desk page, because Desk is the first page.

Chart.js is the default chart engine. Pass `ChartEngine.APEX_CHARTS` when you want ApexCharts. The types live in `org.konaframework.firefly.widgets` (`kona-firefly-widgets`). `extraAttributes` is on every widget. Chart filters also accept `extraInputAttributes`.

## A widget on a page

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val page = Page()
    .title("Desk")
    .headerActions(Action.make("refresh").label("Refresh"))
    .widgets(
        StatsOverviewWidget.make("overview").stats(
            Stat().label("Orders").value("12").description("Today").color("caramel"),
        ),
        RevenueChart(),
        OrdersChart(),
    )
val html = page.render()
```

</TabItem>
<TabItem label="Java">

```java
Page page = new Page();
page.title(get -> "Desk");
page.widgets(
    StatsOverviewWidget.make("overview").stats(
        new Stat().label("Orders").value("12")
    ),
    new RevenueChart(),
    ChartWidget.make("orders").engine(ChartEngine.APEX_CHARTS).type("area")
);
String html = page.render();
```

</TabItem>
</Tabs>

`Page.render()` returns `<section class="ff-page">` with a header, the content region, `<div class="ff-page-widgets">`, and a footer. `Dashboard` uses `ff-page ff-dashboard` and the fallback title `Dashboard`. The content region is filled by `schema(...)`, `form(...)`, `infolistHtml(...)`, or `table(...)`. Widgets render in the widgets region, so a chart is on the page rather than only in a standalone string.

`widgets(...)` replaces the widget list. `discoverWidgets(panelDirectory)` appends every widget found under `panelDirectory/widgets`.

A widget’s own `render()` returns the same HTML you would get by placing that one widget in a schema. Use it in tests and when you embed a widget outside a page.

## Stats

`Stat` needs a label and a value. A blank label throws `Stat label is blank`. A blank value throws `Stat value is blank`. Description, color, icon, and `chart` (a list of numbers) are optional. `StatsOverviewWidget.make(name).stats(...)` renders one `<article class="ff-stat">` per stat. An empty stats list throws `FireflyException`.

## Charts

`ChartWidget` defaults to Chart.js (`ChartEngine.CHART_JS`). Pass `ChartEngine.APEX_CHARTS` to use ApexCharts. The chart type is `line` unless you set `bar`, `area`, `pie`, or `donut`. Any other type throws `FireflyException`. Chart.js receives `area` as `line` and `donut` as `doughnut`. ApexCharts keeps `area` and `donut`. `options` is passed through to the library config.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
ChartWidget.make("revenue")
    .type("bar")
    .categories(listOf("Mon", "Tue", "Wed"))
    .series(listOf(ChartSeries("Revenue", listOf(10, 20, 15))))
    .maxHeight("240px")
```

</TabItem>
<TabItem label="Java">

```java
ChartWidget.make("revenue")
    .type("bar")
    .categories(List.of("Mon", "Tue", "Wed"))
    .series(List.of(new ChartSeries("Revenue", List.<Number>of(10, 20, 15))))
    .maxHeight("240px");
```

</TabItem>
</Tabs>

`RevenueChart` is that bar chart on Chart.js. `OrdersChart` is an area chart on ApexCharts.

`filters` is a map of key to label. `activeFilter` selects which `series(filter, points)` list is drawn. A blank filter name, or a filter with no series, throws `FireflyException`. `extraInputAttributes` lands on the filter `<select>`.

The markup is `<div class="ff-chart">` with `data-ff-engine` (`chartjs` or `apexcharts`), `data-ff-type`, and `data-ff-library-type`. A `<script type="application/json" class="ff-chart-config">` holds the categories, series, and options. Script tags for `/_firefly/widgets/ff-widget.js`, `ff-chart.js`, and either `chart.umd.js` (Chart.js 4.4.6) or `apexcharts.min.js` (ApexCharts 3.54.1) are included once per render. `WidgetScripts.source(path)` returns the vendored file.

`ChartWidget.configureUsing` runs for every later `ChartWidget.make`. Pass `null` to clear it.

## Table and account

`TableWidget.make(name).table(table)` renders the same table HTML as `Table.render()`. A missing table throws `FireflyException`. The table still needs a record `id`.

`AccountWidget.make(name).accountName("Ada").email("ada@example.com").avatar("/ada.png")` renders the account card. A blank name throws `FireflyException`.

## Discovery

`WidgetDiscovery.discover(panelDirectory)` reads `panelDirectory/widgets`. A missing directory returns an empty list. A path that exists and is not a directory throws `FireflyException`. Each `.kt` or `.java` file must declare a package and a class whose name matches the file name. The class must already be on the classpath and must have a public no-arg constructor. Abstract classes and types that are not widgets are skipped. A missing package, a missing class declaration, a name that does not match the file, a class that is not on the classpath, or a constructor that fails throws `FireflyException` and names the file.

## Generate a widget

```bash
./grind make:firefly-widget Revenue
./grind make:firefly-widget Orders --lang=java
```

The command writes `app/firefly/widgets/Revenue.kt` (or `Orders.java`) and a Crema view `firefly.widgets.revenue` that uses `x-data="ffWidget"`. The class extends `Widget` and calls `view(...)`.

## What you build with

| Type | Role |
|------|------|
| `Widget` | Base widget. `make(name)`, `label`, `heading`, `description`, `extraAttributes` |
| `Page` / `Dashboard` | Title, header and footer actions, schema or table, and widgets |
| `Stat` / `StatsOverviewWidget` | One or more stat cards |
| `ChartWidget` | Chart.js by default, ApexCharts when you set the engine |
| `TableWidget` | Embeds a Firefly table |
| `AccountWidget` | Name, email, and avatar |
| `WidgetDiscovery` | Loads widgets from a panel `widgets/` directory |
