Add a screen when the desk needs a page that is not a resource. Give it a title, buttons in the header and the footer, and a content region for the form, the infolist, or the table.

Call `render()` on that page from a test. The panel turns the same page into a URL. In the hello samples, Desk is a custom page at `/admin/desk`. The file is `app/firefly/pages/Desk`.

<FireflyShot file="desk.png" description="The Desk page at http://127.0.0.1:4017/admin/desk, with the name field, the status combobox, the due picker, the infolist, the table, and the Edit header action." />

The types live in `org.konaframework.firefly` and `org.konaframework.firefly.widgets`. `PanelPage` extends `Page`. `ListPage`, `CreatePage`, `EditPage`, `ViewPage`, `ManagePage`, and `CustomPage` are the page kinds. `Dashboard` is a `Page` whose section class is `ff-page ff-dashboard`.

## How the URL is chosen

`Panel.mount` registers `GET /{prefix}/{slug}` for each page discovered from `pages/` or passed to `page(...)`. The hello sample’s `Desk` uses slug `desk`, so the route is `/admin/desk`. When the request is allowed, the panel renders the chrome and puts `page.render()` in the body.

`navigationLabel()` is the sidebar text. The default is the slug, or `Dashboard` when the slug is empty. A page titled `Desk` still shows the link `desk` until you change the label. `parent("name")` nests the page under a navigation item with that name. A missing parent fails at mount and names both items.

## Write the Desk page

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
class Desk : CustomPage("desk") {
    init {
        title("Desk")
        mountForm(
            Schema.make().components(
                TextInput.make("name"),
                Select.make("status").options(mapOf("open" to "Open", "done" to "Done")),
                DateTimePicker.make("due"),
            ),
        )
        mountInfolist(Infolist.make().components(TextEntry.make("name")))
        table(Table.memory(mapOf("id" to "1", "name" to "Ada")).columns(TextColumn.make("name")))
        headerActions(
            Action.make("edit").label("Edit").modal().modalHeading("Edit note").schema(TextInput.make("note")),
        )
    }
}
```

</TabItem>
<TabItem label="Java">

```java
public class Desk extends CustomPage {
    public Desk() {
        super("desk");
        title("Desk");
        mountForm(Schema.make().components(
            TextInput.make("name"),
            Select.make("status").options(Map.of("open", "Open", "done", "Done")),
            DateTimePicker.make("due")
        ));
        mountInfolist(Infolist.make().components(TextEntry.make("name")));
        table(Table.memory(row()).columns(TextColumn.make("name")));
        headerActions(Action.make("edit").label("Edit").modal().modalHeading("Edit note").schema(TextInput.make("note")));
    }
}
```

</TabItem>
</Tabs>

`mountForm` stores the schema as the page form. You see the name field, the status combobox, and the due picker. `mountInfolist` renders the infolist to HTML and stores that markup. `table` and `headerActions` come from `Page`. The edit action’s dialog is in the HTML and stays closed until Alpine opens it.

```bash
./grind make:firefly-page Desk
./grind make:firefly-page Desk --lang=java
```

The command writes a `CustomPage` in `pages/`. The slug is the lowercased name. The generated class has no form yet.

## Methods on Page

| Method | What you get |
|--------|----------------|
| `title(value)` / `title(provider)` | Heading text, or a closure that receives `Get` |
| `headerActions(...)` / `footerActions(...)` | Replaces that action list |
| `widgets(...)` | Replaces the widgets drawn in `ff-page-widgets` |
| `discoverWidgets(directory)` | Appends widgets found under `directory/widgets` |
| `schema(schema)` | Content region from a schema |
| `form(schema)` | Content region from a form schema |
| `infolistHtml(html)` | Content region from infolist HTML |
| `table(table)` | Content region from a table |
| `render()` / `render(state)` | `<section class="ff-page">` with header, content, widgets, and footer |

`PanelPage` adds:

| Method | What you get |
|--------|----------------|
| `slug()` | The constructor slug, or the class name without a trailing `Page`, lowercased |
| `navigationLabel()` | Slug text, or `Dashboard` when the slug is empty |
| `parent(name)` | Navigation parent. `parentName()` reads it back |
| `mountForm(schema)` | Same slot as `form` |
| `mountInfolist(infolist)` | Renders the infolist and stores the HTML |

Section classes: `ff-list`, `ff-create`, `ff-edit`, `ff-view`, `ff-manage`, `ff-custom`. Fallback titles match those names (`List`, `Create`, `Edit`, `View`, `Manage`, `Custom`).

`ManagePage` is the page a simple resource uses. Create, edit, view, and delete for that resource are header actions. Read [Resources](/docs/firefly/resources/).

## Put a widget on the page

`Page.render()` includes `<div class="ff-page-widgets">`. A widget you pass to `widgets(...)` is in the page. The panel also copies discovered widgets onto the home page (empty slug) or the first page. See [Widgets](/docs/firefly/widgets/).
