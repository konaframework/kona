Write the panel class, point `discover` at its folder, and call `mount`. After that, drop a page, a widget, or a resource in the matching folder. The next request can serve it.

The class in your app is `app.firefly.Panel`. It extends `org.konaframework.firefly.Panel`. The hello samples and `kona new --kit=firefly` both start from that class.

<FireflyShot file="panel-directory.png" description="The hello-kotlin app/firefly directory, showing Panel.kt, pages/, widgets/, and resources/." />

## Write the panel file

Put this class in `src/main/kotlin/app/firefly/Panel.kt`, or `src/main/java/app/firefly/Panel.java`. The id shows up in route names and in the guard `firefly-desk`. The path is the URL prefix. `authenticate(false)` leaves the screens public, which is how the hello samples ship. `discover` loads the child folders.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
package app.firefly

import org.konaframework.core.Kona

class Panel : org.konaframework.firefly.Panel() {
    init {
        id("desk")
        path("admin")
        brand("Desk")
        authenticate(false)
        discover(Kona.app().basePath("src/main/kotlin/app/firefly"))
    }
}
```

</TabItem>
<TabItem label="Java">

```java
package app.firefly;

import org.konaframework.core.Kona;

public class Panel extends org.konaframework.firefly.Panel {
    public Panel() {
        id("desk");
        path("admin");
        brand("Desk");
        authenticate(false);
        discover(Kona.app().basePath("src/main/java/app/firefly"));
    }
}
```

</TabItem>
</Tabs>

`./grind make:firefly-panel` writes `id` and `path` only. Add `brand`, `authenticate`, and `discover` yourself when you generate the class. `./grind firefly:install` writes that same shorter class. The kit writes the full class above.

## Mount it after your own routes

hello-kotlin imports `app.firefly.Panel` as `DeskPanel` so the name stays clear in `bootstrap/App.kt`. hello-java constructs `app.firefly.Panel`. Both calls sit after the welcome routes, so `/` stays the welcome page.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
import app.firefly.Panel as DeskPanel

WebRoutes().register(router)
ApiRoutes().register(router)
DeskPanel().mount(router)
```

</TabItem>
<TabItem label="Java">

```java
new WebRoutes().register(router);
new ApiRoutes().register(router);
new app.firefly.Panel().mount(router);
```

</TabItem>
</Tabs>

`mount` registers the panel’s GET and POST paths. Calling it twice throws `FireflyException` and names the panel id. If a path is already taken, `mount` throws and names both handlers. The existing route stays. A panel does not register `/_firefly/` or `/wire/update`.

## What discover loads

`discover(panelDirectory)` reads three folders. A missing folder is empty. A file must declare a package and a class whose name matches the file. That class must already be on the classpath and must have a no-arg constructor. Abstract classes and unrelated types are skipped.

| Folder | Loaded type |
|--------|-------------|
| `pages/` | `PanelPage` (`CustomPage`, and the list, create, edit, view, and manage pages) |
| `widgets/` | `Widget` |
| `resources/` | `Resource` |

hello-kotlin uses exactly those three folders:

```text
app/firefly/Panel.kt
app/firefly/pages/Desk.kt
app/firefly/widgets/DeskWidget.kt
app/firefly/resources/NoteResource.kt
app/firefly/resources/OrderResource.kt
```

hello-java uses the same names under `src/main/java/app/firefly/`.

Generators for fields, entries, columns, filters, actions, layouts, and themes write sibling folders (`fields/`, `entries/`, `columns/`, `filters/`, `actions/`, `layouts/`, `themes/`). `discover` does not scan those folders. Reference those classes from a page, a resource, or `theme(...)`.

You can still call `page`, `widget`, and `resource` on the panel. There is no app-wide registry.

Discovered widgets land on the page whose slug is empty, or on the first page when no page has an empty slug. In the hello samples that first page is `Desk`, so `DeskWidget` renders on `/admin/desk`.

## URLs you get with path("admin")

| URL | Screen |
|-----|--------|
| `/admin/desk` | The custom Desk page |
| `/admin/notes/manage` | The simple notes resource |
| `/admin/orders/list` | Orders list |
| `/admin/orders/create` | Orders create |
| `/admin/orders/edit` | Orders edit |
| `/admin/orders/view` | Orders view |

`path("")` serves the same screens at the site root. Auth screens (`/admin/login`, `/admin/register`, `/admin/password-reset`, `/admin/email-verify`, `/admin/profile`) are registered even when `authenticate(false)` skips the redirect.
