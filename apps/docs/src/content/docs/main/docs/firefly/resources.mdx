Add one class per record type, put it in the panel’s `resources/` folder, and discovery serves it. Bind a model, a form, an infolist, and a table on that class.

Call `simple()` when you want one Manage page. Leave it off when you want list, create, edit, and view as their own URLs. The hello samples use both. The click-through is on [A working app](/docs/firefly/working-app/). This page is the method list.

The sidebar gets **one entry per resource** (the list or manage page). Create, edit, view, and delete are page-header and row actions — never separate sidebar links. See [Navigation](/docs/firefly/navigation/).

The types live in `org.konaframework.firefly` (`kona-firefly`).

## Serve a full resource

Put the class in `app/panels/{panel}/resources/{model}/` (or a flat `resources/` file the panel still discovers). The generator uses the grouped layout: `{Model}Resource` beside a `pages/` folder. Override `form`, `infolist`, `table`, `getRelations`, and `getPages`. Leave `getPages()` alone and a full resource serves list, create, edit, and view. Prefer `getRelations()` for relation managers (same override style as the other hooks); fluent `relation(...)` in `init` still works for one-liners.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
class OrderResource : Resource("orders") {
    init {
        label("Orders")
        model(Order::class.java)
    }

    override fun form(schema: Schema): Schema =
        schema.components(TextInput.make("name"))

    override fun infolist(schema: Schema): Schema =
        schema.components(TextEntry.make("name"))

    override fun table(table: Table<*, *>): Table<*, *> =
        table.columns(TextColumn.make("name"))

    override fun getRelations(): List<RelationManager> = listOf(
        RelationManager("lines").related(Line::class.java).titleAttribute("sku"),
    )

    override fun getPages(): Map<String, Page> = mapOf(
        "list" to ListPage("list"),
        "create" to CreatePage("create"),
        "edit" to EditPage("edit"),
        "view" to ViewPage("view"),
    )
}
```

</TabItem>
<TabItem label="Java">

```java
public class OrderResource extends Resource {
    public OrderResource() {
        super("orders");
        label("Orders");
        model(Order.class);
    }

    @Override
    public Schema form(Schema schema) {
        return schema.components(TextInput.make("name"));
    }

    @Override
    public Schema infolist(Schema schema) {
        return schema.components(TextEntry.make("name"));
    }

    @Override
    public Table<?, ?> table(Table<?, ?> table) {
        return Table.memory().columns(TextColumn.make("name"));
    }

    @Override
    public List<RelationManager> getRelations() {
        return List.of(
            new RelationManager("lines").related(Line.class).titleAttribute("sku")
        );
    }

    @Override
    public Map<String, Page> getPages() {
        Map<String, Page> pages = new LinkedHashMap<>();
        pages.put("list", new ListPage("list"));
        pages.put("create", new CreatePage("create"));
        pages.put("edit", new EditPage("edit"));
        pages.put("view", new ViewPage("view"));
        return pages;
    }
}
```

</TabItem>
</Tabs>

The page calls `form`, `table`, and `infolist` when it renders, so those methods can read the current tenant and `schema.record()`. Resource pages render a Shamar-style breadcrumb trail (Dashboard → resource → current title) above the page heading. List and manage page headings, the sidebar entry, and the list crumb use **`pluralLabel()`** (default: an English plural of `label()`, so `label("User")` shows **Users** without double-pluralizing an already-plural `label("Orders")`). Set `pluralLabel("People")` or `pluralLabel { … }` when the default inflection is wrong. Create and edit titles still use `label()` (`New User`, `Edit Orders`). The list page mounts the table (Wire-driven search, filters, column sort, numbered pagination, and an empty “No records found.” row when the result set is empty), a **New** header action that links to the create page, and row actions (View, Edit, Delete). The create page wraps the form in a native `POST` form (`#ff-form`, with a CSRF field when a session is present). The **Create** header action is a `type="submit"` button associated with that form; **Cancel** links back to the list. A successful create saves through the resource model’s record store and redirects to the list. The edit page loads the Cadence record from `?id=` into form state (`schema.fill`), mounts the same `#ff-form` pattern with a hidden `id`, and offers **Save** plus View / Cancel / Delete. Delete opens a confirm dialog via `data-ff-dialog-*` (no Alpine required) and posts to `…/delete`. The view page fills the infolist the same way, then mounts relation managers and Edit / Back to list / Delete. Override `getRelations()` to declare relation managers (they also merge with fluent `relation(...)`); relation managers span the full content width with flat table chrome (no outer floating card on edit or view). Only the resource’s list (or manage) nav item stays active — Dashboard uses an exact path match. You open `/{prefix}/orders/list`. The prefix is the panel id when `path` is not set. The hello samples call `path("admin")`, so that URL is `/admin/orders/list`. The sidebar shows one **Orders** link to that list URL and keeps it active on create, edit, and view. Header actions stay in a horizontal row.

`query()` chooses the store from the model type. A Cadence model returns a `ModelBuilder`. A document model fails and names `kona-firefly-document`, which is not part of this release. Any other type fails and tells you to use `Table.memory` for custom rows.

## Serve a simple resource

<FireflyShot file="notes-manage.png" description="The notes Manage page at http://127.0.0.1:4017/admin/notes/manage, with the notes table, a Create header action, and row View, Edit, and Delete actions." />

`simple()` keeps one manage page. You still override `form`, `infolist`, and `table`. Leaving `getPages()` alone uses the framework `ManagePage`. The generator instead writes a thin `Manage{Model}` subclass and returns it from `getPages()` so you have a class to customize. The manage page is **table-only** until an action opens a dialog — it does not mount a standing create/edit form. **Create** is the sole header action and opens a dialog with the form schema on a prototype model (so `Select.relationship` can load options). **View**, **Edit**, and **Delete** are row actions: View opens the filled infolist, Edit opens the filled form (or a prototype when the row is not in the store yet), and Delete confirms in a dialog. A simple resource rejects `relation(...)`.

The route is `/{prefix}/notes/manage` when the slug is `notes` and the page slug is `manage`. The hello samples use the prefix `admin`. You see the notes table and the Create, Edit, View, and Delete actions.

## Generate one

`./grind make:firefly-resource Order` treats `Order` as the **model** name and writes one grouped folder:

```
app/panels/admin/resources/order/
  OrderResource.kt
  pages/ListOrder.kt … CreateOrder / EditOrder / ViewOrder
```

Package is `app.panels.admin.resources.order` (pages under `.pages`). Group under the lowercase **model** name so the JVM never confuses a class with a package. The resource’s `getPages()` returns those page instances, and a stub relation manager is included. Passing `OrderResource` already does not double-suffix. `./grind make:firefly-resource Note --simple` writes `resources/note/NoteResource` plus `note/pages/ManageNote`.

Without flags, form / table / infolist stub a single `name` text field. Pass **`--generate`** to boot the app, load `app.models.Order`, introspect that model’s database table, and emit components for the columns (skipping primary key and timestamps on the form). Booleans / `TINYINT(1)` / `BIT` / `NUMBER(1)` map to form `Toggle`, table `IconColumn.make(...).boolean()`, and infolist `IconEntry.make(...).boolean()`. Dates → `DatePicker` / `DateTimePicker`, long text → `Textarea`. `--generate` fails if the model class, table, or database is missing — it does not fall back to the `name` stub. Run `./grind migrate` first. Pass `--panel=billing` for another panel directory. Page stubs register only through `getPages()` (panel `pages/` discovery does not load them).

The hello samples mount a desk panel at `/admin` with a custom page, a widget, a simple note resource, and a full order resource.

## Content max width

`Resource.maxWidth(token)` sets the default content column for every page of that resource (`xs`…`7xl`, `full`, `screen`, `prose`). It overrides the panel default when the page renders. A page that already called `maxWidth` keeps its own value. List and manage tables fill that column.

```kotlin
Resource("orders").model(Order::class.java).maxWidth("full")
```

```java
new Resource("orders").model(Order.class).maxWidth("full");
```

## What you build with

| Type | Role |
|------|------|
| `Resource` | Model, form, infolist, table, actions, and pages. Optional `maxWidth(token)` for the content column |
| `label` / `pluralLabel` | Singular-or-base title vs list/nav plural heading (`pluralLabel` defaults from `label`) |
| `RelationManager` | Related records on a full resource's edit and view pages. Set the label column with `titleAttribute` |
| `ManagePage` | The single page of a simple resource |
| `query()` | `ModelBuilder` for a Cadence model |
