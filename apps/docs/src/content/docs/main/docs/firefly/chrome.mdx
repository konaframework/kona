Change the frame around every screen when the default sidebar, top bar, body, or footer is close and you want a different sidebar, a banner, or your own wrapper.

The class that draws the frame is `org.konaframework.firefly.support.Panel`. The class you mount on the router is `org.konaframework.firefly.Panel`, on [Panel](/docs/firefly/panel/). The support class picks HTML for each region, checks that the hook markers are still there, fills those markers, and asks a layout to wrap the result.

**Direction:** new Firefly chrome and components use [Wire](/docs/wire/) classes with [Crema](/docs/crema/) views — the class holds config and behavior; the Crema file owns markup. Custom fields, columns, and widgets already follow that shape via `./grind make:firefly-field` (and siblings). The built-in document layout still renders from Kotlin today; migrating it to Crema is the next chrome step. Prefer overriding slots with Crema-backed HTML rather than growing string templates in the panel class.

## Call the support Panel

| Method | What you get |
|--------|----------------|
| `theme(FireflyTheme)` | Theme used for tokens, CSS, and theme partials. Default: `KonaTheme` |
| `layout(PanelLayout)` | Replaces the wrapper. Default: `DefaultLayout`. A later call replaces the earlier layout |
| `hook(Hook, String)` | Appends HTML for that hook. Several calls for the same hook concatenate, in order |
| `overridePartial(slot, html)` | App HTML for one slot. Wins over the theme partial and the built-in partial |
| `render(): String` | Resolves every slot, then `layout.render(...)` |

Slots, in order: `sidebar`, `topbar`, `body`, `footer`.

For each slot, `render` picks the first source that exists:

1. `overridePartial` for that slot, when you set one.
2. `theme.partial(slot)`, when it returns non-null.
3. The built-in partial.

Unknown slot names passed to `overridePartial` are stored and ignored, because only the four slots are resolved.

## Keep the hook markers

Every chosen partial must still contain the markers for its slot. The marker text is exact, including the comment:

| Slot | Required markers |
|------|------------------|
| `sidebar` | `<!-- ff-hook:sidebar.start -->` and `<!-- ff-hook:sidebar.end -->` |
| `topbar` | `<!-- ff-hook:topbar.start -->` and `<!-- ff-hook:topbar.end -->` |
| `body` | `<!-- ff-hook:body.start -->` and `<!-- ff-hook:body.end -->` |
| `footer` | `<!-- ff-hook:footer -->` |

If any marker is missing, `render` throws `FireflyException`:

```text
Partial [<slot>] is missing markers [<marker>, ...]
```

The shell does not render. Put the comments back in the HTML, including when your markup surrounds them.

After the check, each marker is replaced with the concatenated hook HTML. A hook you never filled becomes an empty string, so the comment disappears.

`Hook` values: `SIDEBAR_START`, `SIDEBAR_END`, `TOPBAR_START`, `TOPBAR_END`, `BODY_START`, `BODY_END`, `FOOTER`. Each has a `marker` string (`sidebar.start`, and so on).

## Built-in partials

| Slot | Element |
|------|---------|
| sidebar | `<aside class="ff-sidebar">` |
| topbar | `<header class="ff-topbar">` |
| body | `<main class="ff-body">` |
| footer | `<footer class="ff-footer">` |

## What the default layout writes

`DefaultLayout` writes:

```html
<div class="ff-panel">
  <style>…theme CSS…</style>
  …sidebar…
  …topbar…
  …body…
  …footer…
</div>
```

If a slot were absent from the map it receives, it would throw `Missing partial [<name>]`. `Panel` always fills all four slots before calling the layout, so that failure is for a custom caller of `DefaultLayout` that omits a key.

## Replace one partial

The override must keep the markers. This sidebar adds a label and still accepts hooks:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val shell = Panel().overridePartial(
    "sidebar",
    """<aside class="ff-sidebar"><strong>Menu</strong><!-- ff-hook:sidebar.start --><!-- ff-hook:sidebar.end --></aside>""",
)
```

</TabItem>
<TabItem label="Java">

```java
Panel shell = new Panel().overridePartial(
    "sidebar",
    "<aside class=\"ff-sidebar\"><strong>Menu</strong><!-- ff-hook:sidebar.start --><!-- ff-hook:sidebar.end --></aside>"
);
```

</TabItem>
</Tabs>

You see **Menu** at the top of the sidebar. Hooks still inject between the two comments. A theme can supply the same HTML from `partial("sidebar")`. An app override still wins when both exist.

`./grind firefly:publish` copies the sidebar partial to `resources/views/firefly/sidebar.crema.html` so you can edit it in the app. Keep the markers.

## Replace the layout

`PanelLayout.render` receives a `ChromeContext`:

| Field | Contents |
|-------|----------|
| `theme` | The `FireflyTheme` on the shell |
| `hooks` | The `RenderHooks` instance (already applied to the partials) |
| `partials` | Map of slot name to HTML, markers already replaced |
| `css` | The string from `Stylesheet.render(theme)` |

A layout may ignore `DefaultLayout` and place the partials itself. To use the dark tokens, put `ff-dark` on the same element as `ff-panel`:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
class DarkLayout : PanelLayout {
    override fun render(context: ChromeContext): String = """
        <div class="ff-panel ff-dark">
          <style>${context.css}</style>
          ${context.partials["sidebar"]}
          ${context.partials["topbar"]}
          ${context.partials["body"]}
          ${context.partials["footer"]}
        </div>
    """.trimIndent()
}
```

</TabItem>
<TabItem label="Java">

```java
public final class DarkLayout implements PanelLayout {
    @Override public String render(ChromeContext context) {
        return "<div class=\"ff-panel ff-dark\"><style>" + context.getCss() + "</style>"
            + context.getPartials().get("sidebar")
            + context.getPartials().get("topbar")
            + context.getPartials().get("body")
            + context.getPartials().get("footer")
            + "</div>";
    }
}
```

</TabItem>
</Tabs>

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
Panel().layout(DarkLayout()).render()
```

</TabItem>
<TabItem label="Java">

```java
new Panel().layout(new DarkLayout()).render();
```

</TabItem>
</Tabs>

`layout(...)` after `theme(...)` keeps the theme. The theme still supplies tokens, CSS, and theme partials. Only the wrapper changes. Read [Themes and CSS](/docs/firefly/themes/) for the tokens those classes use.
