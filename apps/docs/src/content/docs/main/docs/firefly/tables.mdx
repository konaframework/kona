Name the columns, point the table at the rows, and call `render()`. You get a list toolbar (search field with icon, filters, header buttons), sortable column headers when opted in, pagination with a record count, and an in-table empty state when there are no rows. Columns are not searchable or sortable until you call `searchable()` / `sortable()` (zero-arg means true).

Use `Table.memory` when the rows are already in your hand. The hello samples do that: one row, Ada, so the screen renders before a migration. Use `Table.cadence` when the rows are a Cadence model and you want `where` and `whereHas` on that model’s query.

The types live in `org.konaframework.firefly.tables` (`kona-firefly-tables`). On the notes page the table is `Table.memory(...).columns(TextColumn.make("name"))` inside `app/firefly/resources/NoteResource`.

## Render a table

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val table = Table.memory(
    listOf(
        mapOf("id" to "1", "name" to "Ada", "score" to 2),
        mapOf("id" to "2", "name" to "Bea", "score" to 4),
    ),
).columns(
    TextColumn.make("name").label("Name").searchable().sortable(),
    TextColumn.make("score").money().summarize(Summary.SUM),
)
table.search("ada").sort("name").page(1).perPage(10)
val html = table.render()
```

</TabItem>
<TabItem label="Java">

```java
Map<String, Object> ada = new LinkedHashMap<>();
ada.put("id", "1");
ada.put("name", "Ada");
ada.put("score", 2);
Table<Map<String, Object>, MemoryQuery> table = Table.memory(List.of(ada));
table.columns(
    TextColumn.make("name").label(cell -> "Name").sortable().searchable(),
    TextColumn.make("score").money().summarize(Summary.SUM)
);
table.search("ada").sort("name", "asc").page(1);
String html = table.render();
```

</TabItem>
</Tabs>

`Table.memory` keeps the rows in an in-memory query. `columns(...)` replaces the column list. `search`, `sort`, `page`, and `perPage` narrow what `load()` and `render()` return. Search matches columns you marked `searchable(true)`. Sort accepts `asc` or `desc` on a column you marked `sortable(true)`. You see the Ada row when the search is `ada`.

`load()` returns the current page, the total, the summaries, and the groups. `render()` returns the same page as HTML. An empty page shows “No records found.” inside the table body (override with `empty(...)` / `emptyDescription(...)`). Both accept a fixed string or a closure. Sort headers, search, filters, page links, and per-page size call Wire (`$wire.$call('sort' | 'search' | 'applyFilter' | 'gotoPage' | 'perPage', …)`) so the table updates in place without a full page reload. Pagination shows Previous / numbered pages (with ellipsis) / Next plus an optional rows selector.

## Choose where the rows come from

Use `Table.memory` when the records are already a list of maps. `modifyQueryUsing` receives a `MemoryQuery`. That query filters, sorts, searches, and paginates the list.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
table.modifyQueryUsing { query ->
    query.where("name", "!=", "hidden")
}
```

</TabItem>
<TabItem label="Java">

```java
table.modifyQueryUsing(query -> query.where("name", "!=", "hidden"));
```

</TabItem>
</Tabs>

Use `Table.cadence(Customer::class.java)` when the records are a Cadence model. `modifyQueryUsing` receives that model’s `ModelBuilder`. `where`, `whereHas`, `join`, `with`, and `scope` run on the model query.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val table = Table.cadence(Customer::class.java)
table.modifyQueryUsing { query ->
    query.where("active", true)
        .whereHas("orders") { orders -> orders.where("total", ">", 0) }
        .with("orders")
        .scope { builder -> builder.where("active", true) }
}
```

</TabItem>
<TabItem label="Java">

```java
Table<Customer, ModelBuilder<Customer>> table = Table.cadence(Customer.class);
table.modifyQueryUsing(query -> query
    .where("active", true)
    .with("orders")
    .whereHas("orders", orders -> orders.where("total", ">", 0))
);
```

</TabItem>
</Tabs>

`relationship(Account.class)` builds a query of related options. Pass a closure when that query needs its own `where` or `whereHas`.

`extraAttributes` on a column merges HTML attributes onto the column root. A map or a closure that receives the cell both work. `extraInputAttributes` does the same for a column or filter that renders its own input or select. `type`, `name`, and `value` stay owned by that control.

A list you hold in memory stays on `MemoryQuery`. A Cadence model stays on `ModelBuilder`. A document model fails, and the message names `kona-firefly-document`. That module is not part of this release. Any other type fails and tells you to use `Table.memory` for custom rows.

## Pick a column

| Type | What you call |
|------|----------------|
| `TextColumn.make(name)` | Text, money, or a date. `badge`, `limit`, `html`, `url`, `icon`, `color`, `prefix`, `suffix`, `placeholder` |
| `BadgeColumn.make(name)` | Same as `TextColumn` with `badge(true)` already on — status chips; chain `color(...)` for tone |
| `IconColumn.make(name)` | An icon; chain `.boolean()` (Kotlin) / `.bool()` (Java) for a Shamar check/X chip on truthy state |
| `ImageColumn.make(name)` | An image with `alt`, `imageHeight`, and `imageWidth` |
| `ColorColumn.make(name)` | A color swatch |
| `CheckboxColumn.make(name)` | A checkbox bound to the row. Editable cells call Wire `toggleColumn` and persist immediately; `.editable(false)` / `.editable { … }` makes the cell readonly when the user cannot update the record |
| `ToggleColumn.make(name)` | A toggle that calls `$wire.$call('toggleColumn', ...)` |
| `SelectColumn.make(name)` | A select that calls `$wire.$call('setColumn', ...)` |

`searchable()` / `searchable(true)` includes the column in search. `sortable()` allows `sort(name)`. Zero-arg boolean chainables mean yes; pass `false` to turn off. `toggleable()` adds the column to the toolbar **Columns** picker so users can show or hide it. `toggledHiddenByDefault()` (or `toggledHiddenByDefault(true)`) marks it toggleable and starts it hidden — useful for timestamps so the list stays readable until someone checks them in the picker. Soft-nav keeps the choice in the `columns` query string. `hidden()` and `visible(false)` leave it out of the render entirely (not in the picker). `summarize(Summary.COUNT)`, `SUM`, `AVG`, `MIN`, and `MAX` add a footer value.

Column headings default to a humanized form of the attribute name (`published_at` → `Published At`). CSS still uppercases the header, so you see **PUBLISHED AT**, not `PUBLISHED_AT`. Override with `label(...)` when you need a custom title.

Related titles use a dotted make path (Filament/Shamar shape), up to four levels:

```kotlin
TextColumn.make("project.name").label("Project")
TextColumn.make("owner.company.region.name").label("Region")
```

Cadence tables eager-load the relation path. You can still call `.relationship("project", "name")` on an FK column name when you need the old shape. Mark those columns `searchable()` / `sortable()` the same way as local attributes: search uses a correlated `exists` on the relation (including nested paths), and sort left-joins BelongsTo relations so `order by` targets the related table column. `formatStateUsing` receives the cell state and a `Cell`. `Cell.get` reads a path. A path that starts with `/` is absolute.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
TextColumn.make("name")
    .label { cell ->
        if (cell.get("/kind") == "org") "Organization" else "Name"
    }
    .extraAttributes(mapOf("data-col" to "name"))
```

</TabItem>
<TabItem label="Java">

```java
TextColumn.make("name").label(cell -> "Name").extraAttributes(Map.of("data-col", "name"));
```

</TabItem>
</Tabs>

`money()` formats a number as dollars and cents and defaults the column (and its header) to `Align.END`. `date()` and `dateTime()` format a date, instant, or timestamp for people using PHP-style `F j, Y` (for example `January 2, 2026` or `January 2, 2026, 3:45 PM`). Hover shows the raw value in a tooltip. Columns named like `due_on`, `start_date`, or `created_at` / `updated_at` humanize even without an explicit `.date()` / `.dateTime()` call. `IconColumn.boolean()` paints a Shamar Yes/No toggle pill (check/X mark in a circular badge plus the label inside a capsule). Defaults are `trueLabel("Yes")` / `falseLabel("No")`; blank labels fall back to an icon-only circle. The pill stays content-sized in the cell (not full width). Row action menus (`⋮`) use a fixed overlay so they float above a short table instead of clipping inside `.ff-table-wrap`. `align(Align.END)` / `Align.CENTER` sets both the cell and the `<th>` via `data-ff-align`. The Actions header is right-aligned the same way.

`relationship("project", "name")` on a foreign-key column (for example `project_id`) shows the related record’s title attribute instead of the raw id, labels the heading from the relation name (**Project**), and tells Cadence tables to `with("project")` so the list is not N+1. Generated resources emit this for FK columns.

If IntelliJ does not offer `date()` / `dateTime()` (or other new Firefly APIs) in completion, the IDE is almost always resolving an older published JAR instead of your composite/`kona.home` checkout. Refresh the Gradle project (**Reload All Gradle Projects**), confirm the module dependency points at the included build (not only Maven Local / Central), then **Invalidate Caches** if the index still looks stale. `./gradlew :kona-firefly-tables:compileKotlin` (or a full `./gradlew classes`) after pulling framework changes keeps class files current for the IDE.

Search is instant: typing in the toolbar search field debounces (~280ms) and soft-navigates the table without pressing Enter. Soft-nav restores focus and the caret in the search box so typing is not interrupted. The control is a single bordered field with the icon inside.

Each column renders `x-data="ffColumn('name', true)"` and `@entangle(name)`.

`./grind make:firefly-column Name` writes a column class and a Crema view under `app/firefly/columns`. `--lang=java` writes Java. The view uses `ffColumn`, `@entangle`, and `$wire.$call`. Reference the class from the table. `discover` does not scan `columns/`.

## Add a filter

`filters(...)` lists the filters a table offers. The toolbar gets a funnel button, active filters show as removable chips above the rows, and the state is kept in the URL.

```kotlin
        TernaryFilter.make("in_stock"),
        TrashedFilter.make(),

```

</TabItem>

## Page, select, group, and lay out the rows

`paginated(true)` is the default. `page(1)` and `perPage(10)` choose the window. `pageOptions(10, 25)` lists the page sizes in the HTML. Page numbers start at 1.

Row checkboxes and the actions that use them are covered under [Bulk actions](#bulk-actions) below.

`groups(TableGroup.make("status"))` and `groupedBy("status")` split the page into groups. `label("Status")` or `label { cell -> ... }` sets the group heading.

`reorderable("score")` then `move(key, index)` writes the new order into that attribute.

`layout(TableLayout.ROWS)` is the default table. `TableLayout.STACK` and `TableLayout.GRID` render the same records as cards (stack is a single column of cards; grid fills a responsive card grid). `poll("10s")` or `poll("500ms")` adds `wire:poll` on the root.

## Bulk actions

A bulk action runs once on every row the user has checked. Add one with `bulkActions(...)` and the table puts a checkbox at the start of each row, a "select this page" checkbox in the header, and the action buttons above the table.

### Your first bulk action

`DeleteBulkAction` is ready to use. It asks for confirmation, deletes each checked row through the table's record store, and reports how many rows went away.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
Table.cadence(Note::class.java)
    .columns(TextColumn.make("title"))
    .bulkActions(
        BulkActionGroup.make(DeleteBulkAction.make()),
    )
```

</TabItem>
<TabItem label="Java">

```java
Table.cadence(Note.class)
    .columns(TextColumn.make("title"))
    .bulkActions(
        BulkActionGroup.make(DeleteBulkAction.make())
    );
```

</TabItem>
</Tabs>

Here is what the user sees:

1. Each row has a checkbox. The header checkbox checks every row on the page. When only some rows are checked, the header checkbox shows a dash (the indeterminate state).
2. The **Bulk actions** button above the table is disabled until a row is checked. Once rows are checked, a small badge on the button shows the count.
3. A bar under the toolbar reads "3 records selected". It also has **Select all 42**, which selects every row that matches the current search and filters, even on other pages, and **Deselect all**.
4. Choosing **Delete selected** opens a confirmation dialog. **Delete** posts the selection, the rows are removed, and a toast says **Deleted**.

Checked rows stay checked while the user moves between pages and changes sort. A search or filter change clears them, because the old selection may no longer match. Call `deselectAllRecordsWhenFiltered(false)` to keep them.

Resource list and manage pages get this **Bulk actions → Delete selected** menu on their own. If your resource's `table()` calls `bulkActions(...)`, your list replaces the default. Call `bulkActions()` with no arguments to turn bulk actions off for that resource.

### Write your own action

`BulkAction.make(name)` takes a name that is unique within the table. `action { context -> ... }` runs when the user confirms.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
BulkAction.make("archive")
    .label("Archive")
    .icon("check")
    .color("warning")
    .requiresConfirmation()
    .successNotificationTitle("Archived")
    .deselectRecordsAfterCompletion()
    .action { context ->
        for (record in context.records()) {
            archiveNote(record["id"])
        }
    }
```

</TabItem>
<TabItem label="Java">

```java
BulkAction.make("archive")
    .label("Archive")
    .icon("check")
    .color("warning")
    .requiresConfirmation()
    .successNotificationTitle("Archived")
    .deselectRecordsAfterCompletion()
    .action(context -> {
        for (Map<String, Object> record : context.records()) {
            archiveNote(record.get("id"));
        }
    });
```

</TabItem>
</Tabs>

The `context` gives you the selection:

| Call | Returns |
|---|---|
| `keys()` | The checked record keys, as strings |
| `records()` | Each checked record's attributes as a map. Rows that were deleted after the page loaded are left out |
| `eachChunk { chunk -> ... }` | The records in chunks of `chunkSelectedRecords(n)` (all at once when no size is set) |
| `get("field")` / `data()` | Values from the action's dialog form (see below) |
| `delete(key)` / `deleteAll()` | Deletes through the table's record store. `deleteAll()` counts rows that are already gone as failures |
| `reportBulkProcessingFailure(key, message)` | Marks one record as failed and adds a message to the toast |

When an action does not need the records themselves, call `fetchSelectedRecords(false)` so `records()` stays empty and only `keys()` is filled. This saves a lookup per row.

The default label comes from the name: `archiveAll` becomes "Archive all". `label { cell -> ... }`, `hidden()`, `visible { cell -> ... }`, and `disabled()` work the same way as on `TableButton`. A disabled action stays greyed out even when rows are checked. `tooltip("...")` adds a hover title. `button()` (the default) and `link()` choose the trigger style. `url(...)` posts the selection to another path, which you need when the table lives somewhere other than the page that renders it.

### Ask for input first

`schema(...)` puts fields in the action's dialog. Their values come back through `context.get(name)`.

```kotlin
BulkAction.make("reassign")
    .modalHeading("Move to another owner")
    .modalDescription("The checked notes move to this person.")
    .modalSubmitActionLabel("Move")
    .schema(TextInput.make("owner"))
    .action { context -> moveNotes(context.keys(), context.get("owner")) }
```

`requiresConfirmation()` without a schema shows "Are you sure you would like to do this?" with **Confirm** and **Cancel**. `modalCancelActionLabel("Keep")` renames the cancel button. An action with neither confirmation nor a schema runs as soon as it is clicked.

### Group actions in a dropdown

`BulkActionGroup.make(...)` puts actions in one dropdown. Its trigger is labelled "Bulk actions" by default; `label("Manage")`, `icon(...)`, and `color(...)` change it. Actions you pass straight to `bulkActions(...)` render as their own buttons next to the dropdown:

```kotlin
table.bulkActions(
    BulkActionGroup.make(DeleteBulkAction.make(), archive),
    BulkAction.make("export").label("Export"),
)
```

`groupedBulkActions(a, b)` is a shortcut for `bulkActions(BulkActionGroup.make(a, b))`.

### Check each record

`authorizeIndividualRecords { cell -> ... }` runs before the action for each checked record. Records that fail are skipped and counted, and the toast says "2 selected records were not authorized." Pass a second closure to write your own message: `authorizeIndividualRecords({ cell -> ... }) { counts -> "Skipped ${counts.failureCount}" }`.

When some records fail (because of authorization, `reportBulkProcessingFailure`, or a delete of a row that is already gone), the toast is a warning that shows the messages. When nothing succeeds, it is a danger toast. Set the titles with `successNotificationTitle("...")` and `failureNotificationTitle { counts -> "${counts.successCount} of ${counts.totalCount} archived" }`.

### Control what can be selected

| Call | Effect |
|---|---|
| `selectable(true)` | Show checkboxes without any bulk action. `selected()` returns the keys selected on the server |
| `checkIfRecordIsSelectableUsing { cell -> ... }` | Rows that return `false` get a disabled checkbox and are never sent to an action |
| `maxSelectableRecords(10)` | Stops the user at 10 checked rows. The server rejects larger posts too |
| `selectCurrentPageOnly()` | Hides **Select all N**, so a selection never reaches past the visible page |
| `selectGroupsOnly()` | With `groups(...)`, every group heading gets its own checkbox and a selection stays inside one group |
| `checkboxPosition(RecordCheckboxPosition.AFTER_CELLS)` | Moves the checkbox column to the end of the row |
| `deselectAllRecordsWhenFiltered(false)` | Keeps the selection across search and filter changes |

Card layouts (`TableLayout.STACK`, `TableLayout.GRID`, `contentGrid(...)`, and stacked mobile rows) show the same checkbox in the corner of each card, plus a "Select all on this page" checkbox above the cards.

### How the post works

The chrome script keeps the selection in the browser tab and posts a small form to the page's own URL with `_bulk_action`, `_bulk_keys` (comma separated), `_bulk_all=1` for "select all", the CSRF token, and any dialog fields. The panel finds the table on that page, calls `table.runBulkAction(...)`, flashes the toast, and redirects back with the same query string, so the user stays on the same page, sort, and filters.

You can run an action yourself, for a test or a console command:

```kotlin
val result = table.runBulkAction("archive", listOf("1", "2"))
result.successCount       // 2
result.notificationTitle() // "Archived"
```

From Java, `table.runBulkAction("archive", List.of("1", "2"))` works the same way. Pass `data` and `allMatching` as the third and fourth arguments when you need them.

## Mobile cards, content grid, and Split / Stack

On small screens, ROWS become **cards** by default: each cell shows its column label above the value, and a **Sort** dropdown appears when any visible column is sortable. That is `stackedOnMobile(true)` (the default). Pass `stackedOnMobile(false)` to keep a horizontal scroll table on phones.

`contentGrid(mapOf("md" to 2, "xl" to 3))` turns the list into a card grid: one column on the smallest size, then the counts you set from each breakpoint upward (`sm` … `2xl`, plus `default`). It sets `TableLayout.GRID` and paints the same card chrome as stack/grid layouts (selection checkbox, field labels, row actions).

Compose a row with layout components under `org.konaframework.firefly.tables.layout`:

- `Split.make(...)` — children sit in a row; `from("md")` stacks them below that breakpoint.
- `Stack.make(...)` — vertical stack; `space(1|2|3)`, `alignment(Align.END)`, `visibleFrom("md")`.
- `Grid.make(2).schema(...)` — equal CSS-grid tracks inside one record (from `lg` up).
- `Column.grow(false)` — keep intrinsic width inside a Split instead of sharing leftover space.

Pass Split / Stack / Grid into `columns(...)` mixed with ordinary columns. Search, sort, and filters still use the flattened leaf columns.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
table
    .columns(
        Split.make(
            TextColumn.make("name").label("Name").searchable().sortable().grow(false),
            Stack.make(
                TextColumn.make("phone").label("Phone"),
                TextColumn.make("email").label("Email"),
            ).space(1).visibleFrom("md"),
        ).from("md"),
    )
    .stackedOnMobile() // default true — cards on small screens
    .contentGrid(mapOf("md" to 2, "xl" to 3)) // optional record grid
```

</TabItem>
<TabItem label="Java">

```java
table.columns(
    Split.make(
        TextColumn.make("name").label("Name").searchable().sortable().grow(false),
        Stack.make(
            TextColumn.make("phone").label("Phone"),
            TextColumn.make("email").label("Email")
        ).space(1).visibleFrom("md")
    ).from("md")
);
table.stackedOnMobile(true);
table.contentGrid(Map.of("md", 2, "xl", 3));
```

</TabItem>
</Tabs>

## Click a row

Rows are clickable by default when a **View** or **Edit** row button exists (Filament-shaped). Click prefers **View**, then **Edit**. The click opens that button’s dialog or follows its URL. Clicks on the ⋯ menu, action buttons, checkboxes, and links inside cells do not fire the row click.

Override the target with `recordUrl` or `recordAction`. Turn row clicks off with `recordClickable(false)`.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
// Default: View if present, else Edit — no call needed when those row buttons exist.
table.recordUrl { cell -> "view?id=${cell.get("key")}" }
table.recordAction("view")
table.recordClickable(false)
```

</TabItem>
<TabItem label="Java">

```java
table.recordUrl(cell -> "view?id=" + cell.get("key"));
table.recordAction("view");
table.recordClickable(false);
```

</TabItem>
</Tabs>

## Put a button on the header or the row

A button renders through `Dialog` and can include a schema. `label("Export")` and `label { cell -> "Edit ${cell.get("name")}" }` set the text. `modal()`, `slideOver()`, and `fullscreen()` choose the dialog. `schema(Text.make("Go"))` is the dialog body. `url("https://example.test")` renders a link. `requiresSelection(true)` disables the button while no row is selected.

When a table has **two or more** row buttons, Firefly groups them under a ⋯ (kebab) menu by default so the actions column stays narrow. Call `groupRowActions(false)` to show each action as its own button. Resource manage/list pages use the grouped menu for View / Edit / Delete.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
table.headerButtons(
    TableButton.make("export").label("Export").requiresSelection(true).modal().schema(Text.make("Go")),
)
table.rowButtons(
    TableButton.make("edit").label { cell -> "Edit ${cell.get("name")}" }.slideOver(),
)
```

</TabItem>
<TabItem label="Java">

```java
table.headerButtons(
    TableButton.make("export").label("Export").modal().schema(Text.make("Go"))
);
```

</TabItem>
</Tabs>

You see **Export** above the table. With `requiresSelection(true)` it stays disabled until a row is checked, and it turns back off when the selection is cleared. The button markup uses `ffAction` and `$wire.$call`. To run something on each checked row, use a [bulk action](#bulk-actions) instead.

`configureUsing` on `Table`, `TableButton`, `Column`, `TextColumn`, `Filter`, and `SelectFilter` runs for every later `make()`. Pass `null` to clear it.
