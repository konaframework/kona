Put fields on a schema when the screen needs a name, a status, or a due date. Fill the schema, then `render()` returns the HTML. Wire and Alpine keep the value in sync after the page loads.

Fields live in `org.konaframework.firefly.forms` (`kona-firefly-forms`). Each field is a schema component, so it sits in the same tree as a section or a tab and uses the same live modifiers (`live`, `liveOnBlur`, `liveDebounce`, `hidden`, `visible`, `dehydrated`, `afterStateUpdated`). Place the schema on a page, or render it into a view you already have.

On the hello samples the Desk page and the notes form both use a text field, a status combobox, and a due date picker. The files are `app/firefly/pages/Desk` and `app/firefly/resources/NoteResource`.

## Add a text field

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val name = TextInput.make("name")
    .label("Name")
    .required()
    .live()
val schema = Schema.make().components(name)
schema.fill(mapOf("name" to "Ada"))
val html = schema.render()
```

</TabItem>
<TabItem label="Java">

```java
TextInput name = TextInput.make("name").label("Name").required();
name.live();
Schema schema = Schema.make().components(name);
schema.fill(Map.of("name", "Ada"));
String html = schema.render();
```

</TabItem>
</Tabs>

`make("name")` sets the state key. `render()` wraps the control in the field chrome: label, hint, prefix, suffix, helper text, and a span with `x-data="ffField"` plus `@entangle(name)`. You see a Name field filled with Ada. Live fields also emit `wire:model` on the schema wrapper. Call `registerFirefly` and `registerFireflyForms` on the Alpine instance the page already started. Leave `Alpine.start()` to that instance. Until that script runs, `@entangle(...)` can still show as raw text in the page.

`FormAssets.script()` and `FormAssets.stylesheet()` are the field script and the field CSS. Prose from the rich text and markdown editors uses the caramel accent `#DF8723` through `--ff-primary`.

Most chainable setters take a fixed value or a closure. The closure receives `Get`.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
name.label("Name")
name.label { get -> if (get.get("/kind") == "org") "Organization" else "Name" }
name.placeholder { "Ada Lovelace" }
name.helperText("Shown on the invoice")
```

</TabItem>
<TabItem label="Java">

```java
name.label("Name");
name.label(get -> "Organization");
name.helperText("Shown on the invoice");
```

</TabItem>
</Tabs>

The last call wins. A string replaces a closure, and a closure replaces a string. When you never call `label`, Firefly humanizes the field name (`first_name` → “First Name”) so the form still shows a label.

## Helpers on every field

These methods are on the field base. Every concrete field has them.

| Method | What you get |
|--------|----------------|
| `label`, `heading`, `description` | Text, or a closure that returns text |
| `helperText`, `hint`, `hintColor`, `hintIcon` | Text under or beside the control |
| `placeholder` | Input placeholder |
| `prefix`, `suffix`, `prefixIcon`, `suffixIcon` | Text or icon inside the control |
| `inlinePrefix`, `aboveContent`, `belowContent` | Extra chrome |
| `required()`, `required(false)`, `required { get -> ... }` | Adds the `required` rule. A required field is not nullable |
| `markAsRequired` | Shows the asterisk without the rule |
| `nullable()` | Adds `nullable` and clears `required` |
| `readOnly`, `autofocus`, `autocomplete`, `autocapitalize`, `inputMode` | Input attributes |
| `distinct` | Repeater items reject a repeated value |
| `rule`, `rules` | Extra validation rule strings |
| `validationAttribute` | Rewrites “The name field” to your label |
| `validationMessages` | Message per rule name |
| `saved(false)` | Same as `dehydrated(false)` |
| `formatStateUsing`, `dehydrateStateUsing` | Change the value written by `dehydrate()` |
| `extraAttributes` | HTML attributes merged onto the component root. A map or a closure. Invalid names are skipped |
| `extraInputAttributes` | HTML attributes on the input, textarea, select, or editor control. A map or a closure. `type`, `name`, and `value` stay owned by the field |

`hidden`, `visible`, `live`, `liveOnBlur`, `liveDebounce`, and `afterStateUpdated` stay on the schema component. Call them on the field. They return the component base, so in Java finish the field chain before calling `live()`.

`prefixAction`, `suffixAction`, and `hintAction` take an `Action`. They are under [Actions on a field](#actions-on-a-field).

## Text, tags, color, and maps

`TextInput` is a single-line control. `email()`, `url()`, `numeric()`, `integer()`, `password()`, `tel()`, and `type("search")` set the input type and the matching validation rule. `telRegex` replaces the default telephone pattern. Call `telRegex` before `tel()` when you want your own pattern.

`revealable(true)` adds a show button on passwords. `copyable(true)` adds a copy button. `mask`, `step`, `minValue`, `maxValue`, `minLength`, `maxLength`, `length`, `regex`, `notRegex`, and `datalist` configure the control. `stripCharacters("-")` or `stripCharacters { value -> value.trim() }` changes the stored text before it is rendered.

`unique("users", "email")` and `exists("users", "email")` add those rules. Without a database checker they fail closed.

`Textarea.make("body")` takes `rows`, `cols`, `autosize`, `minLength`, `maxLength`, and the same `required()` chain as other fields. `Hidden.make("token")` renders a hidden input and no label.

`TagsInput.make("tags")` splits a string on the separator (`,` by default) and renders one chip per tag. `suggestions`, `splitKeys`, `reorderable`, and `color` are optional. `tags(raw)` returns the list.

`ColorPicker.make("ink")` stores a color. `hex()`, `rgb()`, and `hsl()` pick the format and the validation pattern.

`Slider.make("volume")` defaults to 0–100 with step 1. `minValue`, `maxValue`, `step`, `decimalPlaces`, and `tooltips` adjust it. Values are clamped and rounded.

`KeyValue.make("meta")` edits a map of strings. `keyLabel`, `valueLabel`, `keyPlaceholder`, `valuePlaceholder`, and `addActionLabel` accept a string or a closure. `addable`, `deletable`, `editableKeys`, `editableValues`, and `reorderable` toggle the controls. `pairs(raw)` reads the map.

`Placeholder.make("note").content("Thanks")` renders HTML and does not dehydrate. `content { get -> "Hello" }` is the closure form. `saved(true)` turns dehydration back on.

`ViewField.make("bio").viewName("bios.card")` renders a Crema view when the schema has an engine. The view receives the state path. Without an engine the field emits `data-ff-view`.

## Choices

`Select` renders a combobox (`ff-combobox`). Call `.native()` when you want a native `<select>`. In Java the method is `useNative(true)`, because `native` is a keyword. `.native(false)` and `useNative(false)` keep the combobox. The status field on the Desk page is the combobox: Open and Done.

<TabItem label="Kotlin">

```kotlin

    .options(mapOf("open" to "Open", "done" to "Done"))
    .searchable(true)
    .placeholder("Pick one")
```

</TabItem>
<TabItem label="Java">

```java

    .options(Map.of("open", "Open", "done", "Done"))
```

</Tabs>

</TabItem>

`options { get -> mapOf("a" to "A") }` loads options from a closure. `optionsFrom(records, "title", "id")` reads a list of maps. `boolean()` uses Yes and No. `multiple(true)`, `preload`, `optionsLimit`, `maxItems`, `searchDebounce`, `position`, and the loading, searching, empty, and search-prompt strings configure the combobox. `getOptionLabelUsing` and `getSearchResultsUsing` replace the label and the search. `disableOptionWhen` disables one option. `allowHtml(true)` keeps HTML in a native option label.

`descriptions` adds a line under each option. A static option list adds an `in:` rule when the field is not multiple and the values contain neither a comma nor a pipe.

`extraAttributes` lands on the field root. `extraInputAttributes` lands on the select control. `type`, `name`, and `value` stay owned by the field.

## Load options from a relationship

`relationship(name, titleAttribute)` reads the related records on the schema’s record. `name` is the relationship. `titleAttribute` is the label field. Pass a closure as `modifyQueryUsing` when you need to narrow the query. `getOptionLabelFromRecordUsing` replaces the label with a value taken from each record.

Put the owner model on the schema with `record(...)` before the options are read. When the related model is a Cadence model, the closure receives a `ModelBuilder`, so `where`, `whereHas`, `join`, `with`, and scopes run on that builder. When the related model is not a Cadence model, the closure receives that model's own query. `.native()` still opts into `<select>`. The default remains the combobox.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
Select.make("authorId")
    .relationship("author", "name") { query ->
        val authors = query as ModelBuilder<Author>
        authors.where("active", true).whereHas("posts") { posts ->
            posts.where("title", "Yes")
        }
    }
    .getOptionLabelFromRecordUsing { record ->
        "Dr " + (record as Author).getAttribute("name")
    }
    .extraAttributes(mapOf("data-field" to "author"))
    .extraInputAttributes(mapOf("data-ff-extra" to "1"))
```

</TabItem>
<TabItem label="Java">

```java
Select.make("authorId")
    .relationship("author", "name", query -> { })
    .getOptionLabelFromRecordUsing(record -> "Ada")
    .extraAttributes(Map.of("data-field", "author"))
    .extraInputAttributes(Map.of("data-ff-extra", "1"));
```

</TabItem>
</Tabs>

`createOptionForm` and `createOptionUsing` open a support `Dialog` and create an option from the submitted map. An action wrapper around that dialog is `createOptionAction`.

`Checkbox`, `Toggle`, `Radio`, `CheckboxList`, and `ToggleButtons` are the other choice fields. `accepted()` on a checkbox adds the `accepted` rule. `Toggle` is a Shamar-style switch (track + thumb); it defaults to `inline()` with the label beside the control, and takes on/off colors and icons. `Radio.boolean()` and `ToggleButtons.boolean()` use Yes and No. `CheckboxList.relationship(name, titleAttribute)` loads options the same way a select does. `CheckboxList.optionColumns` sets the grid (`columns` on the component base is separate). `bulkToggleable` adds a select-all button.

## Dates and times

`DatePicker`, `TimePicker`, `DateTimePicker`, and `DateRangePicker` are separate field types. The default control is a flatpickr-inspired popup (month grid, time selects, Today / Clear) driven by Firefly chrome — no Alpine required. The panel stays closed until the field is clicked. There is no third-party date library. Use `.native()` (Java: `useNative(true)`) for `type="date"`, `type="time"`, or `type="datetime-local"`.

`DateRangePicker` stores `"start to end"` (same date format as `DatePicker`) and highlights the range in the calendar.

Server values use `java.time`. A date-only value stays in the application zone (`FieldClock.appZone`). A date-time uses the field’s `timezone`. `LocalDate` and `LocalDateTime` are written with the storage format (`Y-m-d`, `H:i`, or `Y-m-d H:i`). `seconds(true)` appends seconds. `displayFormat` is what the text input shows.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val day = DatePicker.make("day")
    .minDate("2024-03-01")
    .maxDate { "2024-03-31" }
    .weekStartsOnMonday()
    .disabledDates(listOf("2024-03-10"))
day.normalize(LocalDate.of(2024, 3, 10)) // "2024-03-10"
```

</TabItem>
<TabItem label="Java">

```java

day.normalize(LocalDate.of(2024, 3, 10));
```

</TabItem>
</Tabs>

`firstDayOfWeek` is 0 (Sunday) or 1 (Monday). `hoursStep`, `minutesStep`, and `secondsStep` must stay inside their ranges. `defaultFocusedDate` opens the grid on that day. `FieldClock.pinToday` fixes “today” in tests.

Required labels put a red `*` inline next to the label text. `Textarea.required()` matches other text fields. `defaultValue` / `defaultUsing` seed create forms when `Schema.render()` runs (missing paths only). `Toggle` defaults to an inline Shamar-style switch (track + thumb beside the label).

## Rich text, markdown, and code

`RichEditor` emits a TipTap surface: a grouped sticky toolbar, a bubble menu, and a `.ff-prose` body. Link, image, and custom blocks open the support `Dialog`. `json()` stores JSON. The default is HTML, passed through a sanitizer that strips scripts, styles, iframes, `on*` attributes, and `javascript:` URLs. `disableToolbarButtons`, `mergeTags`, `mentions`, and `customBlocks` configure the toolbar. File attachments name a disk and directory. `editBlockAction` renders an `Action` for a custom block. The block’s edit control still opens the support `Dialog`.

`MarkdownEditor` is a Write | Preview pair. Write uses CodeMirror with the markdown language. Preview renders a GitHub-flavored subset (fences, tables, lists, task lists, headings, links, images) into the same `.ff-prose` class, then sanitizes it.

`CodeEditor` uses CodeMirror 6 and the Shiki language set. `language("kotlin")` selects the grammar. `CodeEditor.languages()` lists the ids shipped with the module. `wrap(true)` wraps long lines. This editor is not a rich-text surface.

The page script looks for `FilePond` and for a `FireflyEditors` object (TipTap, CodeMirror, Shiki, markdown-it). When those scripts are on the page, the field mounts them. The upload path still posts if FilePond is absent.

## Uploads

`FileUpload` posts to `POST /_firefly/uploads` through the filesystem. Register the route once:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
FireflyUploads.register(router, UploadDisks { name -> filesystems.disk(name) })
```

</TabItem>
<TabItem label="Java">

```java
FireflyUploads.register(router, name -> filesystems.disk(name));
```

</TabItem>
</Tabs>

The handler writes `firefly-temporary/{id}.ext` plus a sibling `.ffmeta` file with the original name, then returns JSON `{ "path", "name" }`. `commit(schema, disks)` copies the temporary file into `directory()` (or moves it when `moveFiles(true)` is set), applies `preserveFilenames` or `getUploadedFileNameForStorageUsing`, and stores the final path on the field. `storeFileNamesIn` writes the original names to another state path. `storeFiles(false)` leaves the temporary path in place.

`image()` accepts image types. `avatar()` also turns on the image editor, a compact layout, and a 1:1 crop when you have not set aspect ratios. The editor is FilePond’s image editor. `maxSize` and `minSize` are kilobytes. `minFiles` and `maxFiles` count files. `acceptedFileTypes` takes `image/*`, a mime type, `.png`, or a bare extension.

`preventFilePathTampering(true)` rejects `..`, absolute paths, `.ffmeta` files, and paths outside the directory or `firefly-temporary/`. Mount `VerifyCsrfToken` from `kona-session` on `POST /_firefly/uploads`. The field script sends `X-CSRF-TOKEN` from a `csrf-token` meta tag and `_token`. Pass a checker as the third argument to `register` when you want the route itself to reject a bad token.

`browse` and `browseAction` list files already stored on the disk. They are under [Browsing stored files](#browsing-stored-files).

## Repeater and builder

`Repeater.make("members").simple(TextInput.make("name").required())` edits a list of maps. `schema(...)` replaces the item blueprint. `addItem`, `removeItem`, `cloneItem`, and `moveItem` update the schema state and run `afterStateUpdated`. `orderColumn("sort")` writes 1-based positions. `itemLabel` is a string or a function of the index and `Get`. `grid`, `minItems`, `maxItems`, `defaultItems`, `collapsible`, and `collapsed` change the layout. `relationship("members")` stores the relation name on the repeater. It does not load related records by itself.

`Builder.make("blocks").blocks(BuilderBlock("hero", "Hero", listOf(TextInput.make("title"))))` edits a list of typed blocks. `addBlock(schema, "hero")` appends one. `blockNumbers(true)` prefixes the label with the index. `addBetweenAction` renders an action between blocks.

The walk skips layout nodes, hidden fields, fields with `dehydrated(false)`, and fields with an empty path. Rules go through the HTTP validator. A custom `validationAttribute` rewrites the field name in the message. `extraErrors` from a file upload or a repeater are merged in. `unique` and `exists` fail closed until a checker is configured.

## Generate a field

From the application directory:

```bash
./grind make:firefly-field Price
./grind make:firefly-field Note --lang=java
```

The command writes a class that extends the field base and a Crema view with `x-data="ffField"` and `@entangle`. Kotlin is the default. `--lang=java` writes a Java subclass. The files land under `fields/`. Reference the class from a page or a resource. `discover` does not scan that folder.

## Browse stored files

`FileUpload.browseAction` renders an action beside the upload. `browse(disk)` lists files already stored under `directory()` and skips `*.ffmeta` paths. `chooseBrowsed` writes the chosen path into the same field state. Rename and delete of stored folders are not methods on this field.
