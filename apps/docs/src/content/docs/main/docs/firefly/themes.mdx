Change the colors, the type, and any extra CSS inside the frame. Implement `FireflyTheme`, then pass an instance to `theme(...)` on the panel you mount.

The theme supplies an id, a `ThemeTokens` object, optional HTML for one chrome slot, and optional extra CSS. `Stylesheet.render` turns the tokens into CSS custom properties on `.ff-panel`. Rules in the shipped stylesheet only match inside `.ff-panel`, so a page that never renders a panel leaves Firefly’s buttons, sidebar, and dialogs alone.

The hello samples use the shipped theme. You see it on `/admin/desk`.

<FireflyShot file="themed-panel.png" description="The hello-kotlin panel at http://127.0.0.1:4017/admin/desk wearing the shipped theme on the sidebar and the page." />

## Implement FireflyTheme

| Method | Default | What you return |
|--------|---------|-----------------|
| `id(): String` | required | Short name used in error messages |
| `tokens(): ThemeTokens` | required | Color, type, and size tokens |
| `partial(slot: String): String?` | `null` | Replacement HTML for `sidebar`, `topbar`, `body`, or `footer`. `null` keeps the built-in partial |
| `extraCss(): String` | `""` | Extra rules. Firefly wraps a non-empty value in `.ff-panel { ... }` |

Pass an instance to `Panel.theme(...)`. `./grind make:firefly-theme Harbor` writes the class under `app/firefly/themes/`.

```kotlin
class HarborTheme : FireflyTheme {
    override fun id(): String = "harbor"

    override fun tokens(): ThemeTokens = ThemeTokens(
        primary = "#DF8723",
        accent = "#74453F",
        surface = "#FAF6F0",
        heading = "#2A1C10",
        font = "ui-sans-serif, system-ui, sans-serif",
        radius = "0.75rem",
        sidebarWidth = "18rem",
        topbarHeight = "4rem",
        bodyBackground = "#FAF6F0",
        darkPrimary = "#C9A57B",
        darkSurface = "#1A120C",
        darkHeading = "#E8D4B8",
    )

    override fun extraCss(): String =
        ".ff-sidebar { box-shadow: inset -1px 0 0 var(--ff-accent); }"
}
```

```java
public final class HarborTheme implements FireflyTheme {
    @Override public String id() { return "harbor"; }

    @Override public ThemeTokens tokens() {
        return new ThemeTokens(
            "#DF8723", "#74453F", "#FAF6F0", "#2A1C10",
            "ui-sans-serif, system-ui, sans-serif",
            "0.75rem", "18rem", "4rem", "#FAF6F0",
            "#C9A57B", "#1A120C", "#E8D4B8"
        );
    }

    @Override public String extraCss() {
        return ".ff-sidebar { box-shadow: inset -1px 0 0 var(--ff-accent); }";
    }
}
```

Then call `theme(HarborTheme())` on the panel. The sidebar picks up the inset shadow, and the primary color is `#DF8723`.

`ThemeTokens` is a class with those twelve constructor parameters, in that order. Each field is a public `val` (a Java getter). Values are inserted into CSS as you provide them. Firefly does not validate that a token is a legal CSS color.

## Use the shipped KonaTheme

`KonaTheme` is the built-in theme. `id()` returns `kona`. `Panel` uses it when you never call `theme(...)`. The hello samples leave it in place.

| Token | Light value | Dark token | Dark value |
|-------|-------------|------------|------------|
| primary | `#DF8723` | darkPrimary | `#C9A57B` |
| accent | `#74453F` | — | accent is unchanged in the dark block |
| surface | `#FAF6F0` | darkSurface | `#1A120C` |
| heading | `#2A1C10` | darkHeading | `#E8D4B8` |
| font | `ui-sans-serif, system-ui, sans-serif` | — | |
| radius | `0.5rem` | — | |
| sidebarWidth | `16rem` | — | |
| topbarHeight | `4rem` | — | |
| bodyBackground | `#FAF6F0` | written as `--ff-body` | dark block sets `--ff-body` from `darkSurface` |

## Read Stylesheet.render

`Stylesheet.render(theme)` returns a CSS string:

1. A `.ff-panel { ... }` block of custom properties.
2. A dark block that overrides primary, surface, heading, and body. It targets both the self-class (`.ff-panel.ff-dark`) and an ancestor root (`.ff-dark .ff-panel`), so toggling `ff-dark` on `<html>` is enough.
3. The shipped component stylesheet.
4. When `extraCss()` is non-blank after `trim()`, a trailing `.ff-panel { <extra> }` block.

Custom properties:

| Property | Token |
|----------|--------|
| `--ff-primary` | `primary` / `darkPrimary` |
| `--ff-accent` | `accent` |
| `--ff-surface` | `surface` / `darkSurface` |
| `--ff-shell` | Tracks `--ff-surface` so white `--ff-card` table wraps and sections contrast against the latte shell |
| `--ff-heading` | `heading` / `darkHeading` |
| `--ff-font` | `font` |
| `--ff-radius` | `radius` |
| `--ff-sidebar-width` | `sidebarWidth` |
| `--ff-topbar-height` | `topbarHeight` |
| `--ff-body` | `bodyBackground` / `darkSurface` in the dark block |

`DefaultLayout` emits `<div class="ff-panel">` without `ff-dark`. The built-in top-bar theme toggle adds `ff-dark` to the document root and remembers the choice in `localStorage['ff-theme']` (`light` / `dark` / `system`), applied before first paint so a reload never flashes. Dark tokens also apply when the panel element itself carries `ff-dark`, which a custom `PanelLayout` can set. See [Panel chrome](/docs/firefly/chrome/).

## Keep extra CSS inside the panel

After trim, if `extraCss()` is non-empty and any line matches `body` followed by `{` at the start of the line (leading whitespace allowed), `Stylesheet.render` throws `FireflyException`:

```text
Theme [<id>] CSS must stay under .ff-panel
```

This is rejected:

```css
body { background: red; }
```

This is accepted, because the selector is not a bare `body` rule:

```css
.ff-sidebar { background: var(--ff-surface); }
```

Empty or whitespace-only `extraCss()` is omitted. The check does not run.

## Shipped component classes

The checked-in stylesheet (`firefly.css`) is the scoped result of the Tailwind CSS v4 authoring file `modules/firefly-support/tailwind/input.css`. Authenticated chrome rules are descendants of `.ff-panel`. Guest auth screens use `.ff-auth` (centered shell, no sidebar). There is no preflight on the host welcome page.

| Selector | Effect |
|----------|--------|
| `.ff-panel .ff-btn` | Primary filled button: radius from `--ff-radius`, weight 600 |
| `.ff-panel .ff-sidebar` | Full-height shell column, width `--ff-sidebar-width`, brand strip + scrollable nav |
| `.ff-panel .ff-sidebar-brand` | Logo mark + brand label above the side nav |
| `.ff-panel .ff-sidebar-foot` / `.ff-panel .ff-footer` | Shared shell foot band (padding, type, soft border, fixed `--ff-footer-height`); not a white card |
| `.ff-panel .ff-nav-item` | Pill links; active item uses `--ff-active` with a primary inset bar |
| `.ff-panel .ff-topbar` | Card row with primary top edge, height `--ff-topbar-height` |
| `.ff-panel .ff-body` | Shell background, scrollable page canvas |
| `.ff-panel .ff-table-wrap` | Card around tables, toolbar, and row hover tint |
| `.ff-panel .ff-dialog` | Fixed, inset 0, z-index 50 |
| `.ff-panel .ff-dialog-modal .ff-dialog-window` | Top margin `4rem`, elevated card |

`DefaultLayout` and `AuthLayout` put this CSS in a `<style>` element in the document `<head>`, with Inter / DM Sans linked from Google Fonts. Theme token variables apply to both `.ff-panel` and `.ff-auth`.
