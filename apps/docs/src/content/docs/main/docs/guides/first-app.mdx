## Prerequisites

- JDK 21+
- Global `kona` on your PATH ([Installation](../installation/) — `curl …/scripts/install.sh | bash`)

## Create the project

```bash
kona new hello-kona                 # still asks language, kit, CSS, database, …
kona new hello-kona --no-interaction
cd hello-kona
```

Use `--lang=java` for a Java skeleton. The default kit is **`web`** (Crema welcome view). Other kits: `--kit=api`, `--kit=inertia`, `--kit=brew`. CSS: `--css=tailwind|bootstrap|custom`. Inertia adapters: `--frontend=vue|react|svelte`. Each flag skips only that step. `kona new` with no arguments is the interactive installer; it refuses to overwrite an existing directory.

You should see something like:

```text
 DONE  Application created successfully.
  Path         …/hello-kona
  Language     kotlin
  Stack        Crema · custom CSS
  Database     sqlite
  cd           hello-kona
  serve        ./grind serve
  migrate      ./grind migrate --seed
```

That `./grind` file is part of the scaffold. `kona grind …` is a global convenience that finds this file for you. Contributors browsing `samples/hello-*` inside the Kona git checkout will **not** find `./grind` there — see [Installation → Contributing to Kona](../installation/#contributing-to-kona-optional).

## What you got

Everything application-owned lives under `src/main` (plus project-root `storage/` and `.env`):

| Path | Role |
|------|------|
| `./grind` / `grind.bat` | **App-local** CLI (serve, make:controller, …) — written by `kona new` |
| `./gradlew` / `gradlew.bat` | Gradle wrapper — builds and runs the app |
| `.env` / `.env.example` | `APP_NAME`, `APP_KEY` (generated), `APP_DEBUG`, `HOST`, `PORT`, … |
| `src/main/kotlin/bootstrap/App` (or `…/java/…`) | Boots Kona, registers providers, starts HTTP |
| `src/main/…/bootstrap/Middleware` | Session + CSRF (`/api/*` excepted); trust proxies/hosts |
| `src/main/…/app/providers/` | Your service provider |
| `src/main/…/app/http/controllers/` | Controllers (`Welcome`, `Login`, `Dashboard`, `api/User`) |
| `src/main/…/app/models/User` | Cadence user (session auth + JSON API) |
| `src/main/…/database/migrations/` | `2000_01_01_000000_create_users_table` (class `CreateUsersTable`, listed in `META-INF/kona/migrations`) |
| `src/main/…/database/seeders/DatabaseSeeder` | Demo user for local login |
| `src/main/…/routes/WebRoutes` + `ApiRoutes` | Web (`/`, `/login`, `/dashboard`) and `/api` route tables |
| `src/main/resources/config/` | JSON config (`app`, `http`, `paths`, `session`) |
| `src/main/resources/views/` | Crema views (`welcome`, `login`, `dashboard` on web kits) |
| `public/` | HTTP document root (`branding/kona-logo.svg`, Vite `public/build`) |
| `storage/` | Writable runtime data (logs, framework cache) |
| `build.gradle.kts` | HTTP, grind, extract, redis, session, auth, queue, schedule, mail, crema |

`kona` itself is **not** copied into the project. Only `./grind` (plus the Gradle wrapper and app sources) is local.

### Path helpers

After boot, resolve directories with `Application` helpers or the `Paths` facade:

```kotlin
app.appPath("http", "controllers")
app.storagePath("logs")
app.configPath()
Paths.view("welcome")
Paths.publicDir()
```

Defaults follow the tree above; override with `paths.*` keys in `config/Paths` (registered via `.configs(...)`).

## Migrate, seed, and serve

Web kits ship a Cadence `User` model, a `2000_01_01_000000_create_users_table` migration (class `CreateUsersTable`), and a demo seeder:

```bash
./grind migrate --seed
./grind serve
```

(Or `./grind migrate` then `./grind db:seed` — the scaffold default is a **file** H2 database under `storage/database/`, so both processes share the same data.)

Open `http://127.0.0.1:4000/` (or the `HOST`/`PORT` from `.env`). Stop with Ctrl+C.

With `APP_DEBUG=true` (scaffold default), the terminal shows each request — method, path, status, and duration — as you hit the app. See [Logging](../../http/logging/#request-access-lines-local-serve).

Under the hood, `./grind serve` runs `./gradlew run` so the app compiles with its own dependencies. For tests you can use `./grind serve --in-process` after `./gradlew classes`.

The branded landing page is HTML from `welcome.crema.html` (via `WelcomeController` on `/`). Sign in at `/login` with the demo user **`demo@kona.test`** / **`password`**, then open `/dashboard`. `/api/health` returns JSON `{"status":"ok"}`. `/api/users` and `/api/users/{id}` list or show users (password fields are hidden).

The `--kit=api` skeleton includes the same `User` model and JSON API without Crema login views.

## Add a controller

```bash
./grind make:controller Post
```

Then register a route in `src/main/…/routes/` that uses it. Generators write under `src/main/kotlin|java/app/…`.

## Create another app later

Stay global — do not use grind for this:

```bash
cd ..
kona new shop --lang=java
cd shop
./grind serve
```
