title: Language & editor support
description: Highlight Crema templates and connect kona-lsp in your editor.
---

Kona ships **editor support** for Crema templates so you can edit `*.crema.html` and `*.crema.kt` with highlighting, completion for `@` directives and Wire `wire:*` attributes, and warnings for unknown `@name` / `wire:*` tokens. Inline Wire `template()` strings in Java and Kotlin get the same colors and (with kona-lsp) the same completions. The same Crema grammar and LSP help when you author Wire components or Crema layouts used by Inertia kits.

## What you get

| Piece | Location | Role |
|-------|----------|------|
| TextMate grammar | `ide-support/crema/` | Shared scopes for VS Code / Cursor |
| Language server | `modules/lsp` (`org.konaframework:kona-lsp`) | Completions + diagnostics over LSP stdio |
| VS Code / Cursor extension | `ide-support/vscode-crema/` | Language contribution + setup help |
| IntelliJ native plugin | [konaframework/kona-idea](https://github.com/konaframework/kona-idea) | Crema file type, `@`/view/DB completion, tool window, Grind (no LSP) |

## Fastest path

### IntelliJ IDEA

Install the [Kona Idea](https://github.com/konaframework/kona-idea/releases) zip (**Install Plugin from Disk…**), restart, and open a `*.crema.html` view — language should read **Crema**. Details: [IntelliJ](/docs/language/intellij).

### VS Code / Cursor

1. Open a Crema view with the [VS Code extension](/docs/language/vscode) (grammar from `ide-support/crema/`).
2. Build the language server once:

   ```bash
   ./gradlew :kona-lsp:jar
   ```

3. Point the LSP client at:

   ```bash
   java -jar modules/lsp/build/libs/kona-lsp-*.jar
   ```

From an application project you can also print the same reminder without starting a server:

```bash
./grind ide:lsp
```

## Progressive guides

2. [Language server](/docs/language/lsp) — protocol surface, Kotlin/Java usage in tests, running the jar.
