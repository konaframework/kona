All Kona terminal CLIs share one Termwind-inspired console style: caramel badges (`INFO` / `DONE` / `WARN` / `ERROR`), dim `┌┐└┘` prompt frames with a cyan `›` pointer, intro/outro bars, boxes, two-column lists, tables, and dotted task lines. Brand colors: light caramel `#DF8723`, accent `#74453F`.

| API | Module | Role |
| --- | --- | --- |
| `org.konaframework.support.console.ConsoleIO` | `kona-support` | Canonical implementation |
| `org.konaframework.grind.GrindIO` | `kona-grind` | Wraps `ConsoleIO` with quiet / verbose filtering |
| Helpers on `ConsoleCommand` | `kona-grind` | `info`, `success`, `warn`, `error`, `intro`, `outro`, `note`, `table`, `progress`, … |
| `org.konaframework.grind.Prompts` | `kona-grind` | Interactive ask / confirm / choice |

Do **not** print user-facing output with raw `println` / unstyled `System.out` in commands; use these APIs.

The app-local `./grind` launcher (and `grind serve`’s nested `gradlew run`) use
`--quiet --console=plain -Dorg.gradle.console=plain` so build lifecycle noise and Gradle’s
rich progress bar do not bury Termwind output. Without plain console, `run` can look “stuck”
around 83% for the whole time the HTTP server is up — that percentage is normal Gradle task
progress for a long-lived process, not a hang. Prefer `./grind serve --in-process` when you
already have compiled classes and want to skip an extra Gradle `run` spawn.

## Color environment

`ConsoleIO.detectColor` (also used by `GrindIO.detectColor`):

| Env | Effect |
| --- | --- |
| `NO_COLOR` | Disable ANSI (any value present) |
| `FORCE_COLOR=1` (any non-`0`) | Force ANSI even when `TERM=dumb` |
| `FORCE_COLOR=0` | Keep color off |
| `TERM=dumb` or missing `TERM` | Color off unless forced |

## Verbosity (`GrindIO`)

```kotlin
enum class Verbosity { QUIET, NORMAL, VERBOSE }
```

`GrindIO.fromOptions(options)` sets verbosity from CLI flags:

| Flags | Verbosity |
|-------|-----------|
| `--quiet` / `-q` | `QUIET` |
| `--verbose` / `-v` | `VERBOSE` |
| neither | `NORMAL` |

Quiet wins if both quiet and verbose keys appear (checked first).

| Method | Quiet | Normal | Verbose |
|--------|-------|--------|---------|
| `writeln` / `write` / `line` / `info` / `success` / `warn` / `title` / `subtitle` / `twoColumn` / `box` / `progress` / `table` / `intro` / `outro` / `note` / `promptFrame` / `taskLine` | suppressed | prints | prints |
| `error` | **always prints** (stderr) | prints | prints |
| `verbose` | suppressed | suppressed | prints (dim) |

## `ConsoleIO` surface

Construct with optional `PrintStream` out/err and a `color` boolean:

```kotlin
val console = ConsoleIO()
console.info("Working…")
console.success("Done")
console.warn("Slow path")
console.error("Could not connect")
console.title("Report")
console.subtitle("Section")
console.twoColumn("serve", "Run the HTTP server")
console.box("grind", listOf("Kona app CLI"))
console.progress(3, 10, "users")
console.table(
    listOf("id", "email"),
    listOf(listOf("1", "ada@example.com"), listOf("2", "bea@example.com")),
)
console.taskLine("2000_01_01_000000_create_users_table", "DONE", 12)
console.intro("grind")
console.note("Running migrations.", "INFO")
console.outro("Done.")
```

| Method | Behavior |
|--------|----------|
| `writeln` / `write` / `line` | Raw stdout (still subject to GrindIO quiet when wrapped) |
| `info` | Green ` INFO ` chip + message |
| `success` | Green ` DONE ` chip + message |
| `warn` | Yellow ` WARN ` chip + message |
| `error` | Red ` ERROR ` chip on **stderr** |
| `intro(title)` | Dim top bar `┌ title ────┐` |
| `outro(message)` | Dim bottom bar `└ message ─┘` |
| `note(message, label="NOTE")` | Boxed labeled remark (`INFO` / `WARN` / `ERROR` / `NOTE`) |
| `promptFrame(label, body, pointerLine=-1)` | Prompt box; cyan `›` on `pointerLine` |
| `promptSubmitted(label, value)` | Prompt box with the chosen value in green |
| `title` | Bold green heading + dim underline (max 48) |
| `subtitle` | Cyan line |
| `twoColumn(left, right, width=22)` | Cyan bold left column + dim right |
| `box(title, lines)` | Dim `┌┐└┘` frame; content width clamped roughly 24–56 |
| `progress(current, total, label="")` | 28-cell bar + percent; `total` must be `> 0`; `current` clamped to `[0, total]` |
| `table(headers, rows)` | Aligned columns by **plain** text width (ANSI stripped); headers non-empty; each row must match header width |
| `taskLine(name, status, millis=null, ok=true)` | Dotted row (`name …… 12ms DONE`); green status when `ok`, red otherwise; duration omitted when `millis` is null |
| `paint(codes, text)` | Apply ANSI when color is on |
| `plainLength(text)` | Length with ANSI sequences removed |

`ConsoleIO.formatDuration(millis)` renders `<1000` as `12ms` and longer runs as `1.23s`. Rows align to `ConsoleIO.TASK_WIDTH` (72).

Public ANSI constants on `ConsoleIO`: `RESET`, `BOLD`, `DIM`, `RED`, `GREEN`, `YELLOW`, `CYAN`, `PRIMARY`, `ACCENT`, `GRAY`, `WHITE`, `BLACK`, `BG_GREEN`, `BG_YELLOW`, `BG_RED`, `BG_CYAN`. `PROMPT_WIDTH` is 50.

## `GrindIO` surface

Same high-level helpers as above, plus:

```kotlin
val io = GrindIO.fromOptions(mapOf("verbose" to "true"))
io.verbose("only with -v")
io.subtitle("Detail")
io.twoColumn("left", "right")
io.box("Title", listOf("line"))
io.taskLine("create_users_table", "DONE", 12)
io.intro("grind")
io.outro("Done.")
```

Inside a `ConsoleCommand`, prefer the bound helpers (they use the runner’s `GrindIO`):

```kotlin
info("Working…")
success("Done")
warn("Slow path")
error("Could not connect")
title("Report")
line()
line("plain")
table(
    listOf("id", "email"),
    listOf(listOf("1", "ada@example.com"), listOf("2", "bea@example.com")),
)
progress(3, 10)
progress(3, 10, "users")
verbose("only with -v")
```

`ConsoleCommand.progress` has overloads with and without a label. `intro` / `outro` / `note` are on `ConsoleCommand`. There is still **no** `box` / `twoColumn` / `subtitle` helper on `ConsoleCommand` itself — use `io.box(...)` / `io.twoColumn(...)` / `io.subtitle(...)` when you need them.

## Prompts

Use `Prompts` for interactive input. Injectable streams keep tests non-interactive:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val prompts = Prompts()
val name = prompts.ask("Name", default = "Kona")
val ok = prompts.confirm("Continue?", default = false)
val pick = prompts.choice("Driver", listOf("array", "redis"), defaultIndex = 0)
```

</TabItem>
<TabItem label="Java">

```java
Prompts prompts = new Prompts();
String name = prompts.ask("Name", "Kona");
boolean ok = prompts.confirm("Continue?", false);
String pick = prompts.choice("Driver", List.of("array", "redis"), 0);
```

</TabItem>
</Tabs>

| Method | Behavior |
|--------|----------|
| `ask(question, default=null)` | Boxed question; empty line uses `default` when set; otherwise returns empty string; then reprints a green submitted value |
| `confirm(question, default=false)` | Boxed `Yes` / `No` with `›` on the default; empty → default; `y` / `yes` / `1` → true; `n` / `no` / `2` → false |
| `choice(question, options, defaultIndex=0)` | Boxed options with `›` on the default; empty → default; accepts 1-based index or case-insensitive label; invalid input → default |

`choice` requires a non-empty options list and a `defaultIndex` in range. Frames go to the prompt output stream you inject (default: `System.out`).

Built-ins such as `serve` (port conflict) and `key:generate` (production overwrite) use `Prompts` internally.

## Exit codes

| Code | Constant | Meaning |
|------|----------|---------|
| `0` | `ConsoleCommand.SUCCESS` | Success (also when `--isolated` skips a busy command) |
| `1` | `ConsoleCommand.FAILURE` | Usage errors, missing projects, failed generators, unbound services, unknown commands |

Scripts and CI should treat any non-zero exit as failure. Built-ins typically return `0`/`1` the same way; uncaught `GrindException` / `CadenceException` in `GrindApplication` become error lines and exit `1`.

## Testing output

`ConsoleTester` captures **stdout** only while running `GrindApplication` — see [HTTP & console tests](../../testing/http-console/#console-grind). Assertions:

| Method | Behavior |
|--------|----------|
| `assertOk()` | Exit code `0` |
| `assertExit(code)` | Exact exit code |
| `assertSee(text)` | Stdout contains substring |
| `assertDontSee(text)` | Stdout does not contain substring |

Because `error(...)` writes to stderr, failed error messages may **not** appear in `ConsoleResult.output`. Assert on exit codes for failure paths, or inject streams when testing `Prompts` / `ConsoleIO` directly (as the module tests do).

## Pitfalls

- **Quiet hides progress and tables** — do not rely on progress bars in `-q` CI logs.
- **`table` row width** — mismatched column counts throw; normalize rows first.
- **`progress` total** — must be positive or `ConsoleIO` throws.
- **Color in pipes** — honor `NO_COLOR` in automation; do not assume ANSI in captured test output.
- **Global `System.out` swap** — `Grind.callSilently` and `ConsoleTester` replace stdout; avoid nested concurrent calls that depend on the real stream.
