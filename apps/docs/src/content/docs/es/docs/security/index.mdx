La pila de seguridad de Kona se publica en dos módulos:

- **`kona-session`** — sesiones HTTP (drivers array / file / cookie / Redis), datos flash, URL anterior / input antiguo y verificación CSRF.
- **`kona-auth`** — hashing, guards, la fachada `Auth`, restablecimiento de contraseñas, gates / policies, tokens de API, cifrado, CORS, cabeceras de seguridad y limitación de tasa.

## Camino simple

Las apps de `kona new` ya registran los providers de sesión y auth y conectan `StartSession` + CSRF en la pila de middleware web.

1. Mantén `SessionServiceProvider` y `AuthServiceProvider` en la lista de providers del bootstrap.
2. Mantén `StartSession` y `VerifyCsrfToken` en la pila web (`/api/*` queda excluido de CSRF por defecto).
3. Protege las rutas HTML con `Authenticate`; usa bearer tokens o `AuthenticateWithToken` para las API.
4. Autoriza con `Gate` / policies o el middleware `Authorize`.
