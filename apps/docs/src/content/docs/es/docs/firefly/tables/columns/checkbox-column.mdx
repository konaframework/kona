A `CheckboxColumn` binds a boolean-ish row attribute to a single checkbox in the cell. When the cell is editable, changing the box calls Wire `toggleColumn` with `"true"` or `"false"` and persists immediately. When it is not editable, the input is `disabled` and no change handler is attached.

This is the column type for per-row flags you want to edit inline. It is not the same as the table’s bulk selection checkboxes in the toolbar — those select rows for bulk actions.

## Add the column

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
CheckboxColumn.make("active")
    .label("Active")
```

</TabItem>
<TabItem label="Java">

```java
CheckboxColumn.make("active")
    .label("Active");
```

</TabItem>
</Tabs>

Truthy state checks the box: `Boolean`, non-zero numbers, and `"1"` / `"true"` / `"yes"`. Null and other values leave it unchecked.

## Editable gates

By default every cell is editable. Use `editable` when only some operators or rows may change the value:

| Method | Effect |
|--------|--------|
| `editable()` / `editable(true)` | Always editable (default behavior) |
| `editable(false)` | Always readonly |
| `editable(Predicate<Cell>)` | Per-cell gate; return `true` to allow persist |

`disabled()` on the column always wins: `isEditable(cell)` returns `false` when the column is disabled for that cell, even if the editable predicate would allow it.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
CheckboxColumn.make("active")
    .label("Active")
    .editable { cell -> cell.get("/can_update") == true }
    .extraInputAttributes(mapOf("aria-label" to "Active"))
```

</TabItem>
<TabItem label="Java">

```java
CheckboxColumn.make("active")
    .label("Active")
    .editable(cell -> Boolean.TRUE.equals(cell.get("/can_update")))
    .extraInputAttributes(Map.of("aria-label", "Active"));
```

</TabItem>
</Tabs>

## Extra input attributes

`extraInputAttributes(Map)` or `extraInputAttributes { cell -> ... }` merges onto the `<input>`. Ownership of `type`, checked state, and the Wire change handler stays with Firefly — use extras for `aria-label`, `data-*`, or similar.

`extraAttributes` (inherited from `Column`) applies to the outer `ff-checkbox-column` shell, not the input.

## Shared helpers

| Method | Effect |
|--------|--------|
| `label(...)` | Heading |
| `tooltip(...)` / `description(...)` | Shell tips |
| `align(Align)` / `width(String)` | Layout |
| `hidden()` / `visible(...)` / `disabled(...)` | Visibility and hard disable |
| `toggleable()` / `toggledHiddenByDefault()` | Column picker |
| `extraAttributes(...)` | Attributes on the outer div |

## Tips

- Prefer [Toggle column](/docs/firefly/tables/columns/toggle-column/) when you want a switch UI without an edit gate.
- Prefer [Icon column](/docs/firefly/tables/columns/icon-column/) boolean mode for read-only Yes/No pills.
- Keep form fields ([Checkbox](/docs/firefly/forms/checkbox/), [Toggle](/docs/firefly/forms/toggle/)) for create/edit schemas; this column is for list inline edits.
