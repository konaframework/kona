`KeyValueEntry` expects a `Map` and paints it as a two-column table. It inherits every helper on [Entry](/docs/firefly/infolists/#helpers-on-every-entry) (`label`, `state`, `placeholder`, and the rest). Use it for metadata bags, settings snapshots, or any record field that is already a string-keyed map.

<FireflyShot file="infolist-key-value-entry.png" description="A key-value entry table with Field and Detail headers." />

## Make a key-value entry

Call `KeyValueEntry.make("meta")`, rename the headers if you want, and pass a map as state (or fill it on the schema).

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
KeyValueEntry.make("meta")
    .label("Metadata")
    .keyLabel("Field")
    .valueLabel("Detail")
    .emptyMessage("Nothing yet")
    .state(mapOf("city" to "Kona", "lane" to "north"))
```

</TabItem>
<TabItem label="Java">

```java
KeyValueEntry.make("meta")
    .label("Metadata")
    .keyLabel("Field")
    .valueLabel("Detail")
    .emptyMessage("Nothing yet")
    .state(Map.of("city", "Kona", "lane", "north"));
```

</TabItem>
</Tabs>

You see a table with the header **Field** / **Detail** and one row per map entry. Keys and values are stringified and HTML-escaped. Row order follows the map’s iteration order (`LinkedHashMap` keeps insertion order).

## Headers and empty state

| Method | Effect |
|--------|--------|
| `keyLabel(text)` | Header for the key column (default `Key`) |
| `valueLabel(text)` | Header for the value column (default `Value`) |
| `emptyMessage(text)` | Alias of `placeholder` when the map is empty (default `No values`) |
| `placeholder(text)` | Same empty copy as `emptyMessage` |
| `state(map)` / filled schema | Must be a `Map`; anything else renders empty |

Both `keyLabel` and `valueLabel` also accept a `Function<Get, String>` so the header can depend on the current reader. A null key is skipped. Nested maps and lists in values are stringified with `toString()`, not expanded into nested tables.

## Closures and binding

Prefer filling the parent schema when the map comes from Cadence or a resource record. Explicit `state` is useful in samples and unit tests.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
KeyValueEntry.make("meta")
    .keyLabel { "Field" }
    .valueLabel { get -> get.get("valueHeading")?.toString() ?: "Detail" }
    .emptyMessage { "No metadata on this record" }
```

</TabItem>
<TabItem label="Java">

```java
KeyValueEntry.make("meta")
    .keyLabel(get -> "Field")
    .valueLabel(get -> {
        Object heading = get.get("valueHeading");
        return heading == null ? "Detail" : heading.toString();
    })
    .emptyMessage(get -> "No metadata on this record");
```

</TabItem>
</Tabs>

Dotted names work like other entries: `KeyValueEntry.make("order.meta")` reads `order.meta` from filled state or the schema’s Cadence record.

## Defaults for every make

`KeyValueEntry.configureUsing { entry -> entry.keyLabel("Name").valueLabel("Value") }` runs for every later `make()`. Pass `null` to clear it.
