## Detecting an Inertia request

`InertiaManager.isInertiaRequest(request)` is true when the request has an `X-Inertia` header (any value). The official clients send `X-Inertia: true`.

## First visit → HTML

- Status `200`
- `Content-Type` HTML
- Body: root Crema view or `rootHtml` with optional SSR head/body
- View data: `page`, `pageAttr`, `vite`, `ssrHead`, `ssrBody`
- No `X-Inertia` response header on the plain HTML shell

## Inertia visit → JSON

- Body: JSON map of the page object
- `X-Inertia: true`
- `Vary: X-Inertia`
- `X-Inertia-Version` when the manager version is non-empty

## Page object fields

| Field | Meaning |
|-------|---------|
| `component` | Page component name |
| `props` | Resolved props (always includes `errors` when missing) |
| `url` | Path + query |
| `version` | Asset version or `null` |
| `encryptHistory` / `clearHistory` | History flags |
| `deferredProps` | Group → prop keys (full visits only) |
| `mergeProps` / `prependProps` / `deepMergeProps` / `matchPropsOn` | Client merge hints |

## Status codes

| Status | Meaning |
|--------|---------|
| `200` | HTML shell or JSON page |
| `302` | Ordinary redirect (GET/POST) |
| `303` | Redirect after Inertia `PUT` / `PATCH` / `DELETE` |
| `409` | Asset version mismatch or `Inertia.location` (`X-Inertia-Location`) |
