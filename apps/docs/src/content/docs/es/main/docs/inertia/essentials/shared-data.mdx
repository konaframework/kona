## Global share

Lives for the life of the process (or until cleared):

```kotlin
Inertia.share("appName", "Kona")
Inertia.share(mapOf("features" to listOf("a", "b")))
```

```java
Inertia.share("appName", "Kona");
Inertia.share(Map.of("features", List.of("a", "b")));
```

Inspect with `Inertia.manager().shared()`. Clear with `manager.clearShared()`.

## Middleware defaults

`HandleInertiaRequests` always merges **default share** before your `share(request)` override:

| Prop | Source |
|------|--------|
| `errors` | Session `errors` flash as `Inertia.always(...)` (first message per field). With `X-Inertia-Error-Bag`, nested under that bag name. |
| `flash` | Session keys `success`, `error`, `warning`, `info`, `status` |

Override `defaultShare(request)` to replace those defaults, or override `share(request)` to add app props (they win on key clash).

<TabItem label="Kotlin">

```kotlin
class HandleInertia : HandleInertiaRequests() {
    override fun share(request: Request) = mapOf(
        "auth" to mapOf("user" to currentUser(request)),

}
```

<TabItem label="Java">

```java
public class HandleInertia extends HandleInertiaRequests {
    @Override
    public Map<String, Object> share(Request request) {
        return Map.of("path", request.getPath());
    }
}
```

## Merge order

1. Global `share`
2. Middleware `defaultShare` + `share` / `shareForRequest`
3. Props passed to `Inertia.render` (highest priority)

## Validation errors

`ValidationException` already redirects back with flashed errors for non-JSON requests (Inertia clients send HTML Accept). The next Inertia render picks them up via `errors`. Partial reloads still receive `errors` because they are wrapped in `Inertia.always`.
