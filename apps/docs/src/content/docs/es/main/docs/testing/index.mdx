**kona-testing** es el arnés de pruebas para aplicaciones Kona. Arranca una `Application` real bajo una ruta base temporal y luego conduce HTTP, grind, la base de datos y fakes en memoria sin abrir sockets ni tocar servicios de producción.

Añádelo como dependencia de prueba:

```kotlin
dependencies {
    testImplementation("org.konaframework:kona-testing:${konaVersion}")
}
```

## Arrancar una aplicación

`TestApplication.create(base, *providers)` es un envoltorio fino alrededor de `Kona.create("--base=…").providers(…).boot()`.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
@TempDir
lateinit var base: Path

val app = TestApplication.create(
    base,
    HttpServiceProvider(),
    MyAppProvider(),
)
```

</TabItem>
<TabItem label="Java">

```java
Path base = Files.createTempDirectory("app");
Application app = TestApplication.create(
    base,
    new HttpServiceProvider(),
    new MyAppProvider()
);
```

</TabItem>
</Tabs>

Registra rutas, enlaces y middleware en los providers que pases (o después del arranque). El desmontaje suele ser «tirar el directorio temporal» — prefiere bases nuevas a reutilizar apps de larga vida entre pruebas.

## Ejemplo Java

`modules/testing` incluye `JavaTestingApiTest` — las mismas APIs son `@JvmStatic` / llamables desde Java. Prefiere los ejemplos Kotlin de arriba; llama a los mismos tipos desde Java cuando las pruebas de tu app son Java primero.
