title: Limitación de tasa
description: Define limitadores con nombre y estrangula peticiones HTTP con cabeceras Retry-After y X-RateLimit.

import { Tabs, TabItem } from '@astrojs/starlight/components';

La **limitación de tasa** pone un tope a la frecuencia con la que un cliente puede golpear una ruta — puntos de inicio de sesión, APIs públicas, informes caros. El `RateLimiter` de Kona sigue los golpes en memoria por clave; el middleware `ThrottleRequests` convierte un limitador con nombre en respuestas HTTP con cabeceras estándar.

Artefacto: `org.konaframework:kona-auth`. `AuthServiceProvider` registra un `RateLimiter` compartido.

## Camino más simple

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
import org.konaframework.http.HttpKernel
import org.konaframework.http.Router
import org.konaframework.security.RateLimit
import org.konaframework.security.RateLimiter
import org.konaframework.security.ThrottleRequests

val limiter = app.resolve(RateLimiter::class.java)
limiter.forName("login") { request ->
    RateLimit.perMinute(5) // or RateLimit(5, 60)
}

val router = app.resolve(Router::class.java)
router.routes {
    group(prefix = "/auth", middleware = listOf(ThrottleRequests(limiter, "login"))) {
        post("/login") { /* … */ }
    }
}
```

</TabItem>
<TabItem label="Java">

```java
import org.konaframework.security.RateLimit;
import org.konaframework.security.RateLimiter;
import org.konaframework.security.ThrottleRequests;
import java.util.List;

RateLimiter limiter = app.resolve(RateLimiter.class);
limiter.forName("login", request -> RateLimit.perMinute(5));

Router router = app.resolve(Router.class);
router.prefix("/auth")
    .middleware(List.of(new ThrottleRequests(limiter, "login")))
    .group(auth -> {
        auth.post("/login", request -> /* … */);
    });
```

</TabItem>
</Tabs>

Cuando se supera el límite, el middleware lanza `RateLimitExceededException` — HTTP **429** con una cabecera `Retry-After` (segundos hasta que se reinicia la ventana).

Las respuestas correctas ganan:

- `X-RateLimit-Limit` — intentos máximos en la ventana
- `X-RateLimit-Remaining` — intentos que quedan después de este golpe

## Nombres y claves

Registra limitadores con `for` / `forName` (alias amigable para Java). Cada registro es un callback `(Request) -> RateLimit` para que los límites puedan depender de la ruta, el usuario o el plan:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
limiter.forName("api") { request ->
    val userId = request.getAttribute("user")?.toString()
    if (userId != null) RateLimit(120, 60) else RateLimit(30, 60)
}
```

</TabItem>
<TabItem label="Java">

```java
limiter.forName("api", request -> {
    Object user = request.getAttribute("user");
    return user != null ? new RateLimit(120, 60) : new RateLimit(30, 60);
});
```

</TabItem>
</Tabs>

`ThrottleRequests` construye la clave de golpe como `{limiterName}:{clientKey}`. La clave de cliente predeterminada es:

1. `X-Forwarded-For`
2. si no, `X-Real-IP`
3. si no, el atributo de petición `"ip"`
4. si no, `"global"`

Anúlala con un resolvedor propio:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
ThrottleRequests(limiter, "login") { req ->
    req.input("email") ?: req.header("X-Forwarded-For") ?: "unknown"
}
```

</TabItem>
<TabItem label="Java">

```java
new ThrottleRequests(limiter, "login", req -> {
    String email = req.input("email", null);
    if (email != null) return email;
    String ip = req.header("X-Forwarded-For");
    return ip != null ? ip : "unknown";
});
```

</TabItem>
</Tabs>

## Usar el limitador sin middleware

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val key = "reports:user-42"
if (!limiter.attempt(key, maxAttempts = 10, decaySeconds = 60)) {
    val wait = limiter.availableIn(key)
    throw RateLimitExceededException(wait)
}
// work…
limiter.clear(key)  // reset after success, if desired
```

</TabItem>
<TabItem label="Java">

```java
String key = "reports:user-42";
if (!limiter.attempt(key, 10, 60)) {
    throw new RateLimitExceededException(limiter.availableIn(key));
}
limiter.clear(key);
```

</TabItem>
</Tabs>

Otros ayudantes: `hit`, `tooManyAttempts`, `retriesLeft`, `clearAll`.

## Modos de fallo

| Situación | Resultado |
|-----------|--------|
| Nombre de limitador desconocido en el middleware | `IllegalArgumentException` |
| Demasiados intentos | `RateLimitExceededException` (429 + `Retry-After`) |
| Reinicio del proceso | Los contadores en memoria se reinician (vale para un solo nodo; los almacenes compartidos llegan con hitos de infraestructura posteriores) |

Coloca el middleware de estrangulamiento **fuera** de los manejadores caros pero **dentro** del middleware de identidad cuando la clave depende del usuario autenticado.
