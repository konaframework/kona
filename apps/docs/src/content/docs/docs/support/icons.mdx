`kona-icons` is the shared SVG icon layer for Kona apps and first-party UI (Firefly chrome, Crema views, grind scaffolds). Heroicons v2 ship on the classpath; you can register more sets the same way Blade Icons does.

```kotlin
implementation("org.konaframework:kona-icons")
```

Crema already depends on `kona-icons`, so any kit that pulls in `kona-crema` can call the `icon()` helper in templates without an extra dependency.

## Resolve and render (Kotlin / Java)

Call `Icons.svg(name)` to load an icon, then chain attributes and print HTML with `toHtml()` (or use the value in a string template — `Svg.toString()` is the same markup).

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
import org.konaframework.icons.Icons

val html = Icons.svg("heroicon-o-bell")
    .className("w-5 h-5 text-amber-700")
    .attr("aria-hidden", "true")
    .toHtml()

// Bare style+name resolves against the default set (Heroicons):
Icons.svg("o-user").toHtml()
```

</TabItem>
<TabItem label="Java">

```java
import org.konaframework.icons.Icons;

String html = Icons.svg("heroicon-o-bell")
    .className("w-5 h-5")
    .attr("aria-hidden", "true")
    .toHtml();
```

`Icons.has("heroicon-o-bell")` checks availability without rendering. `Icons.all()` returns registered sets. Missing names throw `IconNotFoundException` unless a fallback is configured.

## Render an icon in a Crema view

Use the `icon` echo helper and **raw** braces so the SVG is not HTML-escaped:

```crema
{{-- Outline bell, optional CSS class --}}
{!! icon('heroicon-o-bell') !!}
{!! icon('heroicon-o-home', 'w-5 h-5 text-caramel') !!}

<button type="submit" class="btn">
  {!! icon('heroicon-o-check', 'btn-icon') !!}
  Save
</button>
```

| Form | Meaning |
| --- | --- |
| `{!! icon('heroicon-o-bell') !!}` | Inline SVG for that Heroicon |
| `{!! icon('o-bell') !!}` | Same, via the default set |
| `{!! icon('heroicon-o-bell', 'my-class') !!}` | Extra `class` on the root `<svg>` |
| `{{ icon('heroicon-o-bell') }}` | Escapes the markup — do **not** use for icons |

Empty or blank names render nothing. Unknown names throw at render time (same as `Icons.svg`).

From a controller or layout Kotlin class you can also pass pre-rendered markup into the view:

```kotlin
view(
    "dashboard",
    mapOf(
        "statusIcon" to Icons.svg("heroicon-o-check-circle").className("status-ok").toHtml(),
    ),
)
```

```crema
{!! statusIcon !!}
```

## Heroicons (default)

Names use the `heroicon` prefix plus a style letter:

| Prefix | Style | Example |
| --- | --- | --- |
| `heroicon-o-…` | Outline (24×24) | `heroicon-o-bell` |
| `heroicon-s-…` | Solid (24×24) | `heroicon-s-home` |
| `heroicon-m-…` | Mini (20×20) | `heroicon-m-check` |

Browse the set at [heroicons.com](https://heroicons.com). File names on the classpath match the site (`o-bell.svg`, `s-home.svg`, …).

## Drop-in icon sets

Register another set with a unique **prefix** and either classpath directories or filesystem paths:

```kotlin
Icons.add(
    "lucide",
    IconSetOptions(
        prefix = "lucide",
        classpath = "icons/lucide",           // src/main/resources/icons/lucide/*.svg
        // path = Path.of("resources/svg"),  // or filesystem
        className = "icon",
        attributes = mapOf("aria-hidden" to "true"),
        fallback = "circle",                  // set-local fallback file name
    ),
)

Icons.svg("lucide-activity").toHtml()
```

Optional global fallback when every set miss fails:

```kotlin
Icons.setFallback("heroicon-o-question-mark-circle")
```

`Icons.setDefault("lucide")` makes bare names (no prefix) resolve against that set. `Icons.reset()` clears registrations (useful in tests); the next `svg` / `ensureDefaults` call restores Heroicons.

## Firefly short names

Firefly’s `org.konaframework.firefly.support.Icon` remains a thin facade for panel chrome. Short names such as `home`, `bars`, `check`, and `trash` map to outline Heroicons and render with the `ff-icon` CSS class. New application code and Crema views should call `Icons` / `icon()` directly.

## Packaging your own set

1. Put `.svg` files under a classpath folder (for example `src/main/resources/icons/acme/`).
2. Depend on `kona-icons` (or `kona-crema`, which already brings it).
3. Call `Icons.add("acme", IconSetOptions(prefix = "acme", classpath = "icons/acme"))` during boot (or from a `ServiceProvider`).
4. Reference icons as `acme-widget-name` in Kotlin/Java or `{!! icon('acme-widget-name') !!}` in Crema.
