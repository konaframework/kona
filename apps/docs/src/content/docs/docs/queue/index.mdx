title: Queues
description: Dispatch jobs, run workers, and inspect failed jobs.

Kona queues run background work with sync, in-memory, Redis, and database drivers. Jobs that implement `ShouldQueue` are pushed; everything else runs immediately through `Bus`.

## Quick start

```kotlin
class SendInvoice : Job, ShouldQueue {
    override fun handle() { /* … */ }
}

val bus = app.resolve(Bus::class.java)
bus.dispatch(SendInvoice())
Worker(app.resolve(QueueManager::class.java)).run(maxJobs = 10)
```

Register `QueueServiceProvider`. Configure `queue.default` and `queue.connections.{name}.driver` (`sync`, `array`/`memory`, `redis`, `database`).

## Workers and failed jobs

```bash
./grind queue:work [--connection=array] [--queue=default] [--max=100]
./grind queue:failed
./grind queue:retry <id>|--all
./grind queue:flush
```

Failed jobs default to an in-memory `FailedJobProvider`. Set `queue.failed.driver=file` and optionally `queue.failed.path` (default `storage/framework/failed_jobs.json`) to persist a JSON array on disk so retries survive process restart.

`./grind queue:retry` **re-queues** the payload (attempts reset) onto the original connection/queue, then forgets the failed row.

Backoff uses `availableAt` on the payload: array/Redis/database drivers skip jobs until the delay elapses (workers are not blocked with `Thread.sleep`).

## Job contracts

Optional `JobContract` methods: `tries()`, `backoffSeconds()`, `displayName()`.

Cross-process workers restore jobs by:
1. A factory registered in `JobRegistry`, or
2. A public no-arg constructor on the job class named by `jobKey`.
