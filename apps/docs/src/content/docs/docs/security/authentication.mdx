Authentication answers: *who is this request?* Kona ships session guards for browsers, bearer-token guards for APIs, password hashing, reset brokers, and middleware that gate routes.

`AuthServiceProvider` registers hashing, an in-memory user provider, `web` + `api` guards, the password broker, personal access tokens, and the `Auth` facade.

## Simple path

1. Keep `AuthServiceProvider` (and `SessionServiceProvider` for web) on your bootstrap list — `kona new` does this.
2. Ensure `StartSession` runs before auth middleware on HTML routes.
3. Log in with credentials; protect routes with `Authenticate`.

```kotlin
auth.setRequest(request)
if (auth.attempt(mapOf("email" to email, "password" to password), remember = true)) {
    val intended = Authenticate.pullIntended(request, "/")
    return Response.redirect(intended)
}
```

```java
auth.setRequest(request);
if (auth.attempt(Map.of("email", email, "password", password), true)) {
    String intended = Authenticate.pullIntended(request, "/");
    return Response.redirect(intended);
}
```

## Auth facade and manager

`AuthManager` resolves named guards. The `Auth` object mirrors the manager after the provider boots:

| Call | Meaning |
|------|---------|
| `attempt` / `login` / `logout` | Persist (or clear) the session user |
| `check` / `guest` / `id` / `user` | Inspect the current user |
| `validate` | Check credentials **without** logging in |
| `once` / `onceUsingId` | Authenticate for **this request only** |
| `loginUsingId` | Log in by primary key |
| `viaRemember` | True when restored from a remember cookie |
| `guard("api")` | Switch guard |

```kotlin
Auth.setRequest(request)
Auth.attempt(mapOf("email" to "a@b.c", "password" to "secret"))
val user = Auth.user()
```

## Guards

- **`web` (`SessionGuard`)** — stores `login_{guard}_id` (and password hash) in the request session attribute `"session"`.
- **`api` (`TokenGuard`)** — reads `Authorization: Bearer {id}|{secret}` via `PersonalAccessTokenManager`.

Register custom guards with `auth.extend("admin", SessionGuard("admin", users))`.

### Remember me

When `login` / `attempt` is called with `remember = true`:

1. A remember token is stored on the user (`Authenticatable.setRememberToken`).
2. A long-lived `remember_{guard}` cookie (`{id}|{token}`) is **queued** on the request.
3. Middleware that flushes auth cookies (built into `Authenticate`, `RedirectIfAuthenticated`, and `AuthenticateSession`) writes `Set-Cookie` on the response.

On a later visit with no session id, `SessionGuard` recalls the user from the cookie and `viaRemember()` returns true. Logout clears the token and queues a forgetting cookie.

`UserProvider.retrieveByToken` / `updateRememberToken` power this; `InMemoryUserProvider` implements both.

## Middleware

| Middleware | Role |
|------------|------|
| `Authenticate` | Require login; redirect to `/login` (or throw 401 when `redirectTo = null`); stores `url.intended` on GET |
| `RedirectIfAuthenticated` | Bounce already-logged-in users away from guest pages |
| `AuthenticateSession` | Log out when the password hash no longer matches the hash captured at login |

```kotlin
router.get("/dashboard", handler).middleware(Authenticate(auth))
router.get("/login", handler).middleware(RedirectIfAuthenticated(auth, "/home"))
router.middleware(AuthenticateSession(auth))
```

After a successful login, send the user to `Authenticate.pullIntended(request, "/")`.

## Hashing

```kotlin
Hash.make("secret")
Hash.check("secret", hash)
Hash.needsRehash(hash)
```

**Bcrypt** is the default (`hash.rounds`, default 10). Passwords longer than 72 bytes are truncated to bcrypt’s limit. Register another `Hasher` with `HashManager.extend` when you need a different algorithm.

## Password resets

`PasswordBroker` issues in-memory reset tokens and applies resets through a callback:

```kotlin
val token = broker.createToken(mapOf("email" to email))
val result = broker.reset(mapOf("email" to email, "token" to token, "password" to next)) { user, password ->
    // persist Hash.make(password)
}
```

For form validation rule lists, use `PasswordRules.min(8)` / `PasswordRules.confirmed()` with the HTTP validator (see [Validation](/docs/http/validation/)).

## API tokens

`PersonalAccessTokenManager.create(user, name, abilities)` returns a plain-text token once (`id|secret`) and stores a SHA-256 hash. Check abilities with `token.can("read")` / `token.cant("write")`.

Authenticate with bearer tokens via `TokenGuard` or `AuthenticateWithToken` middleware.
