Two complementary middleware classes in `dev.kona:kona-auth` harden HTTP responses:

- **CORS** (`CorsMiddleware`) — tell browsers which other origins may call your API with cookies or custom headers.
- **Security headers** (`SecurityHeadersMiddleware`) — attach headers that reduce clickjacking, MIME sniffing, and related risks.

Neither replaces [authentication](../authentication/), [CSRF](../csrf/), or [rate limiting](../rate-limiting/); they constrain how browsers treat responses.

## CORS

### Simplest path

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
import dev.kona.http.HttpKernel
import dev.kona.security.CorsConfig
import dev.kona.security.CorsMiddleware

val cors = CorsMiddleware(
    CorsConfig(
        allowedOrigins = listOf("https://app.example.com"),
        allowedMethods = listOf("GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS"),
        allowedHeaders = listOf("Content-Type", "Authorization", "X-Requested-With"),
        allowCredentials = true,
        maxAgeSeconds = 600,
    ),
)
app.resolve(HttpKernel::class.java).pushMiddleware(cors)
```

</TabItem>
<TabItem label="Java">

```java
import dev.kona.security.CorsConfig;
import dev.kona.security.CorsMiddleware;
import java.util.List;

CorsMiddleware cors = new CorsMiddleware(new CorsConfig(
    List.of("https://app.example.com"),
    List.of("GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS"),
    List.of("Content-Type", "Authorization", "X-Requested-With"),
    List.of(),   // exposedHeaders
    true,        // allowCredentials
    600L
));
app.resolve(HttpKernel.class).pushMiddleware(cors);
```

</TabItem>
</Tabs>

Defaults (no-arg `CorsConfig()`): origins `*`, common methods, headers `*`, credentials off, max-age 600 seconds.

### Behavior

1. **Preflight** — `OPTIONS` with `Origin` + `Access-Control-Request-Method` short-circuits with **204** and CORS headers (handler not run).
2. **Other requests** — the pipeline runs; CORS headers are applied to the response.

| Config field | Effect |
|--------------|--------|
| `allowedOrigins` | Exact origin match, or `*` (with credentials, `*` echoes the request origin) |
| `allowedMethods` | `Access-Control-Allow-Methods` |
| `allowedHeaders` | Fixed list, or `*` (reflect request headers / sensible default) |
| `exposedHeaders` | `Access-Control-Expose-Headers` when non-empty |
| `allowCredentials` | Sets `Access-Control-Allow-Credentials: true` |
| `maxAgeSeconds` | `Access-Control-Max-Age` |

When the allowed origin is not `*`, responses also get `Vary: Origin` (merged with any existing `Vary`).

## Security headers

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
import dev.kona.security.SecurityHeadersConfig
import dev.kona.security.SecurityHeadersMiddleware

val headers = SecurityHeadersMiddleware(
    SecurityHeadersConfig(
        xContentTypeOptions = "nosniff",
        xFrameOptions = "SAMEORIGIN",
        referrerPolicy = "no-referrer-when-downgrade",
        xXssProtection = "0",
        // permissionsPolicy = "geolocation=()",
        // strictTransportSecurity = "max-age=31536000; includeSubDomains",
        // contentSecurityPolicy = "default-src 'self'",
        // custom = mapOf("X-App" to "kona"),
    ),
)
app.resolve(HttpKernel::class.java).pushMiddleware(headers)
```

</TabItem>
<TabItem label="Java">

```java
SecurityHeadersMiddleware headers = new SecurityHeadersMiddleware(
    new SecurityHeadersConfig(
        "nosniff",
        "SAMEORIGIN",
        "no-referrer-when-downgrade",
        "0",
        null,  // permissionsPolicy
        null,  // HSTS
        null,  // CSP
        Map.of()
    )
);
app.resolve(HttpKernel.class).pushMiddleware(headers);
```

</TabItem>
</Tabs>

Any config field set to `null` skips that header. Defaults enable `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, and `X-XSS-Protection` as shown above. Enable HSTS only behind HTTPS.

## Suggested stack order

Push outer concerns first (they wrap later middleware):

1. `CorsMiddleware` — handle preflight early
2. `SecurityHeadersMiddleware` — tag every response
3. `StartSession` / CSRF / auth / throttle — application logic

Order among CORS and security headers is flexible; keep session and CSRF inside the cookie/session path as documented on those pages.
