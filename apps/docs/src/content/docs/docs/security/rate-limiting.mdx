**Rate limiting** caps how often a client may hit a route — login endpoints, public APIs, expensive reports. Kona’s `RateLimiter` tracks hits in memory by key; `ThrottleRequests` middleware turns a named limiter into HTTP responses with standard headers.

Artifact: `io.konaframework:kona-auth`. `AuthServiceProvider` registers a shared `RateLimiter`.

## Simplest path

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
import io.konaframework.http.HttpKernel
import io.konaframework.http.Router
import io.konaframework.security.RateLimit
import io.konaframework.security.RateLimiter
import io.konaframework.security.ThrottleRequests

val limiter = app.resolve(RateLimiter::class.java)
limiter.forName("login") { request ->
    RateLimit.perMinute(5) // or RateLimit(5, 60)
}

val router = app.resolve(Router::class.java)
router.routes {
    group(prefix = "/auth", middleware = listOf(ThrottleRequests(limiter, "login"))) {
        post("/login") { /* … */ }
    }
}
```

</TabItem>
<TabItem label="Java">

```java
import io.konaframework.security.RateLimit;
import io.konaframework.security.RateLimiter;
import io.konaframework.security.ThrottleRequests;
import java.util.List;

RateLimiter limiter = app.resolve(RateLimiter.class);
limiter.forName("login", request -> RateLimit.perMinute(5));

Router router = app.resolve(Router.class);
router.prefix("/auth")
    .middleware(List.of(new ThrottleRequests(limiter, "login")))
    .group(auth -> {
        auth.post("/login", request -> /* … */);
    });
```

</TabItem>
</Tabs>

When the limit is exceeded, the middleware throws `RateLimitExceededException` — HTTP **429** with a `Retry-After` header (seconds until the window resets).

Successful responses gain:

- `X-RateLimit-Limit` — max attempts in the window  
- `X-RateLimit-Remaining` — attempts left after this hit  

## Naming and keys

Register limiters with `for` / `forName` (Java-friendly alias). Each registration is a callback `(Request) -> RateLimit` so limits can depend on path, user, or plan:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
limiter.forName("api") { request ->
    val userId = request.getAttribute("user")?.toString()
    if (userId != null) RateLimit(120, 60) else RateLimit(30, 60)
}
```

</TabItem>
<TabItem label="Java">

```java
limiter.forName("api", request -> {
    Object user = request.getAttribute("user");
    return user != null ? new RateLimit(120, 60) : new RateLimit(30, 60);
});
```

</TabItem>
</Tabs>

`ThrottleRequests` builds the hit key as `{limiterName}:{clientKey}`. The default client key is:

1. `X-Forwarded-For`
2. else `X-Real-IP`
3. else request attribute `"ip"`
4. else `"global"`

Override with a custom resolver:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
ThrottleRequests(limiter, "login") { req ->
    req.input("email") ?: req.header("X-Forwarded-For") ?: "unknown"
}
```

</TabItem>
<TabItem label="Java">

```java
new ThrottleRequests(limiter, "login", req -> {
    String email = req.input("email", null);
    if (email != null) return email;
    String ip = req.header("X-Forwarded-For");
    return ip != null ? ip : "unknown";
});
```

</TabItem>
</Tabs>

## Using the limiter without middleware

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val key = "reports:user-42"
if (!limiter.attempt(key, maxAttempts = 10, decaySeconds = 60)) {
    val wait = limiter.availableIn(key)
    throw RateLimitExceededException(wait)
}
// work…
limiter.clear(key)  // reset after success, if desired
```

</TabItem>
<TabItem label="Java">

```java
String key = "reports:user-42";
if (!limiter.attempt(key, 10, 60)) {
    throw new RateLimitExceededException(limiter.availableIn(key));
}
limiter.clear(key);
```

</TabItem>
</Tabs>

Other helpers: `hit`, `tooManyAttempts`, `retriesLeft`, `clearAll`.

## Failure modes

| Situation | Result |
|-----------|--------|
| Unknown limiter name in middleware | `IllegalArgumentException` |
| Too many attempts | `RateLimitExceededException` (429 + `Retry-After`) |
| Process restart | In-memory counters reset (fine for single-node; shared stores land with later infrastructure milestones) |

Place throttle middleware **outside** expensive handlers but **inside** identity middleware when the key depends on the authenticated user.
