The **router** decides which code runs for an incoming request. A **route** is one entry in the router: a set of HTTP methods, a path pattern such as `/users/{id}`, and a **handler** — a function that receives the `Request` and returns a `Response`. When a request arrives, the [HTTP kernel](../kernel-server/) asks the router for the first matching route, then runs that route’s middleware and handler.

This page walks from the simplest route to the patterns used in a `kona new` app: route classes, controller methods, resource controllers, groups, and named URLs.

## Simplest route

A handler is any function shaped `Request → Response`. In Kotlin that is usually a trailing lambda; in Java a lambda or method reference works the same way:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
router.get("/") { Response.text("home") }
router.post("/echo") { request -> Response.json(request.all()) }
```

</TabItem>
<TabItem label="Java">

```java
router.get("/", request -> Response.text("home"));
router.post("/echo", request -> Response.json(request.all()));
```

</TabItem>
</Tabs>

Register all routes **before** the server starts. The router is shared by every request thread and is not designed to be modified while serving traffic.

## Getting the router

`HttpServiceProvider` registers one shared `Router` in the application container. Resolve it after the application has booted — in a provider’s `boot` method, or right after `boot()` in your bootstrap code.

Applications created by `kona new` do the latter and pass the router to two route tables: `WebRoutes` (browser / HTML) and `ApiRoutes` (JSON under `/api`):

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val app = Kona.create(args)
    .providers(HttpServiceProvider(), /* … */, AppServiceProvider())
    .boot()
WebRoutes().register(app.resolve(Router::class.java))
ApiRoutes().register(app.resolve(Router::class.java))
```

</TabItem>
<TabItem label="Java">

```java
Application app = Kona.create(args)
    .providers(new HttpServiceProvider(), /* … */, new AppServiceProvider())
    .boot();
new WebRoutes().register(app.resolve(Router.class));
new ApiRoutes().register(app.resolve(Router.class));
```

</TabItem>
</Tabs>

Keeping routes in classes keeps `bootstrap.App` small and makes it obvious where to add new endpoints.

## Call a controller

Most routes point at a **controller** method instead of an inline lambda. A controller is an ordinary class with methods that take a `Request` and return a `Response`. You do **not** have to extend `Controller` unless you want the shared `validate` helpers — see [Controllers](../controllers/).

The default scaffold wires a welcome page like this:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
package routes

import app.http.controllers.WelcomeController
import dev.kona.http.Router

class WebRoutes {
    fun register(router: Router) {
        val welcome = WelcomeController()
        router.get("/") { welcome.index(it) }.name("welcome")
    }
}
```

</TabItem>
<TabItem label="Java">

```java
package routes;

import app.http.controllers.WelcomeController;
import dev.kona.http.Router;

public final class WebRoutes {
    public void register(Router router) {
        WelcomeController welcome = new WelcomeController();
        router.get("/", welcome::index).name("welcome");
    }
}
```

</TabItem>
</Tabs>

What matters for the **recommended** style:

1. **Instantiate** the controller (pass `Application` when the controller needs it).
2. **Bind** a method that accepts `Request` and returns `Response` — Kotlin `{ welcome.index(it) }`, Java `welcome::index` — so the IDE autocompletes and type-checks the action.
3. Optionally **name** the route with `.name("…")` so you can build URLs later.

Generate a stub with [`./grind make:controller Post`](../../grind/commands/#grind-makecontroller) (`--resource` adds CRUD method stubs). Put validation and response shaping in the controller; keep this file as the map from URL → action.

## Controller actions (concise alternative)

When you prefer a shorter route table, every verb also accepts a controller `Class` + method name, or a `"pkg.Controller@method"` string. The router uses the bound `Application` (set by `HttpServiceProvider`) to resolve the controller on each request.

Use this as an **optional** form. For application code, keep the typed instantiate + lambda / method-reference style above — autocomplete and navigate-to-definition stay clearer.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
router.get("/projects", ProjectController::class.java, "index")
router.post("/projects", "app.http.controllers.ProjectController@store")
router.delete("/projects/{id}", ProjectController::class.java, "destroy")
```

</TabItem>
<TabItem label="Java">

```java
router.get("/projects", ProjectController.class, "index");
router.post("/projects", "app.http.controllers.ProjectController@store");
router.delete("/projects/{id}", ProjectController.class, "destroy");
```

</TabItem>
</Tabs>

You can also build a `Handler` yourself with `Controllers.action(app, type, "index")` when the router was created without an application.

## Declaring routes

There is one registration method per common HTTP method, plus two general forms:

| Method | Matches |
|--------|---------|
| `get(uri, handler)` | `GET` (and `HEAD` via fallback — see below) |
| `post`, `put`, `patch`, `delete`, `options` | That single method |
| `any(uri, handler)` | `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE`, `OPTIONS` |
| `match(methods, uri, handler)` | Every method in `methods` (case-insensitive) |

Each call returns the new `Route`, so you can chain `.name(...)` and `.middleware(...)`.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
router.get("/") { Response.text("home") }.name("home")
router.post("/users") { users.store(it) }
router.put("/users/{id}") { users.update(it) }
router.delete("/users/{id}") { users.destroy(it) }
router.match(listOf("PUT", "PATCH"), "/profile") { profile.update(it) }
router.any("/health") { Response.text("ok") }
```

</TabItem>
<TabItem label="Java">

```java
router.get("/", request -> Response.text("home")).name("home");
router.post("/users", users::store);
router.put("/users/{id}", users::update);
router.delete("/users/{id}", users::destroy);
router.match(List.of("PUT", "PATCH"), "/profile", profile::update);
router.any("/health", request -> Response.text("ok"));
```

</TabItem>
</Tabs>

### Paths and matching order

- Leading and trailing slashes in the registered path are normalized: `"users"`, `"/users"`, and `"/users/"` all register `/users`.
- A trailing slash on the incoming path is ignored, so `/users/` matches `/users`.
- Static text must match exactly and is case-sensitive.
- Routes are checked **in registration order**, and the first match wins. Register specific routes before general ones: `/users/me` must come before `/users/{id}`, or `me` will be captured as an id.

## Path parameters

A segment written as `{name}` captures **one path segment** (anything up to the next `/`). Parameter names start with a letter or underscore and may contain letters, digits, and underscores.

Captured values are percent-decoded (`/files/a%20b` gives `a b`; a literal `+` stays `+`). If a value cannot be decoded, the raw text is used. The kernel then stores each value in the request attributes under both `name` and `route.name`. Values are always strings — convert them yourself.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
router.get("/users/{id}/posts/{slug}") { request ->
    val id = (request.getAttribute("id") as String).toLong()
    val slug = request.getAttribute("route.slug") as String
    Response.json(mapOf("user" to id, "post" to slug))
}
```

</TabItem>
<TabItem label="Java">

```java
router.get("/users/{id}/posts/{slug}", request -> {
    long id = Long.parseLong((String) request.getAttribute("id"));
    String slug = (String) request.getAttribute("route.slug");
    return Response.json(Map.of("user", id, "post", slug));
});
```

</TabItem>
</Tabs>

There are no optional parameters and no per-parameter patterns. Register a second route when a segment is optional, and check the format inside the handler (or with [validation](../validation/)).

## Resource routes

A **resource** is a collection of records exposed over a conventional set of URLs. `resource(name, controller)` registers the full set (including HTML form routes) against a `ResourceController`:

| Method(s) | Path | Controller method | Route name |
|-----------|------|-------------------|------------|
| `GET` | `/posts` | `index` | `posts.index` |
| `GET` | `/posts/create` | `create` | `posts.create` |
| `POST` | `/posts` | `store` | `posts.store` |
| `GET` | `/posts/{id}` | `show` | `posts.show` |
| `GET` | `/posts/{id}/edit` | `edit` | `posts.edit` |
| `PUT`, `PATCH` | `/posts/{id}` | `update` | `posts.update` |
| `DELETE` | `/posts/{id}` | `destroy` | `posts.destroy` |

### API resource routes

`apiResource(name, controller)` registers the same map **without** `create` / `edit` — the usual shape for JSON APIs:

| Method(s) | Path | Controller method | Route name |
|-----------|------|-------------------|------------|
| `GET` | `/posts` | `index` | `posts.index` |
| `POST` | `/posts` | `store` | `posts.store` |
| `GET` | `/posts/{id}` | `show` | `posts.show` |
| `PUT`, `PATCH` | `/posts/{id}` | `update` | `posts.update` |
| `DELETE` | `/posts/{id}` | `destroy` | `posts.destroy` |

Both accept optional `only` / `except` collections of action names, and a `Class` overload that resolves the controller from the application container.

The paths and names respect the surrounding group, so inside a group with prefix `/api` and name `api.`, you get `/api/posts` and `api.posts.index`. Pass the name **without** a leading slash.

Implement every action yourself, or extend `BaseResourceController` and override only the ones you need — the rest throw `NotFoundException` (HTTP 404).

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
class PostController : BaseResourceController() {
    override fun index(request: Request) = Response.json(posts.all())
    override fun show(request: Request) =
        Response.json(posts.find(request.getAttribute("id") as String))
    override fun store(request: Request) =
        Response.json(posts.create(request.data()), 201)
    override fun update(request: Request) =
        Response.json(posts.update(request.getAttribute("id") as String, request.data()))
    override fun destroy(request: Request): Response {
        posts.delete(request.getAttribute("id") as String)
        return Response.noContent()
    }
}

router.resource("posts", PostController())
router.apiResource("posts", PostController())
router.apiResource("notes", NotesController::class.java, only = listOf("index", "show"))
```

</TabItem>
<TabItem label="Java">

```java
public class PostController extends BaseResourceController {
    @Override public Response index(Request request) { return Response.json(posts.all()); }
    @Override public Response show(Request request) {
        return Response.json(posts.find((String) request.getAttribute("id")));
    }
    @Override public Response store(Request request) {
        return Response.json(posts.create(request.data()), 201);
    }
    @Override public Response update(Request request) {
        return Response.json(posts.update((String) request.getAttribute("id"), request.data()));
    }
    @Override public Response destroy(Request request) {
        posts.delete((String) request.getAttribute("id"));
        return Response.noContent();
    }
}

router.resource("posts", new PostController());
router.apiResource("posts", new PostController());
router.apiResource("notes", NotesController.class, List.of("index", "show"), null);
```

</TabItem>
</Tabs>

Pair JSON payloads with [API Resources](../api-resources/). Validation inside resource actions lives on [Controllers](../controllers/#resource-controllers).

## Groups

A **group** applies shared settings to every route declared inside it:

- **prefix** — prepended to each path (`/api` + `/me` → `/api/me`),
- **name** — prepended to each route name (`api.` + `me` → `api.me`),
- **middleware** — run before each route’s own middleware.

The scaffold’s `ApiRoutes` is a typical group:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
router.group(prefix = "/api", name = "api.") {
    get("/health") { Response.json(mapOf("status" to "ok")) }.name("health")
    // Full path /api/health, name api.health
}
```

</TabItem>
<TabItem label="Java">

```java
router.prefix("/api").name("api.").group(api -> {
    api.get("/health", request -> Response.json(Map.of("status", "ok"))).name("health");
});
```

</TabItem>
</Tabs>

### Nested groups and middleware

Inner groups add to outer ones: prefixes join with `/`, name prefixes concatenate, and middleware lists append (outer first). Group settings are captured when each route is registered, and they end when the group’s block returns.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
router.group(prefix = "/api", name = "api.", middleware = listOf(Authenticate())) {
    get("/me") { Response.json(mapOf("user" to it.getAttribute("user"))) }.name("me")

    group(prefix = "/admin", name = "admin.", middleware = listOf(RequireAdmin())) {
        get("/stats") { Response.json(stats()) }.name("stats")
        // /api/admin/stats, name api.admin.stats
    }
}
```

`router.routes { … }` is a small helper that runs a block with the router as `this`, useful for keeping route files tidy.

</TabItem>
<TabItem label="Java">

```java
router.prefix("/api").name("api.").middleware(new Authenticate()).group(api -> {
    api.get("/me", request -> Response.json(Map.of("user", request.getAttribute("user")))).name("me");

    api.prefix("/admin").name("admin.").middleware(new RequireAdmin()).group(admin ->
        admin.get("/stats", request -> Response.json(stats())).name("stats"));
});
```

Or pass settings positionally:

```java
router.group("/v1", v1 -> v1.get("/ping", request -> Response.text("pong")));
router.group("/v2", List.of(new Authenticate()), v2 -> { /* ... */ });
router.group("/v3", "v3.", List.of(new Authenticate()), v3 -> { /* ... */ });
```

`middleware(...)` on the fluent builder accepts either several middleware arguments or a `List`.

</TabItem>
</Tabs>

## Middleware on a route

Attach middleware to one route with `.middleware(...)`. Route middleware runs **after** any group middleware for that route.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
router.post("/webhooks/stripe") { stripe.handle(it) }
    .middleware(VerifyStripeSignature())
```

</TabItem>
<TabItem label="Java">

```java
router.post("/webhooks/stripe", stripe::handle)
    .middleware(new VerifyStripeSignature());
```

</TabItem>
</Tabs>

Global stacks (session, CSRF, and so on) are configured in `bootstrap.Middleware` and applied to the kernel — see [Middleware](../middleware/).

## Named routes and URLs

`.name("…")` gives a route a name so you can build its URL later without hard-coding the path. Group name prefixes apply automatically (`api.` + `health` → `api.health`).

`router.route(name, params)` returns the **path** with each `{key}` replaced by the matching value:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
router.get("/users/{id}") { users.show(it) }.name("users.show")

val path = router.route("users.show", mapOf("id" to "42"))   // "/users/42"
```

</TabItem>
<TabItem label="Java">

```java
router.get("/users/{id}", users::show).name("users.show");

String path = router.route("users.show", Map.of("id", "42"));  // "/users/42"
```

</TabItem>
</Tabs>

- Values are inserted as given — they are **not** percent-encoded. Encode them first if they can contain `/`, spaces, or other reserved characters.
- Placeholders without a value stay in the output as `{key}`.
- An unknown name throws `IllegalArgumentException("Route [name] not defined")`. If two routes share a name, the first one registered is used.

For absolute URLs, signed links, and the `Url` helpers, see [URL generation](../url-generation/).

When a route has a single action, implement `InvokableController` and register it as a handler:

<TabItem label="Java">

</TabItem>

## HEAD, OPTIONS, 404, and 405

The router answers several situations for you. These rules come from `Router.resolve` and the kernel:

| Request | What happens |
|---------|--------------|
| `HEAD /path`, and only `GET` is registered for it | The `GET` route runs (including its middleware). The kernel then clears the body; status and headers are kept. An explicit `HEAD` route, if registered, wins. |
| `OPTIONS /path`, no route accepts `OPTIONS`, but the path exists | Automatic `200` with an empty body and an `Allow` header listing the methods registered for that path, in registration order, comma-separated (for example `GET,HEAD,POST`). Route middleware does **not** run. |
| Path exists, method not registered | `MethodNotAllowedException` → **405** with a JSON message and header `Allow: …`. |
| No route matches the path at all | `NotFoundException` → **404** with a JSON message. |

Any `GET` registration implies `HEAD` in the `Allow` list. The 404 and 405 responses are produced by the kernel’s exception handler, so **global** middleware still wraps them; route middleware never runs because no route was selected. See [Exceptions](../exceptions/) for the envelope format.

## Inspecting routes

`router.all()` returns every registered `Route`. Each exposes `methods`, `uri`, `name`, and `middleware`. `router.find(method, path)` returns a `MatchResult` (route + captured parameters) or `null`, without throwing. `router.allowedMethods(path)` returns the methods registered for a path.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
router.all().forEach { println("${it.methods} ${it.uri} ${it.name ?: ""}") }
```

</TabItem>
<TabItem label="Java">

```java
for (Route route : router.all()) {
    System.out.println(route.getMethods() + " " + route.getUri() + " " + route.getName());
}
```

</TabItem>
</Tabs>
