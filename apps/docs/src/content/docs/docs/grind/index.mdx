**grind** is the command-line tool that lives **inside each application**. After you `cd` into a project created by `kona new`, you run:

```bash
./grind serve
./grind make:controller Post
./grind make:command SendDigest
./grind list
./grind help
```

`kona new` writes `./grind` (and `grind.bat`) into the project root. There is no global grind install. Creating applications is always:

```bash
kona new my-app
```

From anywhere under an app you can also use the global proxy: `kona grind <args…>` — see [Running commands](./running-commands/#kona-grind-proxy).

If you are browsing `samples/hello-kotlin` or `samples/hello-java` inside the Kona repository, those folders are monorepo modules and do **not** include `./grind`. Run them with `./gradlew :hello-kotlin:run` (or `:hello-java:run`) from the repo root, or create a real app with `kona new` to get grind. Details: [Installation](../guides/installation/#trying-the-repo-samples).

## Why two CLIs?

- **`kona`** (global): rare, machine-wide — “make me a new project,” or `kona grind` as a proxy.
- **`./grind`** (per app): everyday — “run *this* app,” “add a controller *here*,” “run *my* console command.”

The generated `./grind` script forwards to a Gradle `grind` task that puts `kona-grind` on the classpath for that project’s dependency versions.
