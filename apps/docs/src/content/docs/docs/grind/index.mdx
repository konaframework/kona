**grind** is the command-line tool that lives **inside each application**. After you `cd` into a project created by `kona new`, you run:

```bash
./grind serve
./grind make:controller Post
./grind help
```

`kona new` writes `./grind` (and `grind.bat`) into the project root. There is no global grind install. Creating applications is always:

```bash
kona new my-app
```

If you are browsing `samples/hello-kotlin` or `samples/hello-java` inside the Kona repository, those folders are monorepo modules and do **not** include `./grind`. Run them with `./gradlew :hello-kotlin:run` (or `:hello-java:run`) from the repo root, or create a real app with `kona new` to get grind. Details: [Installation](../guides/installation/#trying-the-repo-samples).

## Why two CLIs?

- **`kona`** (global): rare, machine-wide — “make me a new project.”
- **`./grind`** (per app): everyday — “run *this* app,” “add a controller *here*.”

The generated `./grind` script forwards to a Gradle `grind` task that puts `kona-grind` on the classpath for that project’s dependency versions.

## Commands (today)

| Command | Purpose |
|---------|---------|
| [`./grind serve`](./commands/#grind-serve) | Build and run the HTTP server |
| [`./grind make:controller`](./commands/#grind-makecontroller) | Generate a controller class |
| [`./grind make:model`](./commands/#database-commands) | Generate an Extract model (optionally with migration, factory, seeder) |
| [`./grind make:migration`](./commands/#database-commands) | Generate a migration |
| [`./grind make:factory` / `make:seeder`](./commands/#database-commands) | Generate a factory or seeder |
| [`./grind migrate`](./commands/#database-commands) | Run pending migrations (`migrate:rollback`, `migrate:reset`, `migrate:status`) |
| [`./grind db:seed`](./commands/#database-commands) | Run a seeder |
| `./grind schedule:run` / `schedule:list` | Run or list scheduled tasks |
| `./grind steam` | Interactive REPL |
| `./grind assets:vite` | Print Vite asset setup help |
| [`./grind key:generate`](./commands/#grind-keygenerate) | Set `APP_KEY` in `.env` |
| `./grind ide:lsp` | Print kona-lsp (Crema language server) setup help |
| `./grind list` | List commands |
| `./grind help` | Show usage |

Global flags: `-v` / `--verbose`, `-q` / `--quiet`. See [Console depth](./console/).

If you type `./grind new …`, grind reminds you to use `kona new` instead.
