Use **`kona install`** (or **`./grind install`** inside an app) to add a first-party or Maven package without hand-editing `build.gradle.kts` and without forgetting the service provider.

## What it does

1. Resolves a **short alias** (`inertia`, `brew`, …) or a raw `group:artifact[:version]` coordinate.
2. Ensures an `implementation("…")` line in the nearest Gradle build file (Kotlin or Groovy DSL).
3. When the package declares providers, appends their FQCNs to `src/main/resources/META-INF/kona/providers` so [Package discovery](./) registers them on boot through grind’s `AppLoader`.

## Usage

```bash
# From an app created with kona new
kona install inertia
kona install brew --version=0.1.0-SNAPSHOT
kona install com.example:widget:1.2.3

# App-local
./grind install filesystem
./grind install drip --base=/path/to/app
```

| Flag | Role |
| --- | --- |
| `--base=…` | App root (default: walk up from cwd looking for `build.gradle(.kts)`) |
| `--version=…` | Override when the alias/coordinate omits a version (default: detect a `io.konaframework:…:version` already in the build file, else the CLI’s bundled Kona version) |

## Catalog aliases

| Alias | Artifact | Auto-registered provider |
| --- | --- | --- |
| `brew` | `io.konaframework:kona-brew` | `BrewServiceProvider` |
| `inertia` | `io.konaframework:kona-inertia` | `InertiaServiceProvider` |
| `crema` | `io.konaframework:kona-crema` | `CremaServiceProvider` |
| `filesystem` | `io.konaframework:kona-filesystem` | `FilesystemServiceProvider` |
| `search` | `io.konaframework:kona-search` | `SearchServiceProvider` |
| `broadcasting` | `io.konaframework:kona-broadcasting` | `BroadcastServiceProvider` |
| `notifications` | `io.konaframework:kona-notifications` | `NotificationServiceProvider` |
| `drip` | `io.konaframework:kona-drip` | — |
| `concurrency` | `io.konaframework:kona-concurrency` | — |
| `testing` | `io.konaframework:kona-testing` | — |

Unknown short names fail with a message listing the aliases. Coordinates that match a catalog artifact still receive that artifact’s providers.

## After install

Refresh Gradle / rebuild so the new dependency is on the classpath. Providers listed in `META-INF/kona/providers` are registered when the app boots through grind (`serve`, generators, …). Manual `bootstrap.App` setups can still call `PackageDiscovery.registerAll(app)`.

## Programmatic API

The same steps are available from Kotlin/Java as `PackageInstaller.install(projectRoot, spec, defaultVersion)` in `io.konaframework.support.packages` (used by the CLI implementations).
