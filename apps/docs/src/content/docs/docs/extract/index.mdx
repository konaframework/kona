**Extract** is Kona's database layer. It lets you read and write rows in a relational database (H2, PostgreSQL, and other JDBC databases) without writing SQL by hand for everyday work, while still letting you drop down to SQL when you need it. It ships as the `dev.kona:kona-extract` artifact.

Extract has five layers. Each is usable on its own, and each builds on the one before it.

| Layer | What it gives you | Main types |
|-------|-------------------|------------|
| Connections | Named, pooled JDBC connections and transactions | `Database`, `DatabaseConnection`, `DB` |
| Query builder | Fluent `select` / `insert` / `update` / `delete` with bound parameters | `QueryBuilder` |
| Models | One class per table; each instance is one row | `Extract<T>`, `ExtractCompanion<T>` |
| Relations | Links between models, loaded lazily or eagerly | `HasOne`, `HasMany`, `BelongsTo`, `BelongsToMany` |
| Schema tooling | Migrations, seeders, and factories | `Schema`, `Migration`, `Migrator`, `Seeder`, `Factory` |

## Vocabulary

- **Connection**: A named way to reach one database: a JDBC URL, optional credentials, and a pool size. The connection called `default` is used unless you ask for another.
- **Pool**: A small set of open database connections that are reused between queries. Opening a JDBC connection is slow, so Extract keeps a pool per named connection and lends connections out for each statement. Pools open lazily, on the first query.
- **Binding**: A value sent to the database separately from the SQL text, in place of a `?` marker. Extract never pastes values into SQL strings; every value is a binding. This prevents SQL injection.
- **Model**: A Kotlin or Java class that extends `Extract<T>` and represents one table. An instance of the class is one row; its *attributes* are the row's columns.
- **Relation**: A method on a model that describes how its rows connect to another model's rows, for example "a user has many posts".
- **Eager loading**: Loading a relation for a whole list of models up front, with one extra query per relation, instead of one query per model.
- **Migration**: A class that changes the database structure (create a table, add a column) and knows how to undo that change.
- **Seeder** and **factory**: Code that fills tables with data, for development and tests.

## Configuring the database

Applications usually configure connections in `config/database.json`. Kona loads every file in `config/` at boot, under a key named after the file, so this file becomes the `database` section:

```json
{
  "default": "main",
  "connections": {
    "main": {
      "url": "jdbc:h2:file:./storage/app;DATABASE_TO_LOWER=TRUE",
      "username": "sa",
      "password": "",
      "pool_size": 10
    },
    "reports": {
      "url": "jdbc:postgresql://localhost/reports",
      "username": "reporter",
      "password": "secret"
    }
  }
}
```

| Key | Meaning | Default |
|-----|---------|---------|
| `default` | Name of the connection used when none is given | `default` |
| `connections.<name>.url` | JDBC URL (required) | — |
| `connections.<name>.username` / `password` | Credentials | none |
| `connections.<name>.driver` | JDBC driver class, when the driver does not register itself | auto |
| `connections.<name>.pool_size` | Maximum open connections in the pool | `10` |
| `connections.<name>.quote_identifiers` | Quote table and column names in generated SQL | `true` |

When the `database` section defines no connections, Extract falls back to environment variables (or `.env`): `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `DB_DRIVER`, `DB_POOL_SIZE`, and `DB_QUOTE_IDENTIFIERS`.

Add the JDBC driver for your database to your build, for example `runtimeOnly("com.h2database:h2:2.3.232")` or `runtimeOnly("org.postgresql:postgresql:42.7.4")`.

:::note[H2 and letter case]
Extract quotes table and column names (`"users"`), which makes them case-sensitive. H2 upper-cases unquoted names by default, so add `DATABASE_TO_LOWER=TRUE` to H2 URLs. With that flag, raw SQL you write by hand (`select * from users`) and the SQL Extract generates refer to the same tables.
:::

## Registering Extract in an application

`ExtractServiceProvider` builds a `Database` from the `database` config section, binds it in the container as a singleton (also under the alias `db`), and, during the boot phase, makes it the **global** database that models and the `DB` facade use.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
import dev.kona.core.Kona
import dev.kona.extract.ExtractServiceProvider
import dev.kona.http.HttpServiceProvider

val app = Kona.create(args)
    .providers(HttpServiceProvider(), ExtractServiceProvider(), AppServiceProvider())
    .boot()
```

</TabItem>
<TabItem label="Java">

```java
import dev.kona.core.Application;
import dev.kona.core.Kona;
import dev.kona.extract.ExtractServiceProvider;
import dev.kona.http.HttpServiceProvider;

Application app = Kona.create(args)
    .providers(new HttpServiceProvider(), new ExtractServiceProvider(), new AppServiceProvider())
    .boot();
```

</TabItem>
</Tabs>

Outside an application (in a script or a test) you can build the manager yourself and make it global:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
import dev.kona.extract.ConnectionConfig
import dev.kona.extract.Database

val db = Database()
    .addConnection("default", ConnectionConfig("jdbc:h2:mem:demo;DB_CLOSE_DELAY=-1;DATABASE_TO_LOWER=TRUE"))
    .setAsGlobal()
```

</TabItem>
<TabItem label="Java">

```java
import dev.kona.extract.ConnectionConfig;
import dev.kona.extract.Database;

Database db = new Database()
    .addConnection("default", new ConnectionConfig("jdbc:h2:mem:demo;DB_CLOSE_DELAY=-1;DATABASE_TO_LOWER=TRUE"))
    .setAsGlobal();
```

</TabItem>
</Tabs>

`Database` is `AutoCloseable`: `close()` shuts every open pool. A closed manager keeps its configuration and reopens pools on the next query.

## Raw SQL and transactions

The `DB` facade runs statements on the global database's default connection. Pass values as a bindings list; each `?` takes the next value.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
import dev.kona.extract.DB

val admins = DB.select("select * from users where admin = ?", listOf(true))
DB.update("update users set active = ? where id = ?", listOf(false, 7))

DB.transaction { connection ->
    connection.table("accounts").where("id", 1).decrement("balance", 50)
    connection.table("accounts").where("id", 2).increment("balance", 50)
}
```

</TabItem>
<TabItem label="Java">

```java
import dev.kona.extract.DB;
import java.util.List;
import java.util.Map;

List<Map<String, Object>> admins = DB.select("select * from users where admin = ?", List.of(true));
DB.update("update users set active = ? where id = ?", List.of(false, 7));

DB.transaction(connection -> {
    connection.table("accounts").where("id", 1).decrement("balance", 50);
    connection.table("accounts").where("id", 2).increment("balance", 50);
    return null;
});
```

</TabItem>
</Tabs>

A transaction commits when the block returns and rolls back when it throws (the exception is rethrown). Every statement issued on the same thread inside the block uses the transaction's connection, including model saves. Nested `transaction` calls join the outer one.

Failed statements throw `QueryException`, which carries the SQL (`sql`) and the bindings (`bindings`) for debugging. All Extract errors extend `ExtractException`.
