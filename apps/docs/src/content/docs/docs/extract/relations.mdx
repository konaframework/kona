import { Tabs, TabItem } from '@astrojs/starlight/components';

Tables point at each other through **foreign keys**: a `posts.user_id` column holds the `id` of the user who wrote the post. A **relation** is a model method that describes such a link, so you can write `user.posts().get()` instead of a hand-written query.

You define a relation as a **public method with no parameters**, named after the relation, that returns one of four relation types. The method name matters: eager loading finds relations by calling that method by name.

| Relation | Shape | Example | Resolves to |
|----------|-------|---------|-------------|
| `hasOne` | the other table holds our key, at most one row | user → profile | `R?` |
| `hasMany` | the other table holds our key, many rows | user → posts | `List<R>` |
| `belongsTo` | we hold the other table's key | post → user | `R?` |
| `belongsToMany` | a third (pivot) table holds both keys | user ↔ roles | `List<R>` |

## Defining relations

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
import dev.kona.extract.Extract
import dev.kona.extract.ExtractCompanion
import dev.kona.extract.relations.BelongsTo
import dev.kona.extract.relations.BelongsToMany
import dev.kona.extract.relations.HasMany
import dev.kona.extract.relations.HasOne

class User : Extract<User>() {
    fun profile(): HasOne<Profile> = hasOne(Profile::class.java)
    fun posts(): HasMany<Post> = hasMany(Post::class.java)
    fun roles(): BelongsToMany<Role> = belongsToMany(Role::class.java)

    companion object : ExtractCompanion<User>(User::class.java)
}

class Post : Extract<Post>() {
    override val fillable = setOf("title")

    fun user(): BelongsTo<User> = belongsTo(User::class.java)
    fun comments(): HasMany<Comment> = hasMany(Comment::class.java).apply { orderBy("created_at") }

    companion object : ExtractCompanion<Post>(Post::class.java)
}
```

</TabItem>
<TabItem label="Java">

```java
import dev.kona.extract.Extract;
import dev.kona.extract.ExtractCompanion;
import dev.kona.extract.relations.BelongsTo;
import dev.kona.extract.relations.BelongsToMany;
import dev.kona.extract.relations.HasMany;
import dev.kona.extract.relations.HasOne;

public class User extends Extract<User> {
    public static final ExtractCompanion<User> QUERY = Extract.of(User.class);

    public HasOne<Profile> profile() { return hasOne(Profile.class); }
    public HasMany<Post> posts() { return hasMany(Post.class); }
    public BelongsToMany<Role> roles() { return belongsToMany(Role.class); }
}

public class Post extends Extract<Post> {
    public static final ExtractCompanion<Post> QUERY = Extract.of(Post.class);

    public BelongsTo<User> user() { return belongsTo(User.class); }
    public HasMany<Comment> comments() {
        HasMany<Comment> relation = hasMany(Comment.class);
        relation.orderBy("created_at", "asc");
        return relation;
    }
}
```

</TabItem>
</Tabs>

A constraint added inside the definition (like the `orderBy` above) applies every time the relation runs, lazily or eagerly.

### Key conventions

Key names are derived from class names and primary keys. Pass explicit names when your columns differ.

| Call | Defaults | Full form |
|------|----------|-----------|
| `hasOne(Profile)` / `hasMany(Post)` | foreign key `user_id` on the related table; local key `id` | `hasMany(Post::class.java, "author_id", "id")` |
| `belongsTo(User)` | foreign key `user_id` on this table; owner key `id` on `users`; relation name `user` | `belongsTo(User::class.java, "author_id", "id", "author")` |
| `belongsToMany(Role)` | pivot table `role_user` (both snake names, sorted, joined with `_`); pivot keys `user_id` and `role_id`; parent and related keys `id` | `belongsToMany(Role::class.java, "user_roles", "user_id", "role_id", "id", "id")` |

The prefix is the snake-case class name: `BlogPost` gives `blog_post_id`.

## Lazy loading

Calling a relation method returns a fresh relation object. Nothing runs until you ask for results:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val user = User.findOrFail(1)

val posts: List<Post> = user.posts().get()
val published = user.posts().where("published", true).orderBy("created_at", "desc").get()
val profile: Profile? = user.profile().first()
val author: User? = post.user().first()
val howMany: Long = user.posts().count()
val any: Boolean = user.roles().exists()
```

</TabItem>
<TabItem label="Java">

```java
User user = User.QUERY.findOrFail(1);

List<Post> posts = user.posts().get();
List<Post> published = user.posts().where("published", true).orderBy("created_at", "desc").get();
Profile profile = user.profile().first();
User author = post.user().first();
long howMany = user.posts().count();
boolean any = user.roles().exists();
```

</TabItem>
</Tabs>

Every relation supports `get()` (all rows, also for to-one relations), `first()`, `count()`, `exists()`, `getResults()` (the natural value: a list or a single model), and the constraint helpers `where`, `orderBy`, and `constrain { builder -> … }` for anything else on the related `ModelBuilder`.

When the parent has no key yet (an unsaved model), relations return an empty list or `null` without querying.

Each call to `user.posts()` runs a new query. To keep a loaded value on the model, use `getRelationValue`: it loads the relation the first time and returns the stored value afterwards.

```kotlin
val posts = user.getRelationValue<List<Post>>("posts")   // queries
val again = user.getRelationValue<List<Post>>("posts")   // no query
```

## Eager loading

Looping over 50 users and calling `user.posts().get()` for each runs 51 queries: one for the users and one per user. This is the **N+1 problem**. Eager loading fixes it by loading the relation for all users at once: one query for the users, then **one** query for all their posts (`where user_id in (…)`), whose rows are handed out to the right users in memory.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val users = User.with("posts", "profile").get()        // 3 queries in total
for (user in users) {
    val posts = user.getRelation("posts") as List<*>   // already loaded
}

User.query().with("posts.comments").get()             // nested: users, posts, comments — 3 queries
```

</TabItem>
<TabItem label="Java">

```java
List<User> users = User.QUERY.with("posts", "profile").get();
for (User user : users) {
    List<?> posts = (List<?>) user.getRelation("posts");
}

User.QUERY.query().with("posts.comments").get();
```

</TabItem>
</Tabs>

- Names are relation method names; dots load relations of the related models (`posts.comments`, `posts.user`).
- After loading, each model has the relation stored: a list for to-many relations (empty when there are no rows) or a model / `null` for to-one relations. Read it with `getRelation(name)` or `getRelationValue(name)`; check with `relationLoaded(name)`.
- `with` works with `get()`, `first()`, `find()`, `findMany()`, and `paginate()`.
- `toMap()` includes loaded relations, rendered recursively, so `Response.json(user.toMap())` returns the user with its posts.

### Constraining an eager load

Pass a `RelationConstraint` to filter or sort what is loaded:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
import dev.kona.extract.relations.RelationConstraint

val users = User.query()
    .with("posts", RelationConstraint { it.where("published", true).orderBy("created_at", "desc") })
    .get()
```

</TabItem>
<TabItem label="Java">

```java
List<User> users = User.QUERY.query()
    .with("posts", relation -> relation.where("published", true).orderBy("created_at", "desc"))
    .get();
```

</TabItem>
</Tabs>

### Loading onto models you already have

```kotlin
user.load("posts", "roles")          // always queries, replacing loaded values
user.loadMissing("posts", "profile") // only relations not loaded yet
EagerLoader.load(users, "posts")     // a list loaded elsewhere, still one query per relation
```

Asking for a name that is not a public no-argument method returning a relation throws `ExtractException` ("Call to undefined relationship").

## Querying relationship existence

Filter parents by whether related rows exist (translated to `EXISTS` / `NOT EXISTS` subqueries):

| Call | Meaning |
|------|---------|
| `whereHas("posts")` / `has("posts")` | at least one related row |
| `whereDoesntHave("posts")` / `doesntHave("posts")` | no related rows |
| `orWhereHas` / `orWhereDoesntHave` | same checks joined with `or` |
| `whereHas("posts") { it.where("published", true) }` | existence with extra constraints on the related query |

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val authors = User.whereHas("posts") { it.where("published", true) }.get()
val newcomers = User.doesntHave("posts").get()
```

</TabItem>
<TabItem label="Java">

```java
List<User> authors = User.QUERY.whereHas("posts", q -> q.where("published", true)).get();
List<User> newcomers = User.QUERY.doesntHave("posts").get();
```

</TabItem>
</Tabs>

Works for `hasOne` / `hasMany`, `belongsTo`, and `belongsToMany` (including the pivot join).

## Counting related models

`withCount("posts")` adds a `posts_count` attribute (a subquery) without loading the related rows. Use `relation as alias` for a custom attribute name:

```kotlin
val users = User.withCount("posts", "posts as published_posts_count").get()
users[0]["posts_count"]
users[0]["published_posts_count"]

// After the fact:
user.loadCount("posts", "roles")
```

Combine with `select("users.*")` (or let `withCount` ensure a table select) when you also project specific columns.

## Writing through relations

### hasOne / hasMany

`create`, `make`, and `save` set the foreign key for you:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val post = user.posts().create(mapOf("title" to "Hello"))     // fill (fillable rules apply) + user_id + save
val draft = user.posts().make(mapOf("title" to "Draft"))      // same, unsaved
user.posts().save(Post().forceFill(mapOf("title" to "Imported")))
user.posts().createMany(listOf(mapOf("title" to "A"), mapOf("title" to "B")))
```

</TabItem>
<TabItem label="Java">

```java
Post post = user.posts().create(Map.of("title", "Hello"));
Post draft = user.posts().make(Map.of("title", "Draft"));
user.posts().save(new Post().forceFill(Map.of("title", "Imported")));
user.posts().createMany(List.of(Map.of("title", "A"), Map.of("title", "B")));
```

</TabItem>
</Tabs>

These throw `IllegalStateException` when the parent has not been saved yet (it has no key to copy).

### belongsTo

```kotlin
post.user().associate(otherUser)   // sets user_id and stores the "user" relation
post.save()
post.user().dissociate()           // sets user_id to null
post.save()
```

### belongsToMany

Pivot rows are managed with `attach`, `detach`, and `sync`. Each accepts keys or model instances.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
user.roles().attach(admin)                                   // one row
user.roles().attach(listOf(1, 2), mapOf("granted_by" to 7))  // extra pivot columns
user.roles().detach(admin)                                   // returns rows removed
user.roles().detach()                                        // remove all
val result = user.roles().sync(listOf(1, 3))                 // exactly these
result.attached   // [3]
result.detached   // [2]
user.roles().syncWithoutDetaching(listOf(4, 5))              // attach missing only
user.roles().toggle(listOf(1, 6))                            // attach missing, detach present
user.roles().updateExistingPivot(1, mapOf("granted_by" to 9))
user.roles().wherePivot("granted_by", 7).get()               // filter via pivot columns
user.roles().wherePivotIn("role_id", listOf(1, 2)).get()
```

</TabItem>
<TabItem label="Java">

```java
user.roles().attach(admin);
user.roles().attach(List.of(1, 2), Map.of("granted_by", 7));
user.roles().detach(admin);
user.roles().detach();
SyncResult result = user.roles().sync(List.of(1, 3));
result.getAttached();
result.getDetached();
user.roles().syncWithoutDetaching(List.of(4, 5));
user.roles().toggle(List.of(1, 6));
user.roles().updateExistingPivot(1, Map.of("granted_by", 9));
user.roles().wherePivot("granted_by", 7).get();
user.roles().wherePivotIn("role_id", List.of(1, 2)).get();
```

</TabItem>
</Tabs>

### Pivot data

Every model returned by a `belongsToMany` relation carries its pivot row as the `pivot` relation: a map holding the two pivot keys plus any columns named in `withPivot`. `withTimestamps()` fills `created_at` / `updated_at` on `attach` (and `updated_at` on `updateExistingPivot`) and reads them into `pivot`.

```kotlin
fun roles(): BelongsToMany<Role> = belongsToMany(Role::class.java).withPivot("granted_by").withTimestamps()

val role = user.roles().first()!!
val pivot = role.getRelation("pivot") as Map<*, *>
pivot["granted_by"]
pivot["created_at"]
```

Soft-deleted related rows are excluded from every relation unless the related query asks otherwise (`constrain { it.withTrashed() }`).
