title: Getting started with Crema

**Crema** is Kona’s server-side view engine. Templates live under `src/main/resources/views` as `*.crema.html` (or `*.crema.kt`) and use `@` directives plus `{{ }}` echoes. Crema was inspired by familiar server-side template menus; this guide describes Crema on its own terms.

## Render a view

Register `CremaServiceProvider`, then resolve `CremaEngine`:

```kotlin
val html = app.resolve(CremaEngine::class.java)
    .render("home", mapOf("name" to "Ada"))
return Response.html(html)
```

```java
String html = app.resolve(CremaEngine.class)
    .render("home", Map.of("name", "Ada"));
return Response.html(html);
```

`Crema.view(engine, name, data)` builds an HTML `Response` in one call. `View.with(...)` accumulates data before `render()` / `toResponse()`.

## Minimal template

```crema
{{-- src/main/resources/views/home.crema.html --}}
<h1>Hello {{ name }}</h1>
```

## Scaffolding

```bash
./grind make:view home
./grind make:view posts.show
```

Creates `src/main/resources/views/....crema.html`.

## Directive menu

| Area | Directives |
|------|------------|
| Echoes | `{{ }}`, `{!! !!}`, `@@`, `{{-- --}}` |
| Layouts | `@extends`, `@section` / `@endsection` / `@show`, `@yield`, `@parent`, `@hasSection`, `@sectionMissing` |
| Stacks | `@push` / `@endpush`, `@prepend` / `@endprepend`, `@stack` |
| Includes | `@include`, `@includeIf`, `@includeWhen`, `@includeUnless`, `@includeFirst`, `@once`, `@verbatim` |
| Conditionals | `@if` / `@elseif` / `@else` / `@endif`, `@unless`, `@isset`, `@empty` |
| Loops | `@while`, `@foreach` / `@each` / `@for`, `@forelse`, `loop.*` |
| Auth | `@auth`, `@guest`, `@can`, `@cannot` |
| Switch | `@switch` / `@case` / `@break` / `@default` / `@endswitch` |
| Components | `@component` / `@slot`, `<x-*>` |
| Helpers | `@json`, `@csrf`, `@method`, `@asset`, `@lang`, `@vite`, `@error` |

## Config

- Default path: `{basePath}/src/main/resources/views` (falls back to `build/resources/main/views`, then legacy `resources/views`)
- Override: `view.path` in config
- CSRF: pass `_token` or `csrf_token` in the data map for `@csrf`
- Assets: optional `asset_url` / `assetUrl` base for `@asset`
- Auth helpers: pass `__authenticated`, `auth_user`, or `user` for `@auth` / `@guest`
- Abilities: pass `__abilities` (set/list/map) or a `can` map for `@can` / `@cannot`
- Validation errors: pass an `errors` map for `@error`
- Translations: wire `Lang` via support, or pass a `lang` map in the view data
