Crema evaluates expressions against the data map you pass to `view` / `render` (and nested maps, lists, and bean-style getters). This page covers how values become HTML — escaped or raw — and the helpers that turn data into JSON, URLs, and translation strings. For making views from controllers, see the [View helper](/docs/crema/view-helper/).

## Passing data

Every render starts with a `Map<String, Any?>` (Kotlin) or `Map<String, ?>` (Java). Keys become top-level names in the template:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
view(
    "posts.show",
    mapOf(
        "title" to "Hello",
        "post" to post,
        "tags" to listOf("kona", "jvm"),
    ),
).render()
```

</TabItem>
<TabItem label="Java">

```java
Views.make(
    "posts.show",
    Map.of(
        "title", "Hello",
        "post", post,
        "tags", List.of("kona", "jvm")
    )
).render();
```

</TabItem>
</Tabs>

```crema
<h1>{{ title }}</h1>
<p>{{ post.body }}</p>
```

Nested paths use dots: `post.body` walks map keys or zero-arg getters (`getBody()`, `isActive()`, or a method/field named `body`).

`View.with(key, value)` / `with(map)` merges more keys before `render()`. Child contexts (includes, loops, components) inherit parent data and may overlay loop variables or slots.

## Escaped echoes

`{{ expr }}` prints the value as text with HTML escaping for `&`, `<`, `>`, `"`, and `'`:

```crema
<p>Hello {{ name }}</p>
{{-- name = "<script>" → Hello &lt;script&gt; --}}
```

Empty or missing values render as an empty string — not the literal `null`.

## Raw HTML

`{!! expr !!}` prints without escaping. Use only for trusted markup you built yourself (or already sanitized):

```crema
<div class="prose">{!! html !!}</div>
```

Unclosed `{!!` / `{{` sequences are errors at render time.

## Literal `@` and comments

| Syntax | Result |
|--------|--------|
| `@@` | A single `@` in the output (useful when documenting directives) |
| `{{-- … --}}` | Comment — stripped before any other processing |

```crema
{{-- Never appears in HTML --}}
<code>@@extends</code>
```

## Expressions

Echoes and most directive arguments accept a small expression language:

| Kind | Examples |
|------|----------|
| Literals | `true`, `false`, `null` / `nil`, `42`, `3.5`, `'string'`, `"string"` |
| Comparisons | `==`, `!=`, `<`, `>`, `<=`, `>=` (numbers compare numerically; otherwise stringified) |
| Logic | `and`, `or`, `not …`, `!…` |
| Helpers | `isset(name)`, `empty(name)`, `url(path)`, `route(name)`, `asset(path)`, `csrf_token()`, `old(key)`, `env(key)`, `config(key)`, `trans(key)` / `__(key)` / `lang(key)` |
| Paths | `user.name`, `errors.email` |

```crema
@if(count > 0 and ready)
  Ready
@endif

{{ isset(name) }}
{{ empty(items) }}
{{ not ok }}
{{ a == 1 or b == 2 }}
```

`isset(path)` is true when the resolved value is non-null. `empty(path)` is true when the value is not truthy (see [truthiness](/docs/crema/control-structures/#truthiness)).

There is no arbitrary code execution in templates — only this expression subset, the echo helpers below, and property access.

## Echo helpers

Call these by name inside `{{ }}` or `{!! !!}`. Arguments are ordinary Crema expressions (string literals, paths, nested helper calls). IntelliJ and kona-lsp complete the full list as you type.

Write **every** in-app URL through `url(...)` (or `route(...)` / `asset(...)`). A hardcoded `src="/branding/kona-logo.svg"` always hits the host root and ignores `APP_URL`. `kona new` starters already use the helper:

```crema
<img src="{{ url('/branding/kona-logo.svg') }}" alt="Kona" width="52" height="52" />
<a href="{{ url('/login') }}">Log in</a>
<form method="post" action="{{ url('/logout') }}">
```

| Helper | Result |
|--------|--------|
| `url(path)` | Join `path` onto the app root (`Url.url` / `APP_URL`). Absolute `http://` / `https://` values pass through. Missing generator → a rooted path (`/branding/…`). Empty path → `/`. |
| `route(name)` | Named route URL (`Url.route`). Unknown name or missing generator → a rooted path from the name. Empty name → empty string. |
| `asset(path)` | Public asset URL. Leading slashes are trimmed. Prefix with `asset_url` or `assetUrl` in the data map for a CDN; otherwise `/path`. |
| `csrf_token()` | Session CSRF token from `_token` or `csrf_token` in the data map. |
| `old(key)` / `old(key, default)` | Flashed old input from `old`, `_old_input`, or `oldInput`. |
| `env(key)` / `env(key, default)` | Environment value (`Env.get`). |
| `config(key)` | Config value from the booted application (`Kona.app().config`). Missing app or key → empty when echoed. |
| `trans(key)` / `__(key)` / `lang(key)` | Translation string (`Lang.get`). `lang` prefers a `lang` map in the view data when present. Optional second argument is a replacement map (`:name` placeholders). |

Conventional variables the engine (or your controller) may put in the data map, also offered in completion: `errors`, `user`, `auth_user`, `_token`, `asset_url`, `slot`, and `loop` / `loop.index` / `loop.iteration` / `loop.first` / `loop.last` / `loop.even` / `loop.odd` / `loop.count` / `loop.remaining` / `loop.depth` / `loop.parent`. See [Loop metadata](/docs/crema/control-structures/#loop-metadata).

```crema
{{ url('/dashboard') }}
{{ route('login') }}
{{ asset('css/app.css') }}
{{ csrf_token() }}
<input value="{{ old('email') }}" />
{{ config('app.name') }}
{{ trans('messages.welcome') }}
```

The `@asset`, `@csrf`, `@lang`, and `@json` **directives** remain available; use the echo helpers when the value belongs in an attribute or mixed markup. See [URL generation](/docs/http/url-generation/) for `Url` / `route()` / `url()` in Kotlin and Java.

## `@json`

`@json($expr)` encodes a value as JSON (Jackson). Useful inside `<script>` or data attributes:

```crema
<script>
  window.bootstrap = @json($user);
</script>
```

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
crema.render(
    "page",
    mapOf("user" to mapOf("name" to "Ada", "id" to 1)),
)
// → window.bootstrap = {"name":"Ada","id":1};
```

</TabItem>
<TabItem label="Java">

```java
crema.render(
    "page",
    Map.of("user", Map.of("name", "Ada", "id", 1))
);
// → window.bootstrap = {"name":"Ada","id":1};
```

</TabItem>
</Tabs>

## `@lang`

`@lang('key')` resolves a translation string. Crema prefers a `lang` map in the view data when present; otherwise it calls `Lang.get` from `kona-support`.

```crema
@lang('messages.welcome')
@lang('messages.hello', replace)
```

The optional second argument is an expression that evaluates to a `Map` of replacements. Placeholders in the string use `:name` form (`Hi :name` + `name → Ada` → `Hi Ada`).

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
crema.render(
    "greet",
    mapOf(
        "replace" to mapOf("name" to "Ada"),
        // or override a single key:
        // "lang" to mapOf("messages.hello" to "Hi :name"),
    ),
)
```

</TabItem>
<TabItem label="Java">

```java
crema.render(
    "greet",
    Map.of("replace", Map.of("name", "Ada"))
);
```

</TabItem>
</Tabs>

Register `SupportServiceProvider` (or call `Lang.setTranslator`) before rendering when you rely on the global translator.

## `@asset`

`@asset('css/app.css')` builds a public URL. With no base in the data map it emits `/css/app.css`. Pass `asset_url` or `assetUrl` to prefix a CDN:

```crema
<link rel="stylesheet" href="@asset('css/app.css')" />
```

Leading slashes on the path argument are trimmed before joining.

## `@vite`

`@vite('src/main/resources/js/app.js')` emits the script and stylesheet tags for that entry. Lists are supported:

```crema
@vite('src/main/resources/js/app.js')
@vite(['src/main/resources/js/app.js', 'src/main/resources/css/app.css'])
```

When `CremaServiceProvider` has bound the Vite manifest:

- **`public/hot`** (dev server origin) → Vite client plus the entry URL on that origin, for example `http://127.0.0.1:5173/src/main/resources/js/app.js`.
- **Manifest** (`public/build/manifest.json` or `public/build/.vite/manifest.json`) → hashed files such as `/build/assets/app-<hash>.js` and matching CSS.

`.css` entries become `<link rel="stylesheet">`; other entries become `<script type="module">`. Without a hot file or manifest, the directive falls back to `/build/<entry>`. That placeholder is not the file Vite serves — run `npm run dev` or `npm run build` first. See [Vite / asset bundling](/docs/assets/vite/) and [Inertia](/docs/inertia/).

## Edge cases

| Situation | Behavior |
|-----------|----------|
| Missing key in `{{ name }}` | Empty string |
| `null` / `nil` literal | Empty string when echoed |
| Nested null (`user.name` when `user` is null) | Empty string |
| Unclosed `{{` or `{!!` | Render throws |
| Map vs bean | Maps use key lookup; other objects use getters / zero-arg methods / public fields |
