## Manager `fake` and `set`

`FilesystemManager.fake(name)` mounts a temp-rooted local disk under that name and registers a simple temporary-URL builder. `set(name, adapter)` replaces any disk instance:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val files = app.resolve(FilesystemManager::class.java)
files.fake("photos")
files.disk("photos").put("a.jpg", byteArrayOf(1))

files.set("photos", FakeStorage())
```

</TabItem>
<TabItem label="Java">

```java
FilesystemManager files = app.resolve(FilesystemManager.class);
files.fake("photos");
files.disk("photos").put("a.jpg", new byte[] { 1 });

files.set("photos", new FakeStorage());
```

</TabItem>
</Tabs>

## `FakeStorage`

`dev.kona.testing.FakeStorage` is an in-memory `FilesystemAdapter` for unit tests that should not touch the filesystem. It implements the full adapter surface (streams, `putFile`, visibility, checksum, recursive listings). It does **not** support `temporaryUrl` — use `files.fake(...)` or `buildTemporaryUrlsUsing` when your code under test builds signed links.

See also [Database & fakes](../testing/database-fakes/).
