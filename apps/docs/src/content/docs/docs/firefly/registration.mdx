Generate the panel, then set the id, the brand, and the path you want. The service provider from `./grind install firefly` finds every panel class under `app/panels` and mounts it on boot.

## Generate the panel

```bash
./grind make:firefly-panel --id=billing
./grind make:firefly-page Desk --panel=billing
./grind make:firefly-resource Note --simple --panel=billing
./grind make:firefly-resource Order --panel=billing
# → NoteResource.kt / OrderResource.kt under app/panels/billing/resources/
```

Pass `--lang=java` on each command when the app is Java. `--simple` writes one Manage page. Without `--simple`, the resource command writes list, create, edit, and view pages, plus one relation manager.

The panel class looks like this. `path` is absent, so the prefix is `billing` and the Desk page is `/billing/desk`.

```kotlin
package app.panels.billing

class Panel : org.konaframework.firefly.Panel() {

        brand("Billing")
        reuseAppGuard()
        authenticate(true)
    }
}
```

The provider loads this class from `app/panels/billing/Panel.kt` (or `.java`) and then loads `pages/`, `widgets/`, and `resources/` in that same folder. The generator writes `id`, `reuseAppGuard()`, and `authenticate(true)` so `/billing/login` uses the seeded demo user. Call `authenticate(false)` only when the panel should stay open without a sign-in.

## Choose the URL prefix

Leave `path` unset and the prefix is the panel id. These three are the choices:

| Call | Prefix |
|------|--------|
| `path` omitted, id `billing` | `/billing` |
| `path("admin")` | `/admin` |
| `path("")` | the site root |

`path("admin")` and `path("/admin/")` both serve `/admin`. `path("")` and `path("/")` both serve the site root. A root panel registers each page, auth screen, and resource page by name. It does not register a catch-all.

Two panels can mount on one router when their prefixes differ. One can omit `path` and use its id. Another can call `path("admin")` or `path("")`.

## Register a panel by hand

Panels under `app/panels` do not need a manual call. When you build a panel in code, call `Firefly.register` from `app.providers.FireflyServiceProvider`. That class extends the framework provider. `register` runs before any provider boots, so the panel is mounted with the discovered ones.

`Firefly.register(Panel)` keeps that instance. `Firefly.register(Supplier<Panel>)` builds the panel when the app mounts.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
package app.providers

import org.konaframework.core.Application
import org.konaframework.firefly.Firefly
import org.konaframework.firefly.ListPage
import org.konaframework.firefly.Panel

class FireflyServiceProvider : org.konaframework.firefly.FireflyServiceProvider() {
    override fun register(app: Application) {
        super.register(app)
        Firefly.register(
            Panel().id("billing").authenticate(false).page(ListPage("orders")),
        )
        Firefly.register {
            Panel().id("ops").path("").authenticate(false).page(ListPage("home"))
        }
    }
}
```

</TabItem>
<TabItem label="Java">

```java
package app.providers;

import org.konaframework.core.Application;
import org.konaframework.firefly.Firefly;
import org.konaframework.firefly.ListPage;
import org.konaframework.firefly.Panel;

public class FireflyServiceProvider extends org.konaframework.firefly.FireflyServiceProvider {
    @Override
    public void register(Application app) {
        super.register(app);
        Firefly.register(new Panel().id("billing").authenticate(false).page(new ListPage("orders")));
        Firefly.register(() -> new Panel().id("ops").path("").authenticate(false).page(new ListPage("home")));
    }
}
```

</TabItem>
</Tabs>

The billing panel has no `path`, so orders are at `/billing/orders`. The ops panel calls `path("")`, so home is at `/home`. A class you pass to `Firefly.register` is not mounted a second time when discovery finds the same class under `app/panels`.

## What discovery loads

A missing folder is empty. A file must declare a package and a class whose name matches the file. That class must already be on the classpath and must have a no-arg constructor. Abstract classes and unrelated types are skipped.

| Folder | Loaded type |
|--------|-------------|
| `pages/` | `PanelPage` (`CustomPage`, and the list, create, edit, view, and manage pages) |
| `widgets/` | `Widget` |
| `resources/` | `Resource` |

For a generated billing panel the tree is:

```text
app/panels/billing/Panel.kt
app/panels/billing/pages/Desk.kt
app/panels/billing/widgets/Revenue.kt
app/panels/billing/resources/Note.kt
app/panels/billing/resources/Order.kt
```

Java uses the same names under `src/main/java/app/panels/billing/`.

Fields, entries, columns, filters, actions, layouts, and themes are written under `app/firefly/` (`fields/`, `entries/`, `columns/`, `filters/`, `actions/`, `layouts/`, `themes/`). Discovery does not scan those folders. Reference those classes from a page, a resource, or `theme(...)`.

You can still call `page`, `widget`, and `resource` on the panel.

Discovered widgets land on the page whose slug is empty, or on the first page when no page has an empty slug.

## The hello samples

`samples/hello-kotlin` and `samples/hello-java` still construct `app.firefly.Panel` and call `mount` after the welcome routes. Those classes call `path("admin")`, so their screens are under `/admin`. A panel you generate with `make:firefly-panel` uses its id until you set `path`.

```text
app/firefly/Panel.kt
app/firefly/pages/Desk.kt
app/firefly/widgets/DeskWidget.kt
app/firefly/resources/NoteResource.kt
app/firefly/resources/OrderResource.kt
```

With `path("admin")` the sample URLs are `/admin/desk`, `/admin/notes/manage`, and `/admin/orders/list`. Auth screens (`/login`, `/register`, `/password-reset`, `/email-verify`, `/profile`) are registered under the panel prefix even when `authenticate(false)` skips the redirect.

`mount` registers the panel’s GET and POST paths. Calling it twice on the same instance throws `FireflyException` and names the panel id. If a path is already taken, `mount` throws and names both handlers. A panel does not register `/_firefly/` or `/wire/update`.
