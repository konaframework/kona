import { Tabs, TabItem } from '@astrojs/starlight/components';

A theme is a subclass of `FireflyTheme` (`org.konaframework.firefly.support.FireflyTheme`). The panel already draws its layout: the sidebar, the top bar, the page, and the sign-in card. The theme adds CSS classes on that layout, and it can link one stylesheet. The layout stays the panel's own layout. Tailwind and Google fonts stay off until the theme turns them on.

A hook is a method on `FireflyTheme`, such as `sidebar()` or `brand()`. The method returns class names. Firefly appends those names onto one element the panel already renders. A hook that returns `""` leaves that element on the stock look.

The default theme is `KonaTheme`. The panel uses it until you pass another theme to `theme(...)`.

## Create a theme

From the app directory:

```bash
./grind make:firefly-theme MidnightTheme
```

That writes two files:

- `src/main/kotlin/app/panels/admin/themes/MidnightTheme.kt`
- `src/main/resources/css/midnighttheme.css`, the uncompiled stylesheet

`--panel=` chooses the panel package for the class. `--panel=staff` writes `src/main/kotlin/app/panels/staff/themes/MidnightTheme.kt`. The stylesheet stays `src/main/resources/css/midnighttheme.css`.

`--lang=kotlin` or `--lang=java` chooses the language of the class. `--lang=java` writes `src/main/java/app/panels/admin/themes/MidnightTheme.java`. The stylesheet is the same either way. When you omit `--lang`, Grind uses Java if the app already has a `.java` file under `src/main/java`, and Kotlin otherwise.

The class extends `FireflyTheme`. `id()` returns `midnighttheme`. `stylesheet()` returns `asset("css/midnighttheme.css")`, which names that resources file. Every hook returns `""`. `useTailwind()` is commented out. A generated theme does not load the Tailwind browser runtime.

Compile the stylesheet before you serve the panel:

```bash
./grind firefly:theme-css
```

That reads every theme stylesheet under `src/main/resources/css` (a file whose comment contains `firefly-theme`) and writes compiled CSS to `public/css/`. `./grind firefly:theme-css midnighttheme` compiles one file. Run the command again after you edit the resources file. It does not run on each request.

The browser loads `public/css/midnighttheme.css` at `/css/midnighttheme.css`. `@apply` is expanded. `var(--ff-primary)` and the other `--ff-*` tokens stay variables, so the panel color and dark mode still apply. When that compiled file is missing, Firefly falls back to the Tailwind runtime and compiles the resources file in the browser, so you can edit the source and refresh. Run `./grind firefly:theme-css` for a flicker-free compiled sheet.

## Register the theme

Call `theme(...)` on the panel and pass an instance. Return that same panel from `panel(...)`.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
package app.panels.admin

import app.panels.admin.themes.MidnightTheme
import org.konaframework.firefly.Panel as FireflyPanel

class Panel : FireflyPanel() {
    override fun panel(panel: FireflyPanel): FireflyPanel =
        panel
            .id("admin")
            .theme(MidnightTheme())
}
```

</TabItem>
<TabItem label="Java">

```java
package app.panels.admin;

import app.panels.admin.themes.MidnightTheme;

public class Panel extends org.konaframework.firefly.Panel {
    @Override
    public org.konaframework.firefly.Panel panel(org.konaframework.firefly.Panel panel) {
        return panel
            .id("admin")
            .theme(new MidnightTheme());
    }
}
```

</TabItem>
</Tabs>

The command prints the same call: `panel.theme(MidnightTheme())` in Kotlin, and `panel.theme(new MidnightTheme())` in Java.

## Style the chrome with classes

Each hook returns class names separated by spaces. Firefly appends them to the element in the table. `""` leaves the stock look.

A darker sidebar, a tighter brand, and a wider page are three places to start. The [stylesheet below](#add-a-stylesheet) defines those three classes, plus the nav hover and the sign-in card.

| Hook | Element | Example |
| --- | --- | --- |
| `panel()` | `.ff-panel` | `midnight` |
| `sidebar()` | `aside.ff-sidebar` | `midnight-sidebar` — darker sidebar |
| `topbar()` | `header.ff-topbar` | `midnight-topbar` |
| `brand()` | `.ff-sidebar-brand`, `.ff-topbar-brand`, `.ff-auth-brand` | `midnight-brand` — tighter brand |
| `navigation()` | `nav.ff-nav` | `midnight-nav` |
| `navigationItem()` | `.ff-nav-item` | `midnight-item` |
| `navigationItemActive()` | the open page (`.ff-nav-item.ff-active` that is not a group cluster) | `midnight-item-active` |
| `navigationGroup()` | `.ff-nav-group` | `midnight-group` |
| `navigationGroupActive()` | a group that contains the open page | `midnight-group-active` |
| `content()` | `main.ff-body` | `midnight-wide` — wider page |
| `pageHeader()` | `.ff-page-header` | `midnight-header` |
| `footer()` | `footer.ff-footer` | `midnight-footer` |
| `sidebarFoot()` | `.ff-sidebar-foot` | `midnight-foot` |
| `userMenu()` | `.ff-user-menu` | `midnight-user` |
| `column()` | `.ff-column` | `midnight-column` |
| `scroll()` | `.ff-scroll` | `midnight-scroll` |
| `auth()` | `body.ff-auth` | `midnight-auth` |
| `authCard()` | `.ff-auth-panel` | `midnight-card` |

`brand()` is one hook for the three brand elements, so the sidebar, the top bar, and the sign-in brand get the same classes.

`column()` matches every `.ff-column`, including table cells. Use `content()` for the page.

`navigationItem()` is every nav item. `navigationItemActive()` is only the open page. Firefly merges that class onto the active leaf and leaves group clusters alone, even when a cluster has `ff-active` because it contains the page. `navigationGroupActive()` is that group: a cluster with `ff-active`, or a sidebar group with `ff-nav-group-active`. The stylesheet targets the hook class, for example `.midnight-item-active`, and does not restate the `ff-active` selector. `ff-active` stays on the element.

## Add a stylesheet

`stylesheet()` returns either an `asset(...)` token or a URL. Firefly writes `<link rel="stylesheet" href="...">` at the end of `<head>`, after the stock `<style>` block. `null` or a blank string adds no link.

`asset("css/midnighttheme.css")` names the uncompiled source `src/main/resources/css/midnighttheme.css`. At runtime that token becomes the public URL of the compiled file, `/css/midnighttheme.css`. The link the browser receives is that public path. Compile it with `./grind firefly:theme-css`.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
override fun stylesheet(): String? = asset("css/midnighttheme.css")
```

</TabItem>
<TabItem label="Java">

```java
@Override public String stylesheet() { return asset("css/midnighttheme.css"); }
```

</TabItem>
</Tabs>

A literal path such as `/css/midnighttheme.css`, or a full `https://` URL, is linked as given. Use that when the file is already compiled, or when it is hosted elsewhere. `asset(...)` is what a generated theme uses. A missing compiled file falls back to the runtime; `./grind firefly:theme-css` writes the flicker-free sheet.

Write normal CSS. Name the `ff-*` element and the class the hook added. Stock rules use selectors such as `.ff-panel .ff-sidebar`, and the sign-in card is `.ff-auth-panel`. Write your rule at that depth so it applies. The link comes after the stock `<style>` block.

The sign-in page is `body.ff-auth`. Rules for the card and the sign-in brand use `.ff-auth`.

`extraCss()` still appends a string of CSS, wrapped in `.ff-panel { ... }`. Put sign-in rules in the linked file, where `.ff-auth` is in reach.

This theme fills the hooks from the table. The other hooks stay `""`.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
class MidnightTheme : FireflyTheme() {
    override fun id(): String = "midnighttheme"

    override fun stylesheet(): String? = asset("css/midnighttheme.css")

    override fun sidebar(): String = "midnight-sidebar"

    override fun brand(): String = "midnight-brand"

    override fun navigationItem(): String = "midnight-item"

    override fun content(): String = "midnight-wide"

    override fun authCard(): String = "midnight-card"
}
```

</TabItem>
<TabItem label="Java">

```java
public class MidnightTheme extends FireflyTheme {
    @Override public String id() { return "midnighttheme"; }

    @Override public String stylesheet() { return asset("css/midnighttheme.css"); }

    @Override public String sidebar() { return "midnight-sidebar"; }

    @Override public String brand() { return "midnight-brand"; }

    @Override public String navigationItem() { return "midnight-item"; }

    @Override public String content() { return "midnight-wide"; }

    @Override public String authCard() { return "midnight-card"; }
}
```

</TabItem>
</Tabs>

`src/main/resources/css/midnighttheme.css` is the uncompiled source. `./grind firefly:theme-css` writes `public/css/midnighttheme.css`, and that is the file the browser loads:

```css
/* Darker sidebar. Stock link color is set on the anchor. */
.ff-panel .ff-sidebar.midnight-sidebar {
  background: #1c1917;
  color: #e7e5e4;
}

.ff-panel .ff-sidebar.midnight-sidebar .ff-nav-item > a {
  color: #e7e5e4;
}

/* Tighter brand. The logo is .ff-brand-logo, the fallback mark is the
   sidebar ::before, and the name is .ff-brand. On the top bar the brand
   class sits on the mark itself. */
.ff-panel .midnight-brand .ff-brand-mark,
.ff-panel .ff-brand-mark.midnight-brand,
.ff-auth .midnight-brand .ff-brand-mark {
  gap: 0.35rem;
}

.ff-panel .ff-sidebar-brand.midnight-brand:not(.ff-sidebar-brand--logo)::before {
  width: 1.35rem;
  height: 1.35rem;
}

.ff-panel .midnight-brand .ff-brand-logo,
.ff-auth .midnight-brand .ff-brand-logo {
  height: 1.35rem;
}

.ff-panel .midnight-brand .ff-brand,
.ff-auth .midnight-brand .ff-brand {
  font-size: 1rem;
  line-height: 1.2;
}

/* Nav item hover. Cluster labels keep the stock hover. */
@media (hover: hover) {
  .ff-panel .ff-nav-item.midnight-item:not(.ff-cluster) > a:hover {
    background: #44403c;
    color: #fafaf9;
  }
}

/* Wider page. The page block inside main.ff-body is .ff-page. */
.ff-panel .ff-body.midnight-wide .ff-page {
  max-width: 90rem;
}

/* Sign-in card. */
body.ff-auth .ff-auth-panel.midnight-card {
  background: #fffbeb;
  border-color: #d6d3d1;
  box-shadow: none;
}
```

The brand rule is on `.ff-sidebar-brand`, `.ff-topbar-brand`, and `.ff-auth-brand`, because `brand()` adds `midnight-brand` to all three. The mark and the name change together, and the gap between them is `0.35rem`.

## Use Tailwind

A generated theme compiles Tailwind ahead of time. Put `@apply` in `src/main/resources/css/midnighttheme.css`, run `./grind firefly:theme-css`, and the public file has the expanded CSS. That theme leaves `useTailwind()` off. It does not load `/_firefly/tailwind.js`, and it does not hide the page while a browser compile runs. Panel colors stay `var(--ff-primary)` and the other `--ff-*` tokens, including in dark mode.

`useTailwind()` is the no-build runtime. It returns false until you override it, so a stock panel does not load Tailwind. Turn it on only when you want the browser to compile hook classes and `@apply` itself. That compile still flickers unless the page stays hidden, which Firefly does while `useTailwind()` is true. Leave it off when `stylesheet()` uses `asset(...)`.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
override fun useTailwind(): Boolean = true

override fun stylesheet(): String? = "/css/midnight.css"
```

</TabItem>
<TabItem label="Java">

```java
@Override public boolean useTailwind() { return true; }

@Override public String stylesheet() { return "/css/midnight.css"; }
```

</TabItem>
</Tabs>

The runtime fetches that URL. It is not an `asset(...)` token. Write a utility in the file the URL names with `@apply`:

```css
.ff-panel .ff-sidebar.midnight-sidebar {
  @apply bg-slate-950 text-stone-100;
}
```

Or return the same utilities from a hook. Firefly appends them to the sidebar.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
override fun sidebar(): String = "bg-slate-950 text-stone-100"
```

</TabItem>
<TabItem label="Java">

```java
@Override public String sidebar() { return "bg-slate-950 text-stone-100"; }
```

</TabItem>
</Tabs>

Restart `./grind serve`. Open the panel. The sidebar is a dark slate, and the text on it is stone.

Firefly serves a Tailwind runtime in the browser when `useTailwind()` is true and `stylesheet()` is a plain URL. That runtime reads the class attributes on the chrome. A class returned from a hook, such as `bg-slate-950`, is already on the sidebar, so the runtime generates that utility. You do not keep a safelist, and the runtime does not scan your Kotlin. It also compiles `@apply` in the file the URL names, and it loads that file for you. The document stays hidden until that compile is in the CSSOM, then it is shown. A theme that leaves `useTailwind()` false serves the runtime only when its `asset(...)` file has not been compiled yet. `useTailwind()` true stays on the runtime even when the compiled file exists.

The runtime loads Tailwind's theme and utilities. It does not load Tailwind's page reset. Start the runtime stylesheet with `@import "tailwindcss";` when you want that reset. Leave other `@import` rules out of the file while Tailwind is on. The compiled `asset(...)` path does not need that import. `./grind firefly:theme-css` adds the theme Tailwind already uses.

## Brand colors

With Tailwind on, these panel colors are scales: `primary`, `accent`, `success`, `warning`, `danger`, `info`, and `gray`. Step `500` is that color's variable. `primary-500` is `--ff-primary`. `accent-500` is `--ff-accent`. `success-500` is `--ff-success`. `warning-500` is `--ff-warning`. `danger-500` is `--ff-danger`. `info-500` is `--ff-info`. `gray-500` is `--ff-body-subtle`, the gray the chrome already uses. Steps `50`, `100`, `200`, `300`, and `400` mix that color toward white. Steps `600`, `700`, `800`, and `900` mix it toward black. `bg-primary`, `text-accent`, `text-heading`, `bg-surface`, `bg-success`, and `text-danger` use those variables as they are. Background, text, and border utilities all follow the scale: `bg-primary-50`, `text-primary-900`, `border-accent-200`.

The status colors match the hex the chrome already paints on stats, callouts, and notifications: success `#16a34a`, warning `#d97706`, danger `#dc2626`, info `#2563eb`. Set `--ff-success` (or the matching variable) on `.ff-panel` when a step-500 color should differ.

Use the scale from a hook:

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
override fun useTailwind(): Boolean = true

override fun sidebar(): String = "bg-primary-500 text-accent-700"

override fun navigationItem(): String = "text-success-500"

override fun footer(): String = "text-danger-700"
```

</TabItem>
<TabItem label="Java">

```java
@Override public boolean useTailwind() { return true; }

@Override public String sidebar() { return "bg-primary-500 text-accent-700"; }

@Override public String navigationItem() { return "text-success-500"; }

@Override public String footer() { return "text-danger-700"; }
```

</TabItem>
</Tabs>

The same classes work in the stylesheet `stylesheet()` names:

```css
.ff-panel .ff-sidebar.midnight-sidebar {
  @apply bg-primary-500 text-accent-700;
}

.ff-panel .ff-nav-item.midnight-item {
  @apply text-success-500;
}

.ff-panel .ff-footer.midnight-footer {
  @apply text-danger-700;
}
```

`primaryColor` and `accentColor` on the panel set `--ff-primary` and `--ff-accent`. The scale reads those variables, so `500` stays the brand color. Each step is also a custom property on `.ff-panel` and `.ff-auth` (`--ff-primary-500`, `--ff-accent-700`, and the rest). A later rule can replace one step. `useTailwind()` adds the scale in the page. A compiled theme stylesheet adds the same scale in the public file, so `@apply bg-primary-50` still follows the panel color after `./grind firefly:theme-css`. A theme that uses neither does not add the scale.

Dark mode follows the panel color. A panel primary stays that hue in the dark block: Firefly mixes it toward white or black (`color-mix`) and writes the shade on `--ff-primary` only there. `#FF2A00` becomes `#ff6647`, still a red-orange, not Kona's dark primary `#C9A57B`. The light `--ff-primary` stays the color the panel set. The accent follows the same rule.

Set `darkPrimary(color)` or `darkAccent(color)` on the panel when the dark color should differ from that mix. A theme does the same by overriding `darkPrimary()` or `darkAccent()`. An explicit dark color wins over the mix. Leave the override unset to derive from the panel color.

Kona's defaults apply when the panel sets nothing. `tokens().darkPrimary` (`#C9A57B` on `KonaTheme`) is that fallback for primary. It does not replace a primary the panel set. `darkSurface` and `darkHeading` are the fallback for the shell. Override `darkSurface()` or `darkHeading()` on the theme to pick a different dark surface or heading. The panel does not set those colors.

## Use a Google font

`googleFonts()` names one or more families. It returns an empty list until you override it.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
override fun googleFonts(): List<String> = listOf("Figtree", "Source Sans 3")
```

</TabItem>
<TabItem label="Java">

```java
@Override public java.util.List<String> googleFonts() {
    return java.util.List.of("Figtree", "Source Sans 3");
}
```

</TabItem>
</Tabs>

Restart `./grind serve`. The panel and the sign-in page each include a `fonts.googleapis.com` stylesheet. The link uses `display=swap` and asks for weights 400, 500, 600, and 700. Write the family name as you would say it, spaces included. A theme that names no family does not add that link.

Set the family on the panel and the sign-in page in `src/main/resources/css/midnighttheme.css`, then compile it:

```css
.ff-panel,
.ff-auth {
  font-family: "Figtree", "Source Sans 3", sans-serif;
}
```

With Tailwind on, put that `font-family` in the same file as `@apply`:

```css
.ff-panel,
.ff-auth {
  font-family: "Figtree", "Source Sans 3", sans-serif;
}

.ff-panel .ff-sidebar.midnight-sidebar {
  @apply bg-slate-950 text-stone-100;
}
```

Open the panel and the sign-in page. The type is Figtree.

## Start from the stock theme

`KonaTheme` is the stock theme. The panel uses it when you never call `theme(...)`.

Your class extends `FireflyTheme`. Every hook there returns `""`. Override only the hooks you care about. Leave the others returning `""`, or delete those empty overrides. The generated file lists every hook so the names are in front of you.

The stock palette stays until you change it. The built-in CSS reads these custom properties on `.ff-panel` and `.ff-auth`: `--ff-primary`, `--ff-accent`, `--ff-surface`, `--ff-heading`, `--ff-font`, `--ff-radius`, `--ff-sidebar-width`, `--ff-topbar-height`, and `--ff-body`. Set them in the resources stylesheet when you want different colors, type, or widths, then compile:

```css
.ff-panel,
.ff-auth {
  --ff-primary: #c2410c;
  --ff-sidebar-width: 18rem;
}
```
