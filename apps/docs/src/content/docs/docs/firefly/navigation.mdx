Decide where the links sit, then either let `mount` build the tree or write it yourself. Each panel has one layout for that tree. If you never call `item` or `cluster`, `mount` builds the tree from the pages and resources it discovered.

<FireflyShot file="section-navigation.png" description="Panel sidebar navigation." />

Every nav link shows an icon from [kona-icons](/docs/icons/) (`Icons.svg`). Set `icon("folder")` or `icon("heroicon-o-folder")` on a `NavigationItem`, `PanelPage`, or `Resource`. Short names resolve to `heroicon-o-{name}`. When unset, the dashboard home uses `heroicon-o-home` and every other item uses `heroicon-o-squares-2x2`.

On the hello samples that means a link for Desk, plus one sidebar entry each for Notes and Orders. Page labels come from the slug, so you may see `desk` until you set a label. Resource entries use `Resource.pluralLabel()` (from `label()` / `pluralLabel()`), so those links read `Notes` and `Orders` and point at the resource index (list or manage). Create, edit, and view are **page header and row actions**, not extra sidebar links.

<FireflyShot file="panel-navigation.png" description="The hello-kotlin sidebar at http://127.0.0.1:4017/admin/desk, with the desk link and one entry each for Notes and Orders." />

## Pick where the links sit

| Type | Level 1 | Levels 2 and 3 |
|------|---------|----------------|
| `NavigationType.APP` (the default) | Sidebar | Top bar, for the active level-1 item’s children |
| `NavigationType.SIDE` | Sidebar | Sidebar |
| `NavigationType.TOP` | Top bar | Top bar |

`topNavigation()` is `navigation(NavigationType.TOP)`. `navigation` accepts the enum or a closure that receives `Get`.

Nesting stops at level 3. A fourth level fails when the panel mounts, and the message names the item. `cluster("Catalog")` adds a parent with no URL of its own. `userMenu(...)` entries render inside the user-menu dropdown in the top bar. `spa(true)` adds `wire:navigate` on links that have a URL.

With `SIDE` and `APP` the brand sits in the sidebar brand block; on small screens the sidebar collapses into a drawer that the top-bar toggle opens. `TOP` keeps the brand and the whole tree in the top bar and has no sidebar or drawer.

## What the hello samples show

The samples never call `item`. Discovery therefore builds:

- A link for each page. The label is `navigationLabel()`, which is the slug. Desk’s link text is `desk`. The URL is `/admin/desk` because that panel calls `path("admin")`. When `path` is omitted, the same page is `/{id}/desk`.
- **One sidebar entry per resource.** The label is `Resource.navigationLabel()`, which defaults to `Resource.pluralLabel()` (`Notes`, `Orders`). The URL is the resource index: `/admin/notes/manage` for a simple resource, `/admin/orders/list` for a full resource. That entry stays highlighted on create, edit, and view because the panel matches the whole `/{prefix}/{resource}/…` subtree. Create / edit / view / delete are not navigation children.
- **Groups.** The samples declare **Work** (Projects, Tasks, Notes) and **Sales** (Orders, with a count badge) through `navigationGroups(...)` and `navigationGroup(...)`, so the sidebar reads as two headed sections. See [Group the sidebar](#group-the-sidebar).

Use `cluster(...)` only when you want a **manual** group (for example Catalog → Orders). Resources themselves are never auto-clustered into list/create/edit/view children.

Set `label` on a `NavigationItem` when you build the tree yourself and want a word instead of a slug.

## Group the sidebar

A flat list stops working once a panel has a dozen resources. Name a group on each resource or page, and declare the groups on the panel when you care about their order or look. Discovery keeps building the links, so no URL is written by hand and a new resource shows up on its own.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
class OrderResource : Resource("orders") {
    init {
        model(Order::class.java)
        navigationGroup("Sales")
        navigationSort(1)
        navigationLabel("Sales orders")
        navigationBadge("danger") { Order.query().where("status", "late").count() }
    }
}

class ReportsPage : PanelPage("reports") {
    init {
        navigationGroup("Accounting")
        navigationSort(10)
        shouldRegisterNavigation(true)
    }
}

val panel = Panel()
    .navigationGroups(
        NavigationGroup.make("Sales").icon("shopping-bag").collapsible(),
        NavigationGroup.make("Accounting").icon("banknotes"),
        NavigationGroup.make("Settings").icon("cog-6-tooth").collapsed(),
    )
```

</TabItem>

```java
public class OrderResource extends Resource {
    public OrderResource() {
        super("orders");
        model(Order.class);
        navigationGroup("Sales");
        navigationSort(1);
        navigationLabel("Sales orders");
        navigationBadge("danger", () -> Order.QUERY.query().where("status", "late").count());
    }
}

Panel panel = new Panel();
panel.navigationGroups(
    NavigationGroup.make("Sales").icon("shopping-bag").collapsible(),
    NavigationGroup.make("Accounting").icon("banknotes"),
    NavigationGroup.make("Settings").icon("cog-6-tooth").collapsed()
);
```

`Resource` and `PanelPage` carry the same settings. Each has a fluent setter that returns the resource or page, and a getter with the same name that you can override when the value depends on the request.

| Method | What you get |
|--------|----------------|
| `navigationGroup(name)` | The sidebar heading the link sits under. Unset links stay above the groups |
| `navigationSort(n)` | Order among siblings, lowest first. Links without a sort follow, by label |
| `navigationLabel(text)` | The link text. A resource defaults to `pluralLabel()`, a page to its slug (`Dashboard` for home) |
| `navigationBadge { value }` | Text at the end of the link, evaluated on every render. `null` or blank hides it. A `0` shows |
| `navigationBadge(color) { value }` / `navigationBadgeColor(color)` | `primary` (the default), `success`, `warning`, `danger`, `info` or `gray` |
| `shouldRegisterNavigation(false)` | No sidebar link. The routes still answer |

A blank group, label or color throws `FireflyException`.

`NavigationGroup.make(label)` declares a heading:

| Method | What you get |
|--------|----------------|
| `icon(name)` | A [kona-icons](/docs/icons/) icon beside the heading |
| `collapsible()` | The heading folds its links. It renders as a `<details>` element, so it needs no script |
| `collapsed()` | Starts folded (and collapsible). A group that holds the current page stays open |

`Panel.navigationGroups(...)` takes the groups in display order and fails when a label repeats. A group that no item names is not drawn. A group some item names but nobody declared is drawn as a plain heading after the declared ones.

The order in the sidebar is: links with no group, then each declared group, then undeclared groups in the order their first link appears.

### Hidden items and empty groups

Group and badge settings never override [authorization](/docs/firefly/authorization/). A resource whose `canViewAny()` is false, a page whose `canAccess()` is false, and anything `shouldRegisterNavigation(false)` or `visible(false)` hides, all leave the sidebar. When that empties a group, the heading goes with it, whatever the group's declaration says.

### Groups on a manual tree

`NavigationItem` takes the same settings (`group(name)`, `sort(n)`, `badge(...)`), so a hand-built tree can use headings too. Groups apply to level-1 items. Nested items ignore them.

### Groups and the navigation type

| Type | How groups render |
|------|-------------------|
| `SIDE` | A heading in the sidebar above its links |
| `APP` | Each group becomes an L1 cluster in the sidebar; the active group’s links render in the top bar (same split as nested `NavigationItem` children) |
| `TOP` | No sidebar — each group becomes a top-bar cluster that holds its links |

Ungrouped level-1 links stay in the sidebar for `APP` and `SIDE`. Clicking an APP group root opens the first link in that group.

## Build the tree yourself

Once `item` or `cluster` has been called, mount keeps that tree. It does not replace it with the discovered pages.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val catalog = panel.cluster("Catalog")
catalog.child(
    NavigationItem("orders").label("Orders").url("/admin/orders/list").icon("shopping-bag"),
)
panel.userMenu(
    NavigationItem("profile").label("Profile").url("/admin/profile").icon("user"),
)
panel.navigation(NavigationType.SIDE)
```

</TabItem>
<TabItem label="Java">

```java
NavigationItem catalog = panel.cluster("Catalog");
catalog.child(new NavigationItem("orders").label("Orders").url("/admin/orders/list").icon("shopping-bag"));
panel.userMenu(new NavigationItem("profile").label("Profile").url("/admin/profile").icon("user"));
panel.navigation(NavigationType.SIDE);
```

</TabItem>
</Tabs>

You see **Orders** in the sidebar, linking to `/admin/orders/list`, and **Profile** inside the user menu.

## Methods on NavigationItem

A blank name throws `FireflyException` (`Navigation item name is blank`). A blank label or a blank URL from a closure throws and names the item.

| Method | What you get |
|--------|----------------|
| `label(value)` / `label(provider)` | Visible text. The default is the name |
| `url(value)` / `url(provider)` | Link target. Empty until you set it |
| `icon(value)` / `icon(provider)` | kona-icons name (short or `heroicon-o-…`). Unset → home / squares-2x2 default |
| `extraAttributes(map)` / `extraAttributes(provider)` | HTML attributes on the link. A provider receives `Get` |
| `cluster(true)` | Marks the node as a cluster (a parent with no URL) |
| `group(name)` / `sort(n)` / `badge(...)` | Sidebar heading, order and badge. See [Group the sidebar](#group-the-sidebar) |
| `child(item)` | Appends a child and sets its depth |
| `isCluster()` | Whether `cluster(true)` was set |
| `labelText(get)` / `urlText(get)` / `attributes(get)` / `iconName(get)` | Resolves the closure or the stored value |
| `find(name)` | This node or a descendant with that name |

`PanelPage.icon(...)` and `Resource.icon(...)` feed the auto-built tree the same way (as do the `navigation*` settings above) when you leave discovery to mount the sidebar.

Active state: the current path equals the item URL, or starts with that URL plus `/`. An empty URL or `/` is never treated as a prefix match.

## The user menu and signed-in footer

The top bar ends with a tools cluster: a theme toggle, a notifications bell, and the user menu. The user menu shows an avatar (the first letter or digit of the signed-in identifier) and that identifier. Opening it reveals the identifier again, a **Signed in as …** line, a **Profile** link, your `userMenu(...)` entries, and — when someone is signed in — a **Sign out** form that posts to the profile route.

The panel guard’s id is the identifier. When it is null the menu and the sidebar footer read **Guest**, and no sign-out form is shown. The hello samples call `authenticate(false)` and do not sign anyone in, so they read Guest.

On `SIDE` and `APP` panels the sidebar also ends with a **Signed in as _identifier_** footer (`.ff-sidebar-foot`), matching the identifier in the menu. That block and the main-column `.ff-footer` share the shell background, type, soft top border, and fixed `--ff-footer-height` so they read as one bottom chrome band even when one side has no text.
