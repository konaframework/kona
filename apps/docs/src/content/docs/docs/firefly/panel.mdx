Set the id, the URL prefix, and the brand, then call `mount`. The file in your app is `app/firefly/Panel`. The class it extends is `org.konaframework.firefly.Panel`.

The module does not register routes until you call `mount`. Chrome, the sidebar and the top bar, is a second class with the same simple name, `org.konaframework.firefly.support.Panel`. That one is on [Panel chrome](/docs/firefly/chrome/). The class you write is the one in `org.konaframework.firefly`.

<FireflyShot file="desk-panel.png" description="The hello-kotlin panel at http://127.0.0.1:4017/admin/desk, with the sidebar and the Desk page in the body." />

Chainable setters accept a static value or a closure. The closure receives the schema `Get`. A blank id, brand, domain, or guard name throws `FireflyException` and names the field.

## Mount a panel

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val panel = Panel()
    .id("desk")
    .path("admin")
    .brand("Desk")
    .navigation(NavigationType.APP)
    .page(ListPage("orders"))
panel.mount(router)
```

</TabItem>
<TabItem label="Java">

```java
Panel panel = new Panel();
panel.id("desk");
panel.path("admin");
panel.brand("Desk");
panel.navigation(NavigationType.APP);
panel.page(new ListPage("orders"));
panel.mount(router);
```

</TabItem>
</Tabs>

`path("admin")` and `path("/admin/")` both serve `/admin`. `path("")` and `path("/")` serve the site root. A root panel registers each page, auth screen, and resource page by name. It does not register a catch-all.

If a path is already routed, `mount` throws `FireflyException` and names both handlers. Two panels can mount on one router, one at `path("")` and one at `path("admin")`. `domain("ops.example")` rejects a request whose `Host` header does not match, including when the header includes a port.

`mount(router, state)` evaluates closures against that state map. A second `mount` throws `Panel [id] is already mounted`.

## Methods you will call

| Method | What you get |
|--------|----------------|
| `id` / `path` / `brand` / `domain` | String or `Get` closure. Id defaults to `admin`. Path defaults to `admin`. Brand defaults to `Firefly` |
| `navigation` / `topNavigation()` | `NavigationType`. Default `APP`. See [Navigation](/docs/firefly/navigation/) |
| `theme(FireflyTheme)` | Tokens and partials. Default `KonaTheme`. See [Themes and CSS](/docs/firefly/themes/) |
| `layout(PanelLayout)` | Replaces the shell arrangement |
| `hook(Hook, html)` | Appends HTML into a chrome hook |
| `spa(true)` | Adds `wire:navigate` on links that have a URL |
| `authenticate(false)` | Pages skip the login redirect. The hello samples do this |
| `guard` / `useAuthGuard` / `reuseAppGuard` | Who is signed in. See below |
| `item` / `cluster` / `userMenu` | Navigation tree. See [Navigation](/docs/firefly/navigation/) |
| `page` / `resource` / `widget` | Register one instance without discovery |
| `discover(path)` | Load `pages/`, `widgets/`, and `resources/`. See [Register a panel](/docs/firefly/registration/) |
| `tenant` | Adds a tenant link. See [Tenancy](/docs/firefly/tenancy/) |
| `plugin` | Calls `register` immediately. `boot` runs inside `mount`. See [Plugins](/docs/firefly/plugins/) |
| `mount(router)` | Registers routes |
| `render(request)` | The chrome for a request, without a page body |
| `guardName()` | `firefly-{id}`, or the name you passed to `reuseAppGuard` |

## Sign-in and the guard

The panel guard is `firefly-{id}` unless you call `reuseAppGuard()` (the application guard name `web`) or `reuseAppGuard("name")`. `useAuthGuard(guard)` adapts an application `Guard`. Until you do that, the panel keeps its own `MemoryPanelGuard` and leaves the application’s login and session in place.

The screens are `/login`, `/register`, `/password-reset`, `/email-verify`, and `/profile`, under the panel prefix. Pages require that guard unless you call `authenticate(false)`. Login and registration read `email` and `password` (registration also reads `name`). A missing field returns 422 HTML. A failed attempt returns 422 HTML and the message `Those credentials do not match`.

When the guard has no id, the user chip reads **Guest**.

## Pick a theme and a hook

`theme(HarborTheme())` selects the sample theme shipped on the panel artifact: a different primary color, a sidebar partial that keeps the hook markers, and a small extra stylesheet under `.ff-panel`. `hook(Hook.BODY_END, "...")` still injects into the shell. The support `Panel` applies the theme, the layout, and the hooks. Read [Panel chrome](/docs/firefly/chrome/) for slots and partials.

## Generate the class

```bash
./grind make:firefly-panel
./grind make:firefly-panel --lang=java --id=desk --path=admin
./grind firefly:install
./grind make:firefly-theme Harbor
./grind firefly:publish
```

`make:firefly-panel` and `firefly:install` write `Panel` plus empty `pages/`, `widgets/`, and `resources/` folders. The generated class sets `id` and `path` only. `firefly:publish` copies the sidebar partial into `resources/views/firefly/sidebar.crema.html` so you can edit it. Keep the hook markers in that partial, or `render` throws.
