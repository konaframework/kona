Build the tree for a screen, fill the state map, and call `render()`. Sections, text, fields, and buttons all sit in that tree. Live pieces bind with `wire:model` and `@entangle`.

Use a schema when a screen is more than one control. On the Desk page the form is a name field, a status field, and a due field. The types live in `org.konaframework.firefly.schemas` (`kona-firefly-schemas`).

<FireflyShot file="schema-section.png" description="The Desk form at http://127.0.0.1:4017/admin/desk, a schema of the name, status, and due fields." />

## Build one and render it

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val schema = Schema.make()
    .statePath("user")
    .components(
        Section.make("Profile").schema(
            Text.make("Hello"),
        ),
    )
schema.hydrate()
val html = schema.render()
```

</TabItem>
<TabItem label="Java">

```java
Schema schema = Schema.make()
    .statePath("user")
    .components(Section.make("Profile").schema(Text.make("Hello")));
schema.hydrate();
String html = schema.render();
```

</TabItem>
</Tabs>

`Schema.make()` starts an empty tree. `statePath("user")` prefixes every root component, so a field named `name` is stored at `user.name`. `components(...)` replaces the root list and binds each component to the schema. `hydrate()` writes defaults into missing paths. `render()` returns a `<div class="ff-schema">`. You see the Profile section and the text Hello.

`get` and `set` use dotted paths. `set` returns the partial-render keys for that update. A component that called `live()`, `liveOnBlur()`, or `liveDebounce(...)` contributes its own path.

## Pass a value or a closure

Most chainable setters accept a fixed value or a closure. The closure receives `Get`, the same reader the schema uses inside `afterStateUpdated`. `Get.get` resolves a path relative to the component’s container. A path that starts with `/` is absolute.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
val section = Section.make("Profile")
section.label("Title")
section.label { get -> if (get.get("/kind") == "org") "Organization" else "Title" }
section.description { get -> "About ${get.get("/kind")}" }
section.columns { 2 }
section.hidden { get -> get.get("/draft") == true }
```

</TabItem>
<TabItem label="Java">

```java
name.label(get -> "From Java");
details.columns(get -> 2);
Text.make("Hello").content(get -> "Hello");
```

</TabItem>
</Tabs>

The last call wins. `label("Title")` after a closure stores the fixed string and drops the closure. The same shape is on `heading`, `description`, `hidden`, `visible`, `disabled`, `columnSpan`, `columns`, `maxWidth`, `content`, `size`, `url`, `alt`, `imageHeight`, and `imageWidth`.

### Max width (`xl` and friends)

`maxWidth("xl")` (or a closure that returns a token) stores the value on the component and renders `data-ff-max-width="xl"` on its root. The panel stylesheet maps those tokens to CSS variables:

| Token | CSS variable | Width |
|-------|--------------|-------|
| `xs` … `7xl` | `--ff-width-xs` … `--ff-width-7xl` | `20rem` … `80rem` (Tailwind-compatible) |
| `xl` | `--ff-width-xl` | `36rem` |
| `full` / `screen` / `prose` | — | `100%` / `100vw` / `65ch` |

Create, edit, and view pages also constrain the direct `.ff-schema` / `.ff-infolist` child of `.ff-page-content` to `--ff-width-xl`, with `width: 100%` and horizontal auto margins so the column stays centered when the shell is wider. That page rule is CSS-only; call `maxWidth(...)` on a section or entry when one component inside the page should use a different token.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
Section.make("Details").maxWidth("xl").schema(
    Text.make("Name on file"),
)
Section.make("Wide").maxWidth("4xl").schema(
    Text.make("Longer copy"),
)
```

</TabItem>
<TabItem label="Java">

```java
Section.make("Details").maxWidth("xl").schema(
    Text.make("Name on file")
);
Section.make("Wide").maxWidth("4xl").schema(
    Text.make("Longer copy")
);
```

</TabItem>
</Tabs>

`extraAttributes` merges HTML attributes onto the component root. Layouts, primes, actions, infolist entries, table columns, and form fields all have it. Pass a map or a closure. A name that is not an HTML attribute name is skipped. Values are escaped.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
Section.make().extraAttributes(mapOf("data-section" to "intro"))
Text.make("note").extraAttributes { mapOf("data-kind" to "note") }
```

</TabItem>
<TabItem label="Java">

```java
Section.make().extraAttributes(Map.of("data-section", "intro"));
Text.make("note").extraAttributes(get -> Map.of("data-kind", "note"));
```

</TabItem>
</Tabs>

`hidden(true)` and `visible(false)` still take a boolean. `hidden { ... }` and `visible { ... }` recompute when the schema renders or when `isHidden` runs.

## Read and write state

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
schema.fill(mapOf("user.city" to "Kona"))
schema.get("user.city") // "Kona"
```

</TabItem>
<TabItem label="Java">

```java
schema.fill(Map.of("user.city", "Kona"));
schema.get("user.city"); // "Kona"
```

</TabItem>
</Tabs>

Inside a component under `statePath("user")`:

| Call | Result |
|------|--------|
| `get("name")` | the sibling at `user.name` |
| `get("../name")` | still `user.name` — `..` does not leave the schema prefix |
| `get("/user.city")` | absolute read |
| `get(".")`, `get("..")`, `get("")` | `null` |

`defaultValue("Ada")` writes that literal during `hydrate()` when the path is empty. `defaultUsing { get -> get.get("../name") }` writes the closure’s result. A second `hydrate()` leaves an existing value in place.

`dehydrate()` returns a map of paths that should be saved. A hidden component is omitted unless `dehydratedWhenHidden(true)`. `dehydrated(false)` omits the component even when it is visible.

`afterStateUpdated` runs after `set` when the path matches a component. The hook receives the new value, the old value, `Get`, and `Set`. `set.set("slug", "bea", false)` writes a sibling and skips that sibling’s update hook.

## Lay the screen out

Reach for a layout when one field after another is not enough. A section, a grid, tabs, or a wizard is still a schema component. The Desk page stacks a form, an infolist, and a table in the body.

<FireflyShot file="schema-layout.png" description="The Desk page body at http://127.0.0.1:4017/admin/desk, with the form, the name infolist, and the notes table one after another." />

| Type | What you call |
|------|----------------|
| `Grid.make(columns)` | Column grid. `schema(...)` sets the children |
| `Flex.make()` | Row of children |
| `Fieldset.make(legend)` | Group with a legend. `required(true)` marks it |
| `Section.make()` / `Section.make(heading)` | Optional heading and description; slots `afterHeader`, `beforeLabel`, `afterLabel`, `aboveContent`, `belowContent`, `footer`. `columns(N)` lays children in an N-column grid and stays chainable into `.schema(...)`. `collapsible()` / `collapsed()` use a details/summary body. `contained(false)` / `card(false)` skip the card chrome when the host is already a card. `aside(true)` and `formBefore(true)` add data attributes |
| `Schema.make().columns(N)` | Root grid for top-level components (same `--ff-cols` / `data-ff-columns` treatment as sections) |
| `Tabs.make()` | `tabs(...)`, `activeTab`, `vertical`, `scrollable`, `persistTabInQueryString` |
| `Tab.make(label)` | One panel. `badge`, `badgeIcon`, `deferBadge` |
| `Wizard.make()` | `steps(...)`, `nextStep`, `previousStep`, `goToStep`. `skippable(true)` allows a jump |
| `WizardStep.make(label)` | One step. `icon`, `completedIcon`, `formWrapper` |
| `Callout.make(heading)` | `info()`, `success()`, `warning()`, `danger()`, or `status(...)`. `color` overrides the status color |
| `EmptyState.make(heading)` | Heading plus an optional `footer` |

`configureUsing` on a layout runs for every later `make()` of that class. Pass `null` to clear it.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
Section.configureUsing { it.aside(true) }
```

</TabItem>
<TabItem label="Java">

```java
Section.configureUsing(section -> { section.aside(true); });
```

</TabItem>
</Tabs>

Heading level starts at 2. `rootHeadingLevel` changes the start. Nested sections increment it, and the level stops at 6.

## Text, icons, images, and lists

`Text.make(content)` renders a paragraph. `content`, `size`, `badge(true)`, and `js()` change it. `SchemaIcon.make("home")` inlines an icon from the support set (`home`, `bars`, `user`, `x`). `Image.make(url)` takes `alt`, `url`, `imageHeight`, `imageWidth`, and `imageSize`. `UnorderedList.make("one", "two")` renders the items. `items { listOf("Kona") }` replaces them at render time.

## Bind a field so it updates live

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
field.live()
field.liveOnBlur()
field.liveDebounce(400)
field.reactive()   // same binding as live()
field.lazy()       // same binding as liveOnBlur()
```

</TabItem>
<TabItem label="Java">

```java
field.live();
field.liveOnBlur();
field.liveDebounce(400);
field.reactive();
field.lazy();
```

</TabItem>
</Tabs>

`live()` renders `wire:model.live`. `liveOnBlur()` and `lazy()` render `wire:model.blur`. `liveDebounce(400)` renders `wire:model.live.debounce.400ms`. Each also sets `data-ff-entangle="@entangle(path)"`. `afterStateUpdatedJs("watch")` stores the expression on `data-ff-updated-js`. The page does not evaluate that string on the server.

`hiddenJs` and `visibleJs` store browser expressions the same way.

## Write your own component

Subclass `Component`. The constructor name is the state key. Put the class where the page or resource can reference it. `discover` does not scan a layouts folder.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
class Banner(name: String) : Component(name)
```

</TabItem>
<TabItem label="Java">

```java
public class NameField extends Component {
    public NameField() { super("name"); }
}
```

</TabItem>
</Tabs>

`view("notes.banner")` renders that Crema view when `Schema.crema(engine)` is set. The view receives `path`, `content`, and `label`. Without an engine, render emits `<div data-ff-view="notes.banner">`.

```bash
./grind make:firefly-layout Banner
```

The command writes a layout class and a Crema view under `app/firefly/layouts`. `--lang=java` writes a Java class. The view uses `x-data="ffField"` and `@entangle`.

## Alpine factories

`AlpineScripts.source()` is the script that registers `ffField`, `ffEntry`, `ffColumn`, and `ffAction`. Those factories entangle state with `$wire.$entangle` and call server actions with `$wire.$call`. Register that script on the Alpine instance the page already started.

## Defer a heavy schema

`deferLoading(true)` makes `render()` return a loading placeholder until `loadDeferred()`. The schema needs `key(...)`. A deferred schema with no key throws `FireflyException` (`Deferred schema is missing a key`).

## What you add on another page

Inputs such as a select or a date picker are on [Forms](/docs/firefly/forms/). Buttons and confirmation dialogs are on [Actions](/docs/firefly/actions/). This module is the tree and the state those pieces sit on.
