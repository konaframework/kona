Open `samples/hello-kotlin` or `samples/hello-java` and click through the panel. Those classes call `path("admin")`, so the screens are under `/admin`. A panel from `make:firefly-panel` uses its id as the prefix until you set `path`. Notes are a simple resource: one Manage page, and create, edit, view, and delete open in a dialog. Orders are a full resource: list, create, edit, and view are their own URLs, and line items sit on the edit and view pages.

From the Kona repository root, run `./gradlew :hello-kotlin:run` or `./gradlew :hello-java:run`. The app listens on `127.0.0.1` and port `4000` unless `HOST` or `PORT` is set. Then open the routes in the table at the bottom of this page.

## Add the simple notes resource

Put the class in `app/firefly/resources/NoteResource`. `simple()` keeps a single `ManagePage`. The slug is `notes`, so the route is `/admin/notes/manage`. Override `form`, `infolist`, and `table`. The page calls them when it renders. The table is one in-memory row (`Ada`), so the screen renders before a migration. `model(Note::class.java)` is the Cadence type `query()` uses when you build the table from the model instead of `Table.memory`.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
class NoteResource : Resource("notes") {
    init {
        label("Notes")
        simple()
        model(Note::class.java)
    }

    override fun form(schema: Schema): Schema = schema.components(
        TextInput.make("name"),
        Select.make("status").options(mapOf("open" to "Open", "done" to "Done")),
        DateTimePicker.make("due"),
    )

    override fun infolist(schema: Schema): Schema =
        schema.components(TextEntry.make("name"))

    override fun table(table: Table<*, *>): Table<*, *> =
        Table.memory(mapOf("id" to "1", "name" to "Ada")).columns(TextColumn.make("name"))
}
```

</TabItem>
<TabItem label="Java">

```java
public class NoteResource extends Resource {
    public NoteResource() {
        super("notes");
        label("Notes");
        simple();
        model(Note.class);
    }

    @Override
    public Schema form(Schema schema) {
        return schema.components(
            TextInput.make("name"),
            Select.make("status").options(Map.of("open", "Open", "done", "Done")),
            DateTimePicker.make("due")
        );
    }

    @Override
    public Schema infolist(Schema schema) {
        return schema.components(TextEntry.make("name"));
    }

    @Override
    public Table<?, ?> table(Table<?, ?> table) {
        return Table.memory(row()).columns(TextColumn.make("name"));
    }
}
```

</TabItem>
</Tabs>

The Java sample builds `row()` as a `LinkedHashMap` with `id` `1` and `name` `Ada`. `Select` draws a combobox. `DateTimePicker` draws Firefly’s own date and time control. Both are on [Forms](/docs/firefly/forms/).

Create, edit, and view put that schema or infolist in the shared dialog. Delete asks for confirmation in the same dialog. A simple resource rejects `relation(...)`.

Generate the same shape from a standalone app:

```bash
./grind make:firefly-resource Note --simple
./grind make:firefly-resource Note --simple --lang=java
```

That writes `NoteResource` (model name `Note`, no double suffix if you pass `NoteResource`) and `note/pages/ManageNote`. The generator writes `simple()`, overrides for the form, infolist, and table, a text field named `name`, `model(app.models.Note.class)`, and `getPages()` returning `ManageNote()`. Create that Cadence model before the project compiles. The generator’s table calls `columns` on an empty `Table.memory()` and has no seed row.

## Add the full orders resource

Leave `simple()` off. Override `getPages()` with list, create, edit, and view. The sidebar shows one **Orders** entry pointing at the list. The list page mounts the table, a **New** header action linking to create, and View / Edit / Delete row actions. Create and edit mount the form (with Save / Cancel header actions). View mounts the infolist. Edit and view also render each relation manager.

Put the class in `app/firefly/resources/OrderResource`.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
class OrderResource : Resource("orders") {
    init {
        label("Orders")
        model(Order::class.java)
        relation(
            RelationManager("lines")
                .related(Line::class.java)
                .titleAttribute("sku")
                .table(Table.memory(mapOf("id" to "1", "sku" to "A")).columns(TextColumn.make("sku"))),
        )
    }

    override fun form(schema: Schema): Schema =
        schema.components(TextInput.make("name"))

    override fun infolist(schema: Schema): Schema =
        schema.components(TextEntry.make("name"))

    override fun table(table: Table<*, *>): Table<*, *> =
        Table.memory(mapOf("id" to "1", "name" to "Ada")).columns(TextColumn.make("name"))

    override fun getPages(): Map<String, Page> = mapOf(
        "list" to ListPage("list"),
        "create" to CreatePage("create"),
        "edit" to EditPage("edit"),
        "view" to ViewPage("view"),
    )
}
```

</TabItem>
<TabItem label="Java">

```java
public class OrderResource extends Resource {
    public OrderResource() {
        super("orders");
        label("Orders");
        model(Order.class);
        relation(new RelationManager("lines")
            .related(Line.class)
            .titleAttribute("sku")
            .table(Table.memory(lineRow()).columns(TextColumn.make("sku"))));
    }

    @Override
    public Schema form(Schema schema) {
        return schema.components(TextInput.make("name"));
    }

    @Override
    public Schema infolist(Schema schema) {
        return schema.components(TextEntry.make("name"));
    }

    @Override
    public Table<?, ?> table(Table<?, ?> table) {
        return Table.memory(orderRow()).columns(TextColumn.make("name"));
    }

    @Override
    public Map<String, Page> getPages() {
        Map<String, Page> pages = new LinkedHashMap<>();
        pages.put("list", new ListPage("list"));
        pages.put("create", new CreatePage("create"));
        pages.put("edit", new EditPage("edit"));
        pages.put("view", new ViewPage("view"));
        return pages;
    }
}
```

</TabItem>

## Open the Desk page

<FireflyShot file="desk.png" description="The Desk page at http://127.0.0.1:4017/admin/desk, with the name field, the status combobox, the due picker, the infolist, the table, and the Edit header action." />

`app/firefly/pages/Desk` is a `CustomPage` with the same form fields as notes, an infolist, a one-row table, and a header action that opens a dialog. `app/firefly/widgets/DeskWidget` renders a short paragraph. Discovery places that widget on the first page, which is Desk.

```bash
./grind make:firefly-page Desk
./grind make:firefly-widget Desk
```

## Routes that respond

On the hello samples these GET routes return 200:

| Route | Page |
|-------|------|
| `/` | The welcome route, outside the panel |
| `/admin/desk` | Desk |
| `/admin/notes/manage` | Notes |
| `/admin/orders/list` | Orders list |
| `/admin/orders/create` | Orders create |
| `/admin/orders/edit` | Orders edit |
| `/admin/orders/view` | Orders view |

## What you will see in the browser

A few things on that sample are unfinished in the browser. Check these before you debug your own app:

- Dialog markup is in the page, and the dialog stays closed until Alpine opens it. Create, edit, view, and delete on the notes page do not pop open from the first HTML response alone.
- `@entangle(...)` can still appear as raw text when the Alpine binding has not run.
- Navigation labels for pages come from the page slug. The Desk link can read `desk` until you override it. Each resource contributes **one** sidebar entry from `label()` (`Notes`, `Orders`), pointing at manage or list — not create/edit/view children.
- The sample calls `authenticate(false)`. The user chip reads **Guest** when the panel guard has no signed-in id.
