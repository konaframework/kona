Add one class per record type, put it in the panel’s `resources/` folder, and discovery serves it. Bind a model, a form, an infolist, and a table on that class.

Call `simple()` when you want one Manage page. Leave it off when you want list, create, edit, and view as their own URLs. The hello samples use both. The click-through is on [A working app](/docs/firefly/working-app/). This page is the method list.

The sidebar gets **one entry per resource** (the list or manage page). Create, edit, view, and delete are page-header and row actions — never separate sidebar links. See [Navigation](/docs/firefly/navigation/).

The types live in `org.konaframework.firefly` (`kona-firefly`).

## Serve a full resource

Put the class in `app/panels/{panel}/resources/` (or the discovered `resources/` beside your panel class). Override `form`, `infolist`, `table`, and `getPages`. Leave `getPages()` alone and a full resource serves list, create, edit, and view.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
class OrderResource : Resource("orders") {
    init {
        label("Orders")
        model(Order::class.java)
        relation(RelationManager("lines").related(Line::class.java).titleAttribute("sku"))
    }

    override fun form(schema: Schema): Schema =
        schema.components(TextInput.make("name"))

    override fun infolist(schema: Schema): Schema =
        schema.components(TextEntry.make("name"))

    override fun table(table: Table<*, *>): Table<*, *> =
        table.columns(TextColumn.make("name"))

    override fun getPages(): Map<String, Page> = mapOf(
        "list" to ListPage("list"),
        "create" to CreatePage("create"),
        "edit" to EditPage("edit"),
        "view" to ViewPage("view"),
    )
}
```

</TabItem>
<TabItem label="Java">

```java
public class OrderResource extends Resource {
    public OrderResource() {
        super("orders");
        label("Orders");
        model(Order.class);
        relation(new RelationManager("lines").related(Line.class).titleAttribute("sku"));
    }

    @Override
    public Schema form(Schema schema) {
        return schema.components(TextInput.make("name"));
    }

    @Override
    public Schema infolist(Schema schema) {
        return schema.components(TextEntry.make("name"));
    }

    @Override
    public Table<?, ?> table(Table<?, ?> table) {
        return Table.memory().columns(TextColumn.make("name"));
    }

    @Override
    public Map<String, Page> getPages() {
        Map<String, Page> pages = new LinkedHashMap<>();
        pages.put("list", new ListPage("list"));
        pages.put("create", new CreatePage("create"));
        pages.put("edit", new EditPage("edit"));
        pages.put("view", new ViewPage("view"));
        return pages;
    }
}
```

</TabItem>
</Tabs>

The page calls `form`, `table`, and `infolist` when it renders, so those methods can read the current tenant and `schema.record()`. The list page mounts the table, a **New** header action that links to the create page, and row actions (View, Edit, Delete). The create page mounts the form plus Create / Cancel header actions. The edit page mounts the form, relation managers, and Save / View / Cancel / Delete. The view page mounts the infolist, relation managers, and Edit / Back to list / Delete. You open `/{prefix}/orders/list`. The prefix is the panel id when `path` is not set. The hello samples call `path("admin")`, so that URL is `/admin/orders/list`. The sidebar shows one **Orders** link to that list URL and keeps it active on create, edit, and view.

`query()` chooses the store from the model type. A Cadence model returns a `ModelBuilder`. A document model fails and names `kona-firefly-document`, which is not part of this release. Any other type fails and tells you to use `Table.memory` for custom rows.

## Serve a simple resource

<FireflyShot file="notes-manage.png" description="The notes Manage page at http://127.0.0.1:4017/admin/notes/manage, with the notes table and the Create, Edit, View, and Delete actions." />

`simple()` keeps one `ManagePage`. You still override `form`, `infolist`, and `table`. You do not override `getPages()`. Create, edit, view, and delete are header actions, and each one opens the existing dialog. Create and edit put the form schema in that dialog. View puts the infolist in it. Delete asks for confirmation in it. A simple resource rejects `relation(...)`.

The route is `/{prefix}/notes/manage` when the slug is `notes` and the page slug is `manage`. The hello samples use the prefix `admin`. You see the notes table and the Create, Edit, View, and Delete actions.

## Generate one

`./grind make:firefly-resource Order` treats `Order` as the **model** name and writes `app/panels/admin/resources/OrderResource.kt` (or `.java`) with overrides for the form, infolist, table, and `getPages()`, plus one relation manager. Passing `OrderResource` already does not double-suffix. `./grind make:firefly-resource Note --simple` writes the same schema overrides, calls `simple()`, and does not override `getPages()` or write a relation manager. Pass `--panel=billing` to write into another panel directory. The generated class calls `model(app.models.Order::class.java)`. Create that Cadence model, then let the panel discover the resource directory.

The hello samples mount a desk panel at `/admin` with a custom page, a widget, a simple note resource, and a full order resource.

## What you build with

| Type | Role |
|------|------|
| `Resource` | Model, form, infolist, table, actions, and pages |
| `RelationManager` | Related records on a full resource's edit and view pages. Set the label column with `titleAttribute` |
| `ManagePage` | The single page of a simple resource |
| `query()` | `ModelBuilder` for a Cadence model |
