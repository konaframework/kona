## HTTP

`HttpTestClient` resolves `HttpKernel` from the booted app and runs requests without opening a socket.

```kotlin
val http = HttpTestClient(app)
http.get("/ping").assertOk().assertJsonContains("ok")
http.postJson("/users", mapOf("name" to "Ada")).assertStatus(201)
```

Available assertions:

| Method | Behavior |
|--------|----------|
| `assertStatus(code)` | Exact status |
| `assertOk()` | Status `200` |
| `assertJsonContains(fragment)` | Body contains the substring |
| `status()` / `body()` | Raw values for custom asserts |

Register routes in a provider `boot` method (or after boot) before calling the client.

## Console (grind)

`ConsoleTester` runs grind and captures stdout:

```kotlin
ConsoleTester()
    .run("list")
    .assertOk()
    .assertExit(0)
    .assertSee("schedule:run")
    .assertDontSee("missing-command")
```

| Method | Behavior |
|--------|----------|
| `assertOk()` | Exit code `0` |
| `assertExit(code)` | Exact exit code |
| `assertSee(text)` | Stdout contains substring |
| `assertDontSee(text)` | Stdout does not contain substring |

Pass the same flags you would on the CLI (`--base=…`, `--bootstrap=…`, `-q`, and so on). For custom commands, compile the app first so discovery can see `META-INF/kona/commands`. See [Creating commands](../../grind/creating-commands/) and [Running commands](../../grind/running-commands/).
