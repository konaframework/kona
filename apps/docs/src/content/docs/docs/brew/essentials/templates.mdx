Brew renders HTML through **Crema**. Each component must produce a **single root element**. Brew stamps `wire:snapshot`, `wire:effects`, `wire:id`, and `wire:name` onto that root.

## Rendering paths

1. `template()` — inline Crema on the class  
2. `render()` → `view("brew.todos", data)` or `inline(source, data)`  
3. Convention file `src/main/resources/views/brew/<name>.crema.html` when both are absent  

Inside templates, public properties and `@Computed` methods are in scope as Crema data.

### IDE support for inline `template()`

Crema highlighting and completion work on `*.crema.html` files and **inside inline strings**.

**IntelliJ IDEA** (Kona Idea plugin) injects Crema into `Component.template()`, into the `source` parameter of `Component.inline` / `BrewView.inline` (`@CremaTemplate`), and into any string preceded by `// language=Crema`.

**Cursor / VS Code** (vscode-crema extension): TextMate injections color Crema inside Java/Kotlin `template()` text blocks, `inline(` arguments, and `language=Crema` strings. Attach **kona-lsp** with document languages `crema`, `java`, and `kotlin` for `@` directive, `wire:*`, and `{{` member completion in those same ranges. Reload the window after installing or updating the extension.

```kotlin
override fun template(): String =
    // language=Crema
    """
        <div>
            <p>Count: {{ count }}</p>
            <button type="button" wire:click="decrement">-</button>
            <button type="button" wire:click="increment">+</button>
        </div>
    """.trimIndent()
```

Java text blocks work the same way — see `samples/brew-java` `Counter.template()`. You do not need the language comment when the method is `template()` or the call is `inline(`.

## Tags and directives

| Surface | Example |
|---------|---------|
| Tag | `<brew:counter :start="1" />` |
| Directive | `@brew('counter', ['start' => 1])` |
| Styles placeholder | `@brewStyles` |
| Scripts | `@brewScripts` |
| Script config only | `@brewScriptConfig` (for manual ESM bundling) |
| JS encode | `@js($value)` |

When `brew.inject_assets` is true, responses that look like full HTML documents get styles + scripts injected automatically if those directives are missing.

## Assets and routes

| URL | Content |
|-----|---------|
| `/brew/brew.js` | Readable bundle |
| `/brew/brew.min.js` | Minified (+ source map) |

Script tags include a cache-busting `?id=` hash, `data-csrf`, and `data-update-uri="/brew/update"`. Override paths with `Brew.setUpdateRoute` / `Brew.setScriptRoute` when you need a custom mount point (`brew.path` still names the default).

From Kotlin/Java:

```kotlin
Brew.styles()
Brew.scripts()
Brew.scriptConfig()
```

## Morph markers

With `brew.inject_morph_markers` (default true), Crema wraps conditionals and loops in HTML comment markers so the keyed morph can add/remove blocks without tearing sibling DOM. Prefer `wire:key` on list items:

```crema
@foreach(items as item)
    <li wire:key="item-{{ item.id }}">{{ item.title }}</li>
@endforeach
```

## Layout tips

- Keep interactive UI inside the component root; Brew morphs that subtree.  
- Use `wire:ignore` (`.self` / `.children`) for islands Brew must not touch (third-party widgets).  
- `wire:replace` forces a full replace instead of a morph when needed.

## Example page

```crema
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="utf-8">
    <title>{{ title }}</title>
    @brewStyles
</head>
<body>
    <h1>{{ title }}</h1>
    <brew:counter :start="3" />
    <brew:todos />
    @brew('search')
    @brewScripts
</body>
</html>
```
