Forms in Brew keep values on the **server component**. `wire:model` syncs inputs into public properties; `wire:submit` runs an action without a full page navigation.

## Model binding

```html
<input type="text" wire:model="email" />
<textarea wire:model="bio"></textarea>
<input type="checkbox" wire:model="agree" />
<select wire:model="country">…</select>
```

Supported controls: text, textarea, checkbox (boolean or array), radio, select (single/multiple), number, date.

## Modifiers

| Modifier | Behaviour |
|----------|-----------|
| (default) | Sync on `change` / blur-equivalent deferral used by the runtime |
| `.live` | Sync on every input event (coalesced on the request bus) |
| `.blur` | Sync when the field blurs |
| `.change` | Sync on `change` |
| `.lazy` | Alias-style deferred sync |
| `.debounce` / `.debounce.500ms` | Debounce updates |
| `.throttle` / `.throttle.500ms` | Throttle updates |
| `.number` | Cast to number |
| `.boolean` | Cast to boolean |
| `.fill` | Initial fill behaviour for certain controls |
| `.self` | Only events from the element itself |
| `.deep` | Deep watch for nested objects |

```html
<input wire:model.live="query" />
<input wire:model.blur="email" />
<input wire:model.number="age" />
<input wire:model.debounce.500ms="search" />
```

Nested paths:

```html
<input wire:model="todos.0.title" />
```

## Submit

```html
<form wire:submit="save">
    …
</form>
```

`wire:submit` implies `.prevent` so the browser does not navigate. Combine with live models for “type and save” UIs.

## Real-time hooks

Property writes from `wire:model` fire `updating` / `updated` / `updatedFoo` lifecycle hooks—use them for derived state or side effects while the user types. See [Lifecycle](/docs/brew/lifecycle/).

## Validation (later guide)

Server-side `Form` objects, `@Validate` / `rules()`, error bags, and `$errors` ship in a later Brew milestone. Until then, validate inside actions and surface messages as ordinary properties.
