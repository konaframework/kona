title: Config & env
description: Nested configuration, file loading, and environment variable precedence.
---

Configuration answers questions like “what is the app name?” and “is debug mode on?” without hard-coding those answers in every class. Kona splits that into **environment** (process / `.env`) and **config** (structured values, often loaded from files).

## Environment (`Env`)

On startup, Kona can load a `.env` file from the application base path. Lines support quotes, optional `export` prefixes, and `#` comments.

**Precedence:** values already present in the real process environment **override** `.env`. That way CI and production can inject secrets without committing them.

`APP_DEBUG` defaults to **false** when unset. Accepted truthy forms include `true`, `1`, `yes`, and `on`.

## Config object

`Config` stores nested maps. You address values with **dotted keys**:

```kotlin
config.set("app.name", "Demo")
config.set("app.debug", false)

val name = config.getString("app.name", "Kona")
val debug = config.getBoolean("app.debug", false)
```

```java
config.set("app.name", "Demo");
String name = config.getString("app.name", "Kona");
boolean debug = config.getBoolean("app.debug", false);
```

- `get("app")` returns the nested map under `app` when present.
- `has("app.name")` checks a dotted path.
- `all()` returns a deep copy of the tree.
- Typed getters: `getString`, `getInt`, `getBoolean`, each with nullable and default-taking overloads. Non-string values stringify via `toString()` when read as strings.

## Loading files

```kotlin
config.load(basePath.resolve("config/app.properties"))
config.load(basePath.resolve("config/app.json"))
config.loadDirectory(basePath.resolve("config"))
```

- **`.properties`** — flat keys; dots become nesting when loaded.
- **JSON** — root must be an object; nested objects map to nested config.
- **`loadDirectory`** — each supported file becomes a top-level key named after the file stem (`app.json` → `app.*`).

`Kona.create` loads `config/` automatically when the directory exists, before your builder `configure` callbacks run, so callbacks can override file defaults.
