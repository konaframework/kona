Forms in Wire keep values on the **server component**. `wire:model` syncs inputs into public properties; `wire:submit` runs an action without a full page navigation. Validation, form objects, and UI directives (`wire:loading`, `wire:dirty`, …) round out the slice.

## Model binding

```html
<input type="text" wire:model="email" />
<textarea wire:model="bio"></textarea>
<input type="checkbox" wire:model="agree" />
<select wire:model="country">…</select>
```

Supported controls: text, textarea, checkbox (boolean or array), radio, select (single/multiple), number, date. Custom Alpine controls work when they declare `x-modelable` — `wire:model` binds through Alpine’s `x-model`.

## Modifiers

| Modifier | Behaviour |
|----------|-----------|
| (default) | Sync on `change` / blur-equivalent deferral used by the runtime |
| `.live` | Sync on every input event (coalesced on the request bus) |
| `.blur` | Sync when the field blurs |
| `.change` | Sync on `change` |
| `.lazy` | Alias-style deferred sync |
| `.debounce` / `.debounce.500ms` | Debounce updates |
| `.throttle` / `.throttle.500ms` | Throttle updates |
| `.number` | Cast to number |
| `.boolean` | Cast to boolean |
| `.fill` | Initial fill behaviour for certain controls |
| `.self` | Only events from the element itself |
| `.deep` | Deep watch for nested objects |

```html
<input wire:model.live="query" />
<input wire:model.blur="email" />
<input wire:model.number="age" />
<input wire:model.debounce.500ms="search" />
```

## Submit

```html
<form wire:submit="save">
    …
</form>
```

`wire:submit` implies `.prevent`. While the request is in flight, Wire disables submit buttons / selects and marks text inputs read-only, then restores them when the response finishes.

Confirm before running an action:

```html
<button wire:click="delete" wire:confirm="Delete this post?">Delete</button>
<button wire:click="wipe" wire:confirm.prompt="Type DELETE|DELETE">Wipe</button>
```

## Validation

Annotate properties with `@Validate` (or the `@Rule` alias), override `rules()` / `messages()` / `validationAttributes()`, and call `validate()` / `validateOnly()` from actions. Failures fill an `ErrorBag` that is persisted in `memo.errors`, exposed to Crema as `errors`, and available in JS as `$wire.$errors`.

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
class Profile : Component() {
    @Validate("required", "email")
    var email = ""

    override fun rules() = mapOf(
        "email" to listOf("required", "email", Rules.unique("users", "email").ignore(id).toString()),
    )

    fun save() {
        validate()
        // persist…
    }

    override fun template() = """
        <form wire:submit="save">
            <input type="email" wire:model="email" />
            @if(errors['email'])
                <em>{{ errors['email'][0] }}</em>
            @endif
            <button type="submit">Save</button>
        </form>
    """.trimIndent()
}
```

Real-time: properties with `@Validate(onUpdate = true)` (the default) re-validate when `wire:model` updates them. Use `onUpdate = false` to wait for an explicit `validate()` call.

### Form objects

A form object is a class that extends `Form` and holds one form's fields, rules, and helpers. Put it on the component as a public property. Wire constructs the form when that property is null and the class has a public constructor with no arguments. `wire:model` paths are prefixed with the property name (`form.title`); rules inside the form stay local (`title`).

```bash
./grind make:form PostForm
./grind make:form PostForm --lang=java
```

<Tabs syncKey="lang">
<TabItem label="Kotlin">

```kotlin
import org.konaframework.wire.Component
import org.konaframework.wire.Form
import org.konaframework.wire.Validate

class PostForm : Form() {
    @Validate("required", "min:5")
    var title: String = ""

    @Validate("required", "min:5")
    var content: String = ""

    fun store(): Map<String, Any?> {
        val saved = validate()
        reset()
        return saved
    }
}

class CreatePost : Component() {
    var form = PostForm()

    fun save() {
        form.store()
    }

    override fun template() = """
        <form wire:submit="save">
            <input wire:model.blur="form.title" />
            @if(errors['form.title'])
                <em>{{ errors['form.title'][0] }}</em>
            @endif
            <textarea wire:model="form.content"></textarea>
            <button type="submit">Save</button>
        </form>
    """.trimIndent()
}
```

</TabItem>

```java
import org.konaframework.wire.Component;
import org.konaframework.wire.Form;
import org.konaframework.wire.Validate;
import java.util.Map;

public class PostForm extends Form {
    @Validate({"required", "min:5"})
    public String title = "";

    @Validate({"required", "min:5"})
    public String content = "";

    public Map<String, Object> store() {
        Map<String, Object> saved = validate();
        reset();
        return saved;
    }
}

public class CreatePost extends Component {
    public PostForm form;

    public void save() {
        form.store();
    }

    @Override
    public String template() {
        return """
            <form wire:submit="save">
                <input wire:model.blur="form.title" />
                <textarea wire:model="form.content"></textarea>
                <button type="submit">Save</button>
            </form>
            """;
    }
}
```

`component.validate()` and `component.validateOnly("form.title")` include the form's rules, prefixed with the property name. `form.validate()` and `form.validateOnly("title")` run the same rules and return the local field names.

| Method | Role |
|--------|------|
| `fill` / `all` / `only` / `except` | Copy values in or out. Unknown keys in `fill` are ignored |
| `reset` / `resetExcept` | Restore fields to the values on a fresh instance. `reset()` and `reset(emptyList())` restore every field; pass names or a collection to limit which ones |
| `pull` / `pull("title")` / `pull("title", "content")` | Read, then reset. No arguments returns every field |
| `rules` | Merged with `@Validate` / `@Rule`. `rules()` replaces the same key. `messages()` and `validationAttributes()` are overridable maps on the form |
| `addError` / `getErrorBag` / `resetErrorBag` / `resetValidation` | Errors are stored on the component under `form.title` |
| `component` / `getComponent` / `getPropertyName` | The owning component and the property name (`form`) |
| `withValidator` | Runs the callback with the `Validator` before `validate` |
| `boot` / `hydrate` / `dehydrate` / `updating` / `updated` | Lifecycle hooks. `updating` / `updated` receive the path inside the form (`title`) |

Real-time checks run only for fields annotated with `@Validate` or `@Rule` whose `onUpdate` is true (the default). A field that exists only in `rules()` waits until you call `validate()` or `validateOnly()`. `onUpdate = false` keeps the annotation rules but skips the update check.

`@Validate` and `@Rule` accept a pipe (`"required|min:5"`) or separate arguments. Both annotations may appear on one field; their rules are combined and the last annotation decides `onUpdate`.

### Error bag helpers

| API | Role |
|-----|------|
| `addError` / `resetValidation` / `resetErrorBag` | Mutate the bag |
| `getErrorBag` / `setErrorBag` | Replace / read |
| `$wire.$errors.has` / `first` / `get` / `all` / `clear` | Browser-side MessageBag shape |

`Wire.test(…).assertHasErrors("email").assertHasNoErrors("name")` covers the testing surface.

## Loading, dirty, and offline UI

```html
<button wire:click="save">Save</button>
<span wire:loading wire:target="save">Saving…</span>
<span wire:dirty wire:target="title">Unsaved</span>
<span wire:offline>You are offline</span>
```

- `wire:loading` (+ `.class` / `.attr` / `.remove` / `.delay.*` / display modifiers) toggles while a matching request is in flight. `wire:target` / `wire:target.except` scope it; requesting elements also get `data-loading="true"`.
- `wire:dirty` reflects ephemeral vs server-confirmed state; `$wire.$dirty()` / `$wire.$dirty('title')` for expressions.
- `wire:offline` follows the browser online/offline events.
- `wire:poll.5s` / `.keep-alive` / `.visible` refreshes on an interval.

## Show, text, bind, cloak, ref, transition

```html
<div wire:cloak>…</div>
<div wire:show="open">…</div>
<span wire:text="label"></span>
<a wire:bind:href="url">Link</a>
<input wire:ref="email" />
<div wire:transition="panel">…</div>
```

`$wire.$refs.email` (or `$wire.$refs('email')`) returns the element. `@Transition(type = "forward")` on an action (or `$this.transition("forward")` / `skipTransition()`) emits `effects.transition` for the View Transitions API during morph.
