---
title: Notifications
description: Notify users over mail, database, and log channels.
---

Implement `Notifiable` (routing per channel) and `Notification` (`via`, `toMail`, `toArray`), then send through `NotificationSender`.

## Quick start

```kotlin
class InvoicePaid : Notification() {
    override fun via(notifiable: Notifiable) = listOf("mail", "database", "log")
    override fun toMail(notifiable: Notifiable) = object : Mailable() { /* … */ }
    override fun toArray(notifiable: Notifiable) = mapOf("status" to "paid")
}

app.resolve(NotificationSender::class.java).send(user, InvoicePaid())
```

Register `MailServiceProvider` then `NotificationServiceProvider`. Channels: `mail` (needs `Mailer`), `database`, `log`.

## Database channel persistence

By default `DatabaseChannel` keeps rows in memory for the process lifetime. Set `notifications.database.path` to a JSON file (absolute, or relative to the application base path) so rows are written to disk and reloaded on the next boot:

```kotlin
app.config.set("notifications.database.path", "storage/notifications.json")
app.register(NotificationServiceProvider())
```

You can also construct `DatabaseChannel(path)` directly in tests without the provider.
