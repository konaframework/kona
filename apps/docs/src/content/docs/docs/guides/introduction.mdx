**Kona** is a full-stack web framework for the JVM. You write application code in **Kotlin** or **Java** (or both). The framework itself is implemented in Kotlin; every public API is designed so Java call sites stay natural—no Kotlin-only ceremony required to boot an app, register routes, or resolve services.

Kona takes inspiration from productive application frameworks in other ecosystems (notably Laravel and Almasix). From here on, these docs describe **Kona on its own terms**: its names, boot sequence, HTTP stack, and tooling.

## What you get

A typical Kona app:

1. **Boots** an `Application` with configuration and registered *service providers*.
2. **Routes** HTTP requests through a kernel that can run middleware, match a route, validate input, and return a response.
3. **Uses grind**, the command-line tool, to scaffold projects, generate classes, and run the development server.

Named pieces you will see across the docs:

| Name | Role |
|------|------|
| **Kona** | Framework core: application, container, config, HTTP |
| **grind** | Command-line interface (scaffold, serve, generators) |
| **steam** | Interactive REPL inside a booted app (later milestone) |
| **Extract** | Database models and query layer (later milestone) |
| **Crema** | Server-side templates (later milestone) |
| **drip** | Outbound HTTP client (later milestone) |

```text
./grind | ./grind steam | Extract | *.crema.html | Kona.create(args).boot()
```

## Design choices worth knowing up front

- **JDK 21+.** Request handling is built around Virtual Threads, not a coroutine-first HTTP model.
- **Compose, don’t embed.** Kona uses libraries (HTTP server, JSON, logging, connection pools) directly. It is not a thin skin over Spring, Quarkus, or Micronaut.
- **Providers and a container.** You register bindings and boot-time setup in small provider classes. The container resolves dependencies by type, including constructor injection when a type is not explicitly bound.
- **One CLI.** Day-to-day scaffolding and `serve` go through **grind**.

## How to read these docs

Guides assume you already program and understand HTTP at a high level (methods, status codes, JSON bodies). They do **not** assume you already know Kona’s vocabulary—each concept is introduced when you need it.
