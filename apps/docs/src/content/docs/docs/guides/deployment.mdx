description: Ship a Kona app with a start script, environment variables, migrations, and a process manager — systemd, Docker, or any platform that sets PORT.

This page is the **production runbook** for an app created with `kona new`. Local development stays on [Your first app](../first-app/) (`./grind serve`). Production is a different launcher.

**What you are deploying:** one long-lived JVM process. It boots `bootstrap.App` and listens on `HOST`:`PORT` (default `127.0.0.1:4000`). There is no separate application server to install. Put TLS and the public hostname on a reverse proxy or your platform’s load balancer.

## The recipe

Do this on every release. Substitute `hello-kona` with the directory name you passed to `kona new` (`rootProject.name`).

```bash
# 1. On a machine with JDK 21 (CI or the server)
cd hello-kona
./gradlew installDist

# Vite / Inertia / Brew kits only:
# npm ci && npm run build

# 2. Production environment (process env or a file your supervisor loads)
export APP_ENV=production
export APP_DEBUG=false
export APP_URL=https://app.example.com
export APP_KEY=base64:…          # secret — never commit
export HOST=127.0.0.1            # 0.0.0.0 in Docker / most PaaS
export PORT=4000                 # or the PORT your platform injects
export DB_URL='jdbc:postgresql://db.internal:5432/kona'
export DB_USERNAME=kona
export DB_PASSWORD=…

# 3. Writable runtime dirs + schema
mkdir -p storage/logs storage/framework storage/app/public storage/database
./grind migrate

# 4. Start the app process — not ./grind serve
./build/install/hello-kona/bin/hello-kona
```

Probe it:

```bash
curl -fsS http://127.0.0.1:4000/api/health
# {"status":"ok"}
```

That is the whole model. The sections below are copy-paste for VMs, containers, CI, and a reverse proxy.

## Local vs production

| | Local | Production |
|---|--------|------------|
| Command | `./grind serve` | `build/install/<app>/bin/<app>` after `./gradlew installDist` |
| `APP_ENV` | `local` | `production` |
| `APP_DEBUG` | `true` | `false` |
| Database | SQLite file under `storage/` (scaffold default) | PostgreSQL, MySQL, MariaDB, SQL Server, or Oracle — not SQLite/H2 |
| Process manager | your terminal | systemd, Docker, or the platform |
| TLS | optional | reverse proxy / load balancer |

`./grind` remains the tool for **one-off ops** on a checkout (`migrate`, `key:generate`). It is not the HTTP process you supervise.

## 1. Build the start script

From the application directory (JDK 21+):

```bash
./gradlew installDist
```

Output:

```text
build/install/hello-kona/
  bin/hello-kona       # Unix
  bin/hello-kona.bat   # Windows
  lib/                 # app JAR + dependencies
```

That tree is **not** the whole app. The process still needs a **base directory** that contains `public/`, `storage/`, and (optionally) `.env`. Easiest layout on a VM: keep the git checkout as the working directory and run the script from there.

```bash
cd /var/www/hello-kona
export APP_ENV=production APP_DEBUG=false
./build/install/hello-kona/bin/hello-kona
```

Ship a zip instead:

```bash
./gradlew distZip
# → build/distributions/hello-kona-<version>.zip
```

Unpack on the host, copy `public/` and an empty `storage/` next to `bin/` / `lib/`, and start with that folder as the working directory — or pass the folder explicitly:

```bash
./bin/hello-kona --base=/var/www/hello-kona
```

`Kona.create` reads `--base=/absolute/path` before it falls back to the current working directory.

`./gradlew run` starts the same `main`. Use it only if CI already built the release and you accept a Gradle JVM in the process tree. Prefer `installDist` on long-lived machines.

## 2. Environment variables

The process environment wins over a `.env` file. In production, inject variables from systemd, Docker, or your platform. If you keep a file on the server, do not commit it.

| Variable | Production | Notes |
|----------|------------|--------|
| `APP_ENV` | `production` | Required for production behavior |
| `APP_DEBUG` | `false` | Turns off exception pages |
| `APP_KEY` | `base64:…` | Encryption / signed cookies. Create with `./grind key:generate` on a trusted machine, then store the value in your secret manager |
| `APP_URL` | `https://app.example.com` | Public URL used in links |
| `HOST` | `127.0.0.1` behind a local proxy; `0.0.0.0` in Docker / PaaS | Bind address |
| `PORT` | `4000` or the platform’s `PORT` | Listen port |
| `DB_CONNECTION` | `pgsql`, `mysql`, … | Must match `config/Database` |
| `DB_URL` | JDBC URL | Example: `jdbc:postgresql://db:5432/kona` |
| `DB_USERNAME` / `DB_PASSWORD` | credentials | Prefer secrets, not git |
| `LOG_LEVEL` | `info` | |
| `LOG_TO_FILE` | `true` on VMs with disk; `false` when the platform captures stdout | |

Generate a key (writes `APP_KEY` into `.env` unless you copy it out yourself):

```bash
./grind key:generate
./grind key:generate --force    # production, key already set
```

## 3. Database and migrations

Point `DB_URL` at a real server database. Run migrations **before** or **as** you start the new process, from a checkout that still has `./grind`:

```bash
export DB_URL='jdbc:postgresql://db.internal:5432/kona'
export DB_USERNAME=kona
export DB_PASSWORD=…
./grind migrate
```

Typical splits:

- **VM:** deploy the git tree, run `./gradlew installDist`, then `./grind migrate`, then restart the start script.
- **Container / immutable image:** run `./grind migrate` in CI or as an init job against the production database, then roll out the image that only contains `bin/` + `lib/` + `public/` + `storage/`.

Ensure `storage/` is writable by the service user:

```bash
mkdir -p storage/logs storage/framework storage/app/public
chown -R kona:kona storage
```

Engine list and JDBC URLs: [Database](../../cadence/database/).

## 4. systemd (VM)

`/etc/kona/hello-kona.env` (mode `0600`, not in git):

```bash
APP_ENV=production
APP_DEBUG=false
APP_URL=https://app.example.com
APP_KEY=base64:…
HOST=127.0.0.1
PORT=4000
DB_URL=jdbc:postgresql://127.0.0.1:5432/kona
DB_USERNAME=kona
DB_PASSWORD=…
```

`/etc/systemd/system/hello-kona.service`:

```ini
[Unit]
Description=Kona hello-kona
After=network.target postgresql.service

[Service]
Type=simple
User=kona
Group=kona
WorkingDirectory=/var/www/hello-kona
EnvironmentFile=/etc/kona/hello-kona.env
ExecStart=/var/www/hello-kona/build/install/hello-kona/bin/hello-kona
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now hello-kona
sudo systemctl status hello-kona
curl -fsS http://127.0.0.1:4000/api/health
```

## 5. Docker

There is no published Kona runtime image. Use a two-stage build in **the app repo**. Replace `hello-kona` with `rootProject.name`.

```dockerfile
# syntax=docker/dockerfile:1
FROM eclipse-temurin:21-jdk AS build
WORKDIR /src
COPY . .
RUN ./gradlew installDist --no-daemon

FROM eclipse-temurin:21-jre
WORKDIR /app
COPY --from=build /src/build/install/hello-kona/ /app/
COPY --from=build /src/public /app/public
RUN mkdir -p /app/storage/logs /app/storage/framework /app/storage/app/public \
    && chown -R 65534:65534 /app/storage
ENV HOST=0.0.0.0 PORT=4000 APP_ENV=production APP_DEBUG=false LOG_TO_FILE=false
EXPOSE 4000
USER 65534:65534
CMD ["/app/bin/hello-kona", "--base=/app"]
```

```bash
docker build -t hello-kona:latest .
docker run --rm -p 4000:4000 \
  -e APP_KEY=base64:… \
  -e APP_URL=https://app.example.com \
  -e DB_URL=jdbc:postgresql://db:5432/kona \
  -e DB_USERNAME=kona \
  -e DB_PASSWORD=… \
  hello-kona:latest
```

Mount a volume on `/app/storage` if you need logs or local disks to survive restarts. Run `./grind migrate` from CI (or a one-shot JDK job that has the source tree) against the same `DB_*` values before you point traffic at the new container.

Any platform that injects `PORT` works: the scaffold reads it.

## 6. CI (GitHub Actions)

Put this in the **application** repository:

```yaml
name: build
on:
  push:
    branches: [main]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: "21"
      - name: Tests
        run: ./gradlew check
      - name: Release tree
        run: ./gradlew installDist
      # Vite kits only:
      # - uses: actions/setup-node@v4
      #   with: { node-version: "22" }
      # - run: npm ci && npm run build
      - uses: actions/upload-artifact@v4
        with:
          name: hello-kona-dist
          path: build/install/hello-kona
```

Promote the artifact (or the image from section 5), run migrations, then restart the process.

## 7. Reverse proxy and TLS

The JVM speaks **HTTP**. Terminate TLS in Caddy, nginx, Traefik, or the cloud load balancer.

**Caddy** (certificates included):

```text
app.example.com {
    reverse_proxy 127.0.0.1:4000
}
```

**nginx:**

```nginx
upstream kona_app {
    server 127.0.0.1:4000;
}

server {
    listen 443 ssl http2;
    server_name app.example.com;

    location / {
        proxy_pass http://kona_app;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-Host  $host;
        proxy_set_header X-Forwarded-Port  $server_port;
    }
}
```

Behind a proxy, enable trusted forwarded headers in `bootstrap.Middleware` so `APP_URL`, redirects, and client IP match the public request: `.trustProxies(at = listOf("*"))` and `.trustHosts(at = listOf("app.example.com"))` (Java: `List.of(...)`). Details: [Kernel & server](../../http/kernel-server/).

Bind the app to `127.0.0.1` when the proxy is on the same host. Use `HOST=0.0.0.0` when the platform routes to the container port.

## 8. Health and static files

```http
GET /api/health → {"status":"ok"}
```

HTTP 200 means the process is up and the kernel answered. It does **not** check the database. Add your own readiness route if you need that.

`GET`/`HEAD` under `public/` (including `/build/assets/…` after a Vite production build) are served from disk. Do not ship `public/hot` — that file selects the Vite dev server.

```bash
# Vite / Inertia / Brew kits, in CI or on the build machine
npm ci && npm run build
```

## Checklist

1. JDK 21 in CI / on the build host  
2. `./gradlew check` green  
3. `APP_ENV=production`, `APP_DEBUG=false`, real `APP_KEY`, public `APP_URL`  
4. `DB_*` on a server database; `./grind migrate`  
5. `storage/` exists and is writable  
6. `npm run build` if the kit uses Vite  
7. `./gradlew installDist` and start **`bin/<app>`**, not `./grind serve`  
8. Reverse proxy + `trustProxies` / `trustHosts`  
9. `GET /api/health` returns `{"status":"ok"}`
