This walkthrough creates a small app, explains what each generated piece does, and starts the HTTP server.

## 1. Scaffold

```bash
grind new hello-kona --lang=kotlin
# or
grind new hello-kona --lang=java

cd hello-kona
```

`grind new` writes a **self-contained Gradle project**, including:

| Path | Purpose |
|------|---------|
| `settings.gradle.kts` / `build.gradle.kts` | Project name, JVM toolchain, Kona dependency |
| `gradlew` + wrapper | Build and run without a global Gradle install |
| `.env` | Local `APP_NAME`, `APP_DEBUG`, `HOST`, `PORT` |
| `bootstrap/App` | Entry that creates the application and starts the server |
| `app/Providers/AppServiceProvider` | Your place to bind services and register routes |
| `app/Http/Controllers/…` | Example controller |
| `routes/…` | Route definitions wired during provider boot |

Skeleton templates strip any `.txt` suffix used in the framework resources, so you get real `.kt` / `.java` files on disk.

## 2. How boot works

Kona separates **registration** from **boot**:

1. Providers are asked to `register` — bind services into the container, no side effects that need other providers finished yet.
2. Only after every provider has registered does Kona call `boot` — safe place to read bindings, attach routes, start background work.

Use the builder so you never boot before providers are listed:

```kotlin
val app = Kona.create(args)
    .providers(HttpServiceProvider(), AppServiceProvider())
    .boot()
```

```java
Application app = Kona.create(args)
    .providers(new HttpServiceProvider(), new AppServiceProvider())
    .boot();
```

`Kona.create` loads `.env`, seeds default `app.*` config, and loads files from `config/` when that directory exists. Your `.configure { }` / `configure(...)` blocks run afterward so you can override defaults.

## 3. Serve

```bash
./grind serve
```

By default grind looks for a Gradle project at or above the current directory and runs `./gradlew run` (or `gradle` if there is no wrapper). The process inherits `HOST` and `PORT` from the app’s `.env` after load; if unset, the server binds **127.0.0.1:8080**.

Useful flags:

```bash
grind serve --host=127.0.0.1 --port=8080
grind serve --in-process --once   # load compiled classes; stop after listen (handy in tests)
```

`--in-process` uses `AppLoader` to call `bootstrap.App.create` on the compiled classpath. Prefer the Gradle path when the app has extra dependencies that are not on grind’s own classpath.

Open `http://127.0.0.1:8080/` (or your configured port) and you should see the welcome route respond.

## 4. Monorepo samples

In the Kona repository, `samples/hello-kotlin` and `samples/hello-java` boot an application **in process** (no listen socket) and drive `HttpKernel` directly. They are the regression path for providers, route groups, and middleware. Use them as readable examples alongside your generated app.
