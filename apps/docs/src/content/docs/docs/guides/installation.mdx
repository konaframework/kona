Kona uses **two** command-line tools on purpose:

| Tool | Where it lives | What it does |
|------|----------------|--------------|
| **`kona`** | On your PATH (global) | Creates new applications: `kona new my-app` |
| **`./grind`** | Inside each app | Day-to-day work for *that* app: serve, generate controllers, … |

You install `kona` once. Every new project ships its own `./grind` script — you do not install grind globally.

## 1. JDK 21+

```bash
java -version   # must report 21 or newer
```

## 2. Install the global `kona` CLI

From a clone of [konaframework/kona](https://github.com/konaframework/kona):

```bash
./scripts/install-kona.sh
```

That builds the CLI and links `~/.local/bin/kona` (override with `KONA_PREFIX=/somewhere`). Ensure `~/.local/bin` is on your `PATH`, then check:

```bash
kona version
kona help
```

### What the installer does

1. Runs `./gradlew :kona-cli:installDist`
2. Symlinks the `kona` binary into `$KONA_PREFIX/bin` (default `~/.local/bin`)

You only need this when you want a newer `kona` from source. Creating apps afterward does not require the Kona git checkout on your PATH.

:::tip[Package managers later]
Published installers (Homebrew, SDKMAN, …) will wrap the same binary. Until then, the script above is the supported path.
:::

## 3. Create an application

```bash
kona new my-app                 # Kotlin (default)
kona new my-app --lang=java
```

## 4. Work inside the app with `./grind`

```bash
cd my-app
./grind serve
./grind make:controller Post
```

That is the whole happy path: **install `kona` once → `kona new` → `cd` → `./grind …`**.

## Optional: local Kona sources while developing the framework

Generated apps depend on `dev.kona:kona-http` and `dev.kona:kona-grind` from `mavenLocal()` / Maven Central. If you are changing Kona itself:

```bash
# from the Kona checkout
./gradlew :kona-core:publishToMavenLocal :kona-http:publishToMavenLocal :kona-grind:publishToMavenLocal
```

Or point the app at a checkout:

```bash
./gradlew run -Pkona.home=/path/to/kona
# or: export KONA_HOME=/path/to/kona
```

You do **not** need these steps just to try Kona after a normal `kona new`.
