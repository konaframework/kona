Kona uses **two** command-line tools on purpose:

| Tool | Where it lives | What it does |
|------|----------------|--------------|
| **`kona`** | On your PATH (global) | Creates new applications: `kona new my-app` |
| **`./grind`** | Inside each app created by `kona new` | Day-to-day work for *that* app: serve, generate controllers, … |

You install `kona` once. Every project from `kona new` ships its own `./grind` (and `grind.bat` on Windows) — you do not install grind globally.

## Happy path (exact commands)

```bash
# 1. Clone the framework (needed today to install the CLI)
git clone https://github.com/konaframework/kona.git
cd kona

# 2. Install global `kona` onto ~/.local/bin
./scripts/install-kona.sh

# 3. Create an application (any empty parent directory is fine)
kona new my-app
cd my-app

# 4. Serve with the app-local CLI
./grind serve
```

Open `http://127.0.0.1:8080/`. That is the supported path today: **install `kona` from source → `kona new` → `./grind serve`**.

## 1. JDK 21+

```bash
java -version   # must report 21 or newer
```

Gradle is bootstrapped by the project wrappers (`./gradlew`); you do not need a separate Gradle install.

## 2. Install the global `kona` CLI

### What works today

The only supported install is **from a clone of this repository**:

```bash
git clone https://github.com/konaframework/kona.git
cd kona
./scripts/install-kona.sh
```

That builds the CLI and links `~/.local/bin/kona` (override with `KONA_PREFIX=/somewhere`). Ensure `~/.local/bin` is on your `PATH`, then check:

```bash
kona version
kona help
```

### What the installer does

1. Runs `./gradlew :kona-cli:installDist`
2. Symlinks the `kona` binary into `$KONA_PREFIX/bin` (default `~/.local/bin`)

You only need this when you want a newer `kona` from source. Creating apps afterward does not require the Kona git checkout on your PATH.

### What is not available yet

There is **no** turnkey `kona` install via npm, Homebrew, SDKMAN, a standalone GitHub Release binary, or a “download and run” Maven Central launcher. Framework libraries publish under the `dev.kona` Maven group for *applications* to depend on; that is separate from putting the `kona` CLI on your PATH. Until packaged installers land, use `./scripts/install-kona.sh`.

:::tip[Package managers later]
Published installers (Homebrew, SDKMAN, …) will wrap the same binary built by `:kona-cli:installDist`. The script above is the supported path until those exist.
:::

## 3. Create an application

```bash
kona new my-app                 # Kotlin (default)
kona new my-app --lang=java
```

`kona new` writes a self-contained Gradle app that already includes:

- `./grind` / `grind.bat` — app-local CLI
- `./gradlew` / `gradlew.bat` — Gradle wrapper
- `src/main/…` layout, `.env`, and starter kit files

You should see a hint ending with `./grind serve`.

## 4. Work inside the app with `./grind`

```bash
cd my-app
./grind serve
./grind make:controller Post
```

`./grind` is a thin script that runs the project’s Gradle `grind` task with `kona-grind` on the classpath. It is **not** the same binary as global `kona`, and it is **not** something you copy from the Kona monorepo by hand.

## Trying the repo samples

The checked-in apps under `samples/hello-kotlin` and `samples/hello-java` are **monorepo Gradle modules** used for regression and layout reference. They intentionally:

- do **not** ship `./grind` or their own `./gradlew`
- depend on sibling `project(":kona-…")` modules instead of Maven coordinates
- are run from the **Kona repository root**

```bash
# from the Kona checkout root
./gradlew :hello-kotlin:run
./gradlew :hello-java:run
```

To experience the product path (`./grind serve`, generators, a standalone wrapper), use `kona new` as above. Do not expect `./grind` inside `samples/` — those directories are not full scaffolds.

## Optional: local Kona sources while developing the framework

Generated apps depend on `dev.kona:kona-http`, `dev.kona:kona-grind`, and related artifacts from `mavenLocal()` / Maven Central. If you are changing Kona itself:

```bash
# from the Kona checkout
./gradlew :kona-core:publishToMavenLocal :kona-http:publishToMavenLocal :kona-grind:publishToMavenLocal
```

Or point the app at a checkout:

```bash
./gradlew run -Pkona.home=/path/to/kona
# or: export KONA_HOME=/path/to/kona
```

You do **not** need these steps just to try Kona after a normal `kona new`.
