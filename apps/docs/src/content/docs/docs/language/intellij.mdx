IntelliJ IDEA uses a **native** JetBrains plugin — [kona-idea](https://github.com/konaframework/kona-idea) — the same approach as other first-class JetBrains language plugins. Crema is a real file type with an HTML-layered highlighter, not a TextMate bundle. From **0.2.0** onward the plugin also understands the `kona new` app tree and runs **Grind Serve** against the Netty HTTP adapter.

Installing, updating, or removing the plugin requires an IDE restart.

## Install

1. Download the latest `kona-idea-*.zip` from [Releases](https://github.com/konaframework/kona-idea/releases) (current line: **v0.2.0**), or build locally with `./gradlew buildPlugin`.
2. **Settings → Plugins → ⚙ → Install Plugin from Disk…** and choose the zip.
3. Restart when prompted.
4. Open a Kona app (create one with `kona new demo` if needed). Confirm:
   - Crema views under `src/main/resources/views/….crema.html` (or `*.crema.kt`) open as language **Crema**
   - Canonical folders (`bootstrap`, `routes`, `app`, `config`, `database`, `views`, `storage`) show the Kona icon
   - A **Grind Serve** run configuration is available (or add **Run → Edit Configurations → Grind**)

## What you get

### Crema

- Native Crema lexer: HTML colors plus `@directives`, `{{ }}`, `{!! !!}`, `{{-- --}}`
- Directive completion (Ctrl+Space on `@…`)
- Warnings for unknown `@name` tokens (emails like `hi@example.com` are ignored)
- `{{` auto-closes as `{{  }}` with the caret in the middle
- **New → Crema View**

### Project layout

The plugin detects apps shaped like the `kona new` / grind scaffolds:

- `src/main/{kotlin|java}/bootstrap`, `app`, `routes`, `config`, `database`
- `src/main/resources/views`, `public`, `lang`
- `storage/`, app-local `./grind`, and `dev.kona:*` dependencies

### Grind + HTTP (Netty)

- **Grind** run configuration type for `./grind …` (arguments are persisted)
- Host and port fields for `serve` (defaults `127.0.0.1` / **4000**)
- Opening a detected Kona app can auto-create **Grind Serve**
- `./grind serve` starts **KonaHttpServer** — a **Netty** adapter that handles each request on a **virtual thread**

### Templates and help

- Live templates such as `kroute` / `jroute` (typed Router handlers), `kextract`, `kauth`, `kdisk`, `kqueue`, `kschedule`, `kcrema`
- File templates for controllers, Crema views, and WebRoutes that use **typed instance / method-reference handlers** (not `Controller@method` strings)
- **Kona** menu: project layout help, routing help, Maven `dev.kona` modules, and optional kona-lsp setup

## Develop the plugin

```bash
git clone https://github.com/konaframework/kona-idea.git
cd kona-idea
./gradlew test
./gradlew buildPlugin   # → build/distributions/*.zip
./gradlew runIde        # sandboxed IntelliJ with the plugin loaded
```

JDK 21+. Keep `CremaDirectives` in the plugin in sync with `modules/lsp` `CremaDirectives` in this repository when you add template directives. Agent resume notes for the plugin live in that repo’s [`HANDOFF.md`](https://github.com/konaframework/kona-idea/blob/main/HANDOFF.md).

## Optional: TextMate or LSP only

If you cannot install the zip, see the legacy TextMate notes in `ide-support/intellij/README.md`. For a stdio language server used by other tooling:

```bash
./gradlew :kona-lsp:jar
java -jar modules/lsp/build/libs/kona-lsp-*.jar
```

Details: [Language server](/docs/language/lsp).
