---
title: Language server (kona-lsp)
description: Minimal LSP for Crema directive completion and unknown-directive diagnostics.
---

**kona-lsp** is a small Language Server Protocol implementation for Crema. It speaks JSON-RPC with `Content-Length` framing over **stdio** — the usual shape editors expect when you configure “run this command as the language server.”

It accepts **`crema`**, **`java`**, and **`kotlin`** documents. On Crema files it scans the whole buffer. On Java and Kotlin it finds inline Crema ranges — `template()` return/assignment strings, `inline(` arguments, and strings preceded by `// language=Crema` / `/* language=Crema */` — then runs the same analyzer on the string contents with positions mapped back to the host file.

Maven coordinates: `org.konaframework:kona-lsp` (module `modules/lsp`, package `org.konaframework.lsp`).

## Capabilities

| Method | Behavior |
|--------|----------|
| `initialize` / `initialized` | Advertise full document sync, completion (trigger `@`), diagnostic provider |
| `shutdown` / `exit` | Clean teardown (exit code `0` after shutdown) |
| `textDocument/didOpen` / `didChange` / `didClose` | Track buffer text; `publishDiagnostics` on open/change |
| `textDocument/completion` | Suggest built-in Crema directives, Wire `wire:*` attributes, echo helpers/variables inside `{{ }}` (`url`, `route`, `asset`, `csrf_token`, `old`, `env`, `config`, `trans`, `lang`, `loop.index`, …), and (inside `{{ }}` in a host class) public fields/methods |
| `textDocument/diagnostic` | Pull-model report of unknown `@directive` names and unknown `wire:*` attributes (mapped into inline strings on Java/Kotlin) |

Comments `{{-- … --}}` are ignored when scanning for directives and `wire:*` attributes so examples inside comments do not warn.

### Wire `wire:*` (Crema HTML)

Inside an open HTML tag, typing `wire:` (or a stem like `wi`) offers the same Wire attribute list as the IntelliJ plugin: `wire:model`, `wire:click`, `wire:submit`, `wire:loading`, `wire:target`, `wire:ignore`, `wire:key`, `wire:dirty`, `wire:offline`, `wire:confirm`, `wire:poll`, `wire:init`, `wire:show`, `wire:transition`, plus common modifiers (`.live`, `.prevent`, …). Unknown `wire:*` names produce a warning. Trigger characters include `@`, `:`, `.`, and `{`.

When the caret is inside `{{ … }}` of a Crema view, kona-lsp suggests every Crema echo helper and conventional variable (`CremaEchoCatalog`, kept in sync with `CremaHelpers` and the IntelliJ plugin). On an inline `template()` string it also suggests public properties and methods scanned from the enclosing class source (no full Java type resolver — inherited members from `Component` appear only if they are written in that file). Helper names from the catalog still appear beside those members.

`CremaEchoCatalog.completions(prefix)` / `CremaHelpers.completions(prefix)` expose the same names for tests and tooling.

## Run it

```bash
./gradlew :kona-lsp:jar
java -jar modules/lsp/build/libs/kona-lsp-*.jar
```

Or:

```bash
./gradlew :kona-lsp:installDist
modules/lsp/build/install/kona-lsp/bin/kona-lsp
```

The process reads LSP messages from stdin and writes responses/notifications to stdout. Do not type into it interactively — let the editor own the pipes.

From an app checkout:

```bash
./grind ide:lsp
```

prints the same instructions without starting a server.

## Use from Kotlin or Java (tests / tooling)

The public surface is usable without an editor. Kotlin:

```kotlin
val diags = CremaAnalyzer.diagnostics("@csrf @notReal")
val items = CremaAnalyzer.completions("@for", 0, 4)
val code = LspServer().serve(inputStream, outputStream)
```

Java:

```java
List<CremaAnalyzer.Diagnostic> diags = CremaAnalyzer.diagnostics("@csrf @notReal");
List<CremaAnalyzer.CompletionItem> items = CremaAnalyzer.completions("@for", 0, 4);
int code = new LspServer().serve(inputStream, outputStream);
```

`CremaDirectives.KNOWN` / `isKnown(name)` expose the built-in directive set shared with completion and diagnostics.

## What it does not do (yet)

- Full Crema parsing or HTML validation
- Route-name completion from your app’s router
- Formatting or rename refactorings
- A second language server for Java/Kotlin (the Java extension still owns `.java` files; merge completion lists in the editor)

Those can grow later; this milestone keeps the protocol surface small but real so editors can attach today.
