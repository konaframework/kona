The **Crema (Kona)** extension under `ide-support/vscode-crema/` contributes the Crema language id, TextMate grammar, and settings keys for the language server jar.

## Install for local development

```bash
# VS Code
code --install-extension ide-support/vscode-crema

# Cursor
cursor --install-extension ide-support/vscode-crema
```

Reload the window (`Developer: Reload Window`), then open any `*.crema.html` file — highlighting should activate without further setup. The grammar also highlights known Brew `wire:*` attributes (`wire:model`, `wire:click`, …).

Inline Brew markup in Java and Kotlin is highlighted too: `template()` text blocks, `inline(` string arguments, and strings preceded by `// language=Crema` or `/* language=Crema */`. That is the path you use when editing `samples/brew-java/.../Counter.java` (and the Kotlin equivalent) without a separate `.crema.html` file.

With **kona-lsp** attached to **`crema`**, **`java`**, and **`kotlin`** documents, completions and diagnostics cover Crema `@` directives, Brew `wire:*` attributes, and (inside `{{ }}`) public members of the enclosing component class. Inertia apps that use Crema layouts benefit from the same Crema/LSP path; page-component completion stays on the IntelliJ plugin today.

Command palette: **Crema: Show kona-lsp setup help** prints build/run lines to an output channel.

## Settings

| Setting | Default | Purpose |
|---------|---------|---------|
| `crema.lsp.enabled` | `true` | Reserved for clients that auto-start the server |
| `crema.lsp.javaPath` | `java` | JDK launcher |
| `crema.lsp.jarPath` | `""` | Absolute path to the kona-lsp jar |

Example `settings.json`:

```json
{
  "crema.lsp.javaPath": "java",
  "crema.lsp.jarPath": "/home/you/kona/modules/lsp/build/libs/kona-lsp-0.1.1.jar"
}
```

Build the jar first: `./gradlew :kona-lsp:jar`.

## Wiring a full LSP client

The stub extension registers language support and help; for live completion and diagnostics, configure an LSP client (for example `vscode-languageclient`) with:

```text
java -jar /absolute/path/to/kona-lsp.jar
```

stdio transport. Document selector languages: `crema`, `java`, `kotlin`. See [Language server](/docs/language/lsp) for the protocol surface.

Point the client at Java and Kotlin buffers as well as `*.crema.html`. kona-lsp ignores ordinary Java/Kotlin code: it only scans inline Crema ranges, so `@Override` in a Java file is not treated as a Crema directive.

## Sync grammar after edits

```bash
cd ide-support/vscode-crema && node scripts/sync-grammar.js
```

Canonical grammar sources remain in `ide-support/crema/`.
