Vous utilisez ce guide lorsque vous voulez un bureau pour les personnes qui font tourner l’application : trouver un enregistrement, le modifier et voir qu’il est enregistré. Écrivez les écrans en Kotlin ou Java, placez-les à côté du panneau, et ouvrez `/admin`.

Firefly dessine le HTML sur le serveur. Les boutons, les dialogues et les champs live restent dans le navigateur à travers [Wire](/docs/wire/) et Alpine. Lorsque vous ajoutez une colonne ou un bouton, vous l’ajoutez sur la classe.

Firefly se tient sur les épaules de [Filament](https://filamentphp.com/). La façon dont Filament assemble un panneau — ressources, formulaires, tableaux, et comment ces pièces se composent — a façonné une grande part de ce que vous pouvez faire ici. Nous sommes notre propre panneau pour Kona. Vous l’écrivez en Kotlin, et vous appelez les mêmes types depuis Java. Les champs live passent par [Kona Wire](/docs/wire/), les vues par [Crema](/docs/crema/), et les enregistrements par [Cadence](/docs/cadence/).

</FilamentNod>

Utilisez un panneau pour le bureau. Gardez une page publique ou une API JSON sur une route Kona ordinaire. Ajouter le module laisse ces routes tranquilles. Les URL apparaissent lorsque votre `Panel` appelle `mount`.

Vous pouvez aussi appeler `render()` sur un schéma, un formulaire ou un tableau et déposer ce HTML dans une vue ou un test. Le panneau est ce qui transforme ces pièces en URL, une barre latérale et un écran de connexion.

## Ce que vous mettez dans l’application

Créez `app/firefly/Panel`. Il étend `org.konaframework.firefly.Panel`. `discover` lit trois dossiers à côté de ce fichier :

| Dossier | Mettez ceci ici |
|--------|----------------|
| `pages/` | Un écran que vous concevez, comme la page Desk |
| `widgets/` | Une stat, un graphique ou un bloc sur une page |
| `resources/` | Une classe par type d’enregistrement, comme les notes ou les commandes |

`samples/hello-kotlin` et `samples/hello-java` sont cette disposition, montée à `/admin`. Ces pages suivent l’exemple Kotlin. L’exemple Java a les mêmes écrans.

Sur cette application vous pouvez ouvrir :

- `/` — la page d’accueil, hors du panneau
- `/admin/desk` — la page Desk : un formulaire, une infolist, un tableau, une action d’en-tête et un widget
- `/admin/notes/manage` — une ressource simple. Une page. Create, edit, view et delete s’ouvrent dans un dialogue
- `/admin/orders/list`, `/admin/orders/create`, `/admin/orders/edit`, `/admin/orders/view` — une ressource complète, avec des lignes sur edit et view

Déposez une ressource dans `resources/`. La découverte la prend. Appelez `page`, `widget` ou `resource` vous-même seulement lorsque vous voulez sauter le dossier.

## Où vivent les types

Dépendez de `org.konaframework:kona-firefly`. Cette coordonnée apporte les autres modules Firefly avec elle. Ouvrez un module lorsque vous voulez le paquet d’un type :

- `kona-firefly` — le panneau, les pages, les ressources, la navigation, le multi-tenant, les plugins, l’import et l’export, et `Firefly.test`
- `kona-firefly-schemas` — l’arbre de composants et sa map d’état. Les sections, grilles, onglets et le texte brut vivent ici
- `kona-firefly-forms` — les champs sur cet arbre, y compris le select combobox et le sélecteur de date façonné, avec validation
- `kona-firefly-infolists` — entrées en lecture seule : texte, icônes, images, et les autres façons de montrer un enregistrement
- `kona-firefly-tables` — colonnes, filtres, recherche, tri et pages
- `kona-firefly-actions` — un bouton ou un lien, le dialogue qu’il peut ouvrir, et la méthode serveur qu’il appelle
- `kona-firefly-notifications` — un toast, une cloche de base, et un marqueur de rafraîchissement de diffusion
- `kona-firefly-widgets` — stats, graphiques et blocs personnalisés sur une page
- `kona-firefly-support` — le dialogue, les icônes, les jetons de thème et `FireflyException`. Les autres modules en dépendent, donc votre application ne dépend que de `kona-firefly`

## Lorsque vous voulez un plugin, un thème ou un test

Passez un plugin à `plugin(...)`. `register` s’exécute immédiatement. `boot` s’exécute lorsque le panneau se monte. Dans ces méthodes vous appelez les mêmes méthodes de panneau que l’application appelle : une marque, un hook, une page. Gardez la classe dans l’application lorsque le comportement appartient à cette application. Lisez [Plugins](/docs/firefly/plugins/).

L’apparence livrée est `KonaTheme`. `Stylesheet.render` écrit les couleurs et le type comme propriétés CSS personnalisées sur `.ff-panel`. Les règles de composant ne correspondent qu’à l’intérieur de cette classe. Pour changer l’apparence, implémentez `FireflyTheme` et passez-le à `theme(...)`. `extraCss()` est enveloppé dans `.ff-panel { ... }`, donc vos règles restent dans le panneau. L’exemple hello utilise le thème livré. Lisez [Thèmes et CSS](/docs/firefly/themes/).

`Firefly.test` lit le HTML que vous avez déjà rendu. Il vit dans `org.konaframework.firefly.testing`.

`assertSee` échoue lorsque le texte manque. `assertFormField` cherche `data-ff-path`. `assertTable` veut à la fois `ff-table` et le texte. `assertDialog` veut à la fois `ff-dialog` et le titre. `Firefly.test(html)` vérifie une chaîne. Les mêmes assertions sont sur [Import et export](/docs/firefly/import-export/).

## Lisez ces pages dans l’ordre

1. [Prérequis](/docs/firefly/requirements/) — JDK 21 et l’application Kona que vous avez déjà.
2. [Installation](/docs/firefly/installation/) — `kona new --kit=firefly`, ou ajoutez le module à une application existante.
3. [Enregistrer un panneau](/docs/firefly/registration/) — le fichier `Panel`, les trois dossiers et `discover`.
4. [Une application qui tourne](/docs/firefly/working-app/) — la ressource notes et la ressource orders dans hello-kotlin et hello-java.

Ensuite, ouvrez la page de la pièce que vous ajoutez. [Panneau](/docs/firefly/panel/) est la classe que vous montez. Kotlin et Java appellent les mêmes types. Les exemples sont dans les onglets de langue. La classe que vous étendez est `Panel`. Le paquet est `org.konaframework`.
