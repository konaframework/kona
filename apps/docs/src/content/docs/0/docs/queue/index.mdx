Queues let your app finish a request quickly and do heavier work moments later — send mail, resize images, call slow APIs — on a separate worker process.

Register `QueueServiceProvider`, then dispatch jobs through `Bus`. Jobs that implement `ShouldQueue` are pushed onto a connection; everything else runs immediately.

## Quick start

```kotlin
class SendInvoice : Job, ShouldQueue {
    override fun handle() { /* … */ }
}

val bus = app.resolve(Bus::class.java)
bus.dispatch(SendInvoice())
```

```java
Bus bus = app.resolve(Bus.class);
bus.dispatch(new SendInvoice());
```

```bash
./grind queue:work --connection=array --stop-when-empty
```

## Connections

Configure `queue.default` and `queue.connections.{name}.driver`:

| Driver | Role |
|--------|------|
| `sync` | Run inline on dispatch (delay ignored) |
| `array` / `memory` | In-process queue for tests and local workers |
| `redis` | Shared Redis list (needs `RedisManager`) |
| `database` | `jobs` table (needs Cadence `Database`) |

Default queue name per connection: `queue.connections.{name}.queue` (fallback `default`).

## steam

From `./grind steam`, resolve `Bus` / `QueueManager` after boot and dispatch jobs interactively while a worker runs in another terminal.
